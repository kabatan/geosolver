# 書き換え実験プロトコル（実行前に固定、2026-10-21）

この文書は、solverを1度も走らせない段階で固定した。問題の選定、書き換えの規則、同値性の根拠、入力の大きさを決めてある。
選定でも作成でも、323問のsolverの成績は見ていない。DSLを作ったのはAI（Claude）。同値性は、solverとは別に作った数値検算スクリプトで確かめた。
323問の凍結版（`benchmarks/cases.jsonl` と `dsl/`）は変えていない。

## 実験1 表現の書き換え（6問 × 3表現 × 3 seed = 54実行）

### 選定規則（機械的に適用）
1. 323問DSL監査（AI一次）で、E1・V・導出なしと判定された問題に限る。
2. 自由変数が1〜4個で、Easy2Hard-Benchの131問に入っている問題に限る。
3. 点を返す構成（`Point(...)` 以外）を2つ以上持つ問題に限る。
4. 規則Cで分岐を変えずに展開できない構成を使う問題は除く。対象は near/far、Tangent、AngleBisector、Reflect、Arc、PointOn*、Incircle 系、Polygon、Segment など。
5. 構造の種類は次の3つ。
   - T1「直線だけの作図」: Midpoint、交点、垂線の足、垂線、平行線だけを使う。
   - T2「三角形の中心」: 外心・内心・垂心・重心を使い、円は作らない。
   - T3「円との交点」: Circumcircle または Circle を作る。
6. 各種類について、AIMEとHMMTからそれぞれ cases.jsonl の並び順で最初の1問を取る。

| 種類 | 問題 |
|---|---|
| T1 | AIME-2021-I-11, HMMT-2017-FEB-GEO-10 |
| T2 | AIME-2014-II-14, HMMT-2013-FEB-GEO-07 |
| T3 | AIME-2016-I-06, HMMT-2013-FEB-GEO-05 |

### 表現
- **A（基準）**: 凍結版のDSLそのもの。変えたのは id だけ。
- **B（冗長な等式の追加）**: Aの等式条件を並び順に e1,…,ek とする。次の式を条件の末尾に足す。
  - 隣り合う組の和 e_i+e_{i+1}（i=1..k−1）。
  - k≥3 のときは、全体の和 e1+…+ek も足す。
  - 形は「(左辺_i)+(左辺_j) = (右辺_i)+(右辺_j)」とする。元の条件はすべて残す。
  - 足す本数は k−1、k≥3 なら k。
- **C（構成の展開）**: 点を返す構成を、新しい変数 (xN, yN) を持つ自由な点に置き換える。その点を定める条件は、下の規則で条件の末尾に足す。
  - 元の条件・ガード・目標の式は一字も変えない。点の名前が同じなので、参照先も同じ。
  - 直線の構成（`PerpendicularLine` など）は点ではないので、そのまま残す。

| 元の構成 | 足す条件 |
|---|---|
| `M = Midpoint(P,Q)` | Vector(P,M).x = Vector(M,Q).x、.y も同様 |
| `X = Intersect(Line(P,Q), Line(R,S))` | Collinear(P,Q,X)=0、Collinear(R,S,X)=0 |
| `X` が「Nを通りUVに垂直な直線」上 | Dot(Vector(N,X), Vector(U,V))=0 |
| `H = FootOfPerpendicular(P, Line(U,V))` | Collinear(U,V,H)=0、Dot(Vector(H,P), Vector(U,V))=0 |
| `O = Circumcenter(A,B,C)` | Distance(O,A)=Distance(O,B)、Distance(O,A)=Distance(O,C) |
| `I = Incenter(A,B,C)` | a·Vector(I,A)+b·Vector(I,B)+c·Vector(I,C)=0 の x 成分と y 成分（a=BC, b=CA, c=AB、重みつき平均の式） |
| `Γ = Circumcircle(A,B,C)` | 新しい中心 K を外心の規則で作り、Γ = CircleThroughPoint(K, A) とする。同じ三角形の Circumcenter が別にあっても共有しない（機械的に適用するため） |
| `X = Intersect(Line(P,Q), Γ, exclude=E)` | Collinear(P,Q,X)=0、Distance(K,X)=Distance(K,A)、ガード Distance(X,E)>0 |

### 目標値・枝・定義域が保たれる根拠
- **B**: 足した式は元の等式の和なので、解の集合は変わらない。新しい関数も使っていないので、定義域も変わらない。ガードと目標はAと同じ。
- **C**: 上の規則はどれも、もとの構成の値を一意に特徴づける。
  - 中点、2直線の交点、垂線の足、外心は、対応する線形方程式またはその連立の一意解になる。
  - 内心は重みつき平均の式なので、傍心の枝は入らない。
  - 円と直線の交点は2点のうち E でない方で、exclude と同じ選び方になる。
  - 構成が定義されない配置（平行な2直線など）では、Cの条件にも解がない。
  - 目標とガードは同じ名前の点を参照するので、元の変数が同じなら値も同じになる。
- **数値検算**（`tools/check_equivalence.py`、solverは使っていない）は2方向で行った。
  - 前向き: A の条件を満たす配置をランダムな初期値から最小二乗で最大8個求める。各配置で、B の条件が成り立ち目標が一致すること、C に構成の値を入れると条件が成り立ち目標が一致することを確かめた。
  - 後ろ向き: C の条件を満たす配置を同様に求める。展開した点が元の構成の値と一致すること、その配置が A の条件を満たし目標が一致することを確かめた。後ろ向きで A を満たさない解（余分な枝）が見つかれば、同値でないことになる。
  - 結果は下の表の「検算」の列。

### 検算結果
実験2 の R も含め、検算は2026-10-21にクラウドのコンテナで行った。実行コマンドは `uv run python benchmarks/rewrite-experiment/tools/check_equivalence.py <id>`。HMMT-2017-FEB-GEO-10 だけは別の方法で始点を作った（下の表を参照）。

| 問題 | 前向き（A の配置 → B, C） | 後ろ向き（C の解 → A） |
|---|---|---|
| AIME-2021-I-11 | 8配置すべてで B・C が成立し、目標が一致 | 8解すべてが A を満たし、展開した点・目標が一致 |
| HMMT-2017-FEB-GEO-10 | 6配置すべてで一致 | 30解すべてが A を満たし、一致 |
| AIME-2014-II-14 | 8/8 一致 | 8/8 一致 |
| HMMT-2013-FEB-GEO-07 | 8/8 一致（A 自体に目標値が2つあり、C も同じ2つ） | 8/8 一致 |
| AIME-2016-I-06 | 8/8 一致 | 見つかった2解とも一致 |
| HMMT-2013-FEB-GEO-05 | 4配置すべてで一致 | 27解すべてが A を満たし、一致 |

- HMMT-2017-FEB-GEO-10（`tools/check_hmmt_2017_10.py`）と HMMT-2013-FEB-GEO-05（`tools/check_hmmt_2013_05.py`）は、ランダムな初期値では A の解が見つからなかった。そこで手計算で始点を作った。
  - 2017-10: 接線四角形の性質（半角の和が π）から、r と接点の角を計算した。
  - 2013-05: AM·MD=BM·MC から A=(±√7/2, 1/2)·s とした。
  - この計算は検算のためだけに使い、DSLには入れていない。
- 後ろ向きの解は、C の解を最大20%ずらした点から解き直して求めた。
- 検算用の評価器では、厳密な不等式のガードを 1e-7 の余裕つきで判定する。退化した配置（面積がほぼ0の三角形など）を除くため。

## 実験2 事前導出をsolverに戻す（5問 × 2表現 × 3 seed = 30実行）

- **A**: 凍結版のDSL。
- **R**: 監査で「重いE2」とした導出を外し、原文の未知量と条件に戻した版。
- 対象: E2（重）のうち、原文の言葉だけで書き戻せるものを AI が選んだ。この選び方には判断が入っている。
- AIME-2015-II-07 と HMMT-2016-FEB-GEO-03 の R は、DSL修正版 r1（`benchmarks/dsl-revisions/`）と同じもの。

| 問題 | 外した導出 | R での書き方 | 変数 A→R | 等式 A→R |
|---|---|---|---|---|
| HMMT-2006-FEB-GEO-04 | 半円の中心を角の二等分線から B から 8/5 の位置に固定していた | 中心 O=(o,0) を未知にし、「ABとACへの距離が等しい」と「0<o<4（直径がBC上）」で決める | 0→1 | 4→4 |
| HMMT-2010-FEB-GEO-10 | 2円の半径と A, B, X, Y の座標をすべて手で解いていた | P=(0,0), Q=(1,0) とし、ω1, ω2 は PQ に P, Q で接する円（半径 r1, r2 は未知）。A, B は2円の交点で、A の方が PQ に近い。∠APQ=30°, ∠PQA=15°。X, Y は原文どおり平行線と円の交点 | 0→6 | 2→6 |
| AIME-2013-I-12 | 正六角形の位置を手で決めていた | 正六角形を「中心 (zx,zy)、向きの単位ベクトル (ux,uy)、巡回の向き sg（sg²=1）」で表す。AB が PQ 上、CD が QR 上、E か F が RP 上という原文の条件だけで位置を決める。r>2 という導出したガードは外した | 1→6 | 5→7 |
| AIME-2015-II-07 | target が β を手で導いた「高さ/底辺」だった | 2つの長方形で「面積=αw−βw²」を条件にし、α, β を解かせる | 1→2 | 12→5 |
| HMMT-2016-FEB-GEO-03 | target が答えの式 (三角形−円)/3 だった | X, Y を扇形の公式で直接書く（図が欠けているので領域は解釈） | 0→0 | 0→0 |

- 検算: R を満たす配置をランダムな初期値から求め、その目標値の集合が A の目標値と一致することを確かめた。結果は下に示す。
- AIME-2013-I-12 の R の解の一意性（論証）は次のとおり。
  - AB が直線 PQ 上、CD が直線 QR 上にあり、∠Q=60° である。正六角形で辺 AB の延長と辺 CD の延長がなす角は60°なので、向きは整合する。2本の直線上の位置で、六角形の位置は1つに決まる。
  - 巡回の向き sg を逆にすると B と C が隣り合わない配置になり、AB と CD が両方とも辺の上に乗れない。
  - 残る未知数は r だけで、「E か F が RP 上」から r の候補は2つ（3.366 と 2+√3）になる。前者は F が三角形の外に出るので、ガードで除かれる。
  - 検算: `tools/check_aime_2013_I_12.py`。
- 外した候補: HMMT-2019-FEB-GEO-07。答えの円を外して「3円に接する円」を未知にすると、接し方（内接・外接）を原文が指定していないため、半径の違う解が複数出た（6.09, 6.50, 6.87 など）。凍結版の答えは、そのうち特定の接し方を選んだものになる。原文の言葉だけでは答えが1つに決まらないので、この実験からは外した。

検算結果（`tools/check_derivation.py`）:

| 問題 | A の目標値 | R の解の目標値 |
|---|---|---|
| HMMT-2006-FEB-GEO-04 | 1つ | 8解すべてが同じ値 |
| HMMT-2010-FEB-GEO-10 | 1つ | 8解すべてが同じ値 |
| AIME-2015-II-07 | 1つ | 8解すべてが同じ値 |
| HMMT-2016-FEB-GEO-03 | 1つ | 同じ値（変数0個） |
| AIME-2013-I-12 | 1つ（r=2+√3） | A の配置から作った R の変数で、R の条件がすべて成り立ち、目標も一致した（前向き）。ずらした始点からの解き直しは収束しなかった。min と OnSegment の残差が滑らかでないためで、後ろ向きは下の論証で代える |

## 実行（PC、凍結版のコード）

```bash
uv run python benchmarks/research_runner.py validate --cases benchmarks/rewrite-experiment/cases.jsonl
uv run python benchmarks/research_runner.py validate --cases benchmarks/rewrite-experiment/derivation/cases.jsonl
```

- 交互の実行順は `run-order.tsv` と `derivation/run-order.tsv` に固定した。
  - 並びは seed ごと。問題ごとに、表現の順を (問題番号+seed) だけ巡回させてある。
  - runner は1回の run の中で「case の並び → seed」の順に投入する。順序を守るには、この表の順に `--case-id` と `--seeds` で1件ずつ投入するのがよい。
- 各 case の参照答は、元の問題の参照答と同じ。
