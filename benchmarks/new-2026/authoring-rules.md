# 2026年新規問題のDSL化規則（DSL作成前に固定）

対象: HMMT February 2026（Geometry 10問・Guts 7問）、JMO 2026予選（3問）。AIME 2026は問題文が取得でき次第、同じ規則で追加する。
固定日時: 2026-10-21 17:35 UTC（DSLを1問も書く前）。solverは60db4b6で凍結済み。

## 許す操作
1. 原文に書かれた量・点・図形の構成を、DSLの記号または座標式でそのまま表すこと。
2. 一般性を失わない座標の置き方（合同変換による正規化）。例: ある点を原点、ある辺をx軸の正の向きに置く、ある点をx軸の上側に置く。
3. 原文に長さが与えられていない図形での相似の正規化（ある長さを1に置く）。ただし求める量が相似で不変な場合に限る。
4. 原文の語句の直訳にあたる条件の書き換え。例:「Pは線分AB上」→ PointOnSegment(A, B, t) と t の範囲、「凸五角形」→ ConvexPolygon、「内部にある」→ 符号条件・不等式。
5. 図からだけ読める情報（点の順序・どちら側か）を条件に入れること。図の何から読んだかを対応表に書く。

## 禁止する操作
1. 原文にない定数を、解法の推論で導いてDSLに入れること（例: 二等分線の性質から中心をPoint(8/5,0)に固定する）。
2. 原文にない補題・定理の結論を条件や構成に使うこと（例: 共円であることを証明済みとして使う）。
3. solverの解きやすさのための式変形・変数削減・補助変数の工夫。
4. solverの実行結果を見たあとでDSLを直すこと。

## 監査
- 原文の各条件とDSLの各行の対応表を作る。原文にない定数があれば導出元（座標の置き方など）を書く。
- 枝（交点のどちら、内分・外分、図の向き）と端点（含む・含まない）の扱いを記録する。
- 意味の一致を条件ごとに監査する（答えの一致だけで済ませない）。
- 独立の数値検算（`benchmarks/new-2026/verify/check_dsl.py`、GeoSolverの探索は使わずDSLの評価層とSciPy多点開始＋60桁精密化のみ）で、(a) 公式の答えを与える配置が全条件を満たすか、(b) 公式以外の答えの値を許していないか、を確認する。
- 検算でずれが見つかった場合の修正は、原文との意味の食い違いを直すときだけ。理由をすべて改訂履歴に残す。
- DSLで表せない問題は除外せず「表現不能」として記録し、失敗として数える。
