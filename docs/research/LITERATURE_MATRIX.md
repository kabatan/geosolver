# Primary-Source Literature Matrix

Status: **M0 research input**
Last reviewed: 2026-07-10

Only primary papers and official project/language documentation appear below.
A citation records a comparison obligation, not an automatic design choice.

| ID | Source | Relevant result or interface | Assumptions | Break conditions in GeoTarget | M0-M4 decision |
|---|---|---|---|---|---|
| LIT-JULIA-PERF | [Julia Performance Tips](https://docs.julialang.org/en/v1/manual/performance-tips/) | Official guidance recommends type-stable functions, function barriers, preallocation and static arrays for small fixed-size operations. | Concrete types and stable call paths are available. | Open plugin calls can be opaque; excessively large generated methods can trade evaluation speed for compilation latency. | Measure type stability, allocations, compile latency and warm latency separately in `EXP-COMP-001`. |
| LIT-RGF | [RuntimeGeneratedFunctions official API](https://docs.sciml.ai/RuntimeGeneratedFunctions/stable/api/) | Runtime-generated callables can be invoked immediately without ordinary world-age failures. | Generated expressions use a controlled module context. | Arbitrary JSON code, closures with changed semantics, plugin mutation or code-size explosion. | RGF is one candidate, never the semantic reference; no `eval`/`invokelatest` hot path. |
| LIT-NLS-PAPER | [NonlinearSolve.jl paper](https://arxiv.org/abs/2403.16341) | Presents unified Julia nonlinear solvers, sparse AD and Jacobian-free methods with cross-solver benchmarks. | Problems fit the declared nonlinear/root/least-squares interfaces and backend capabilities. | A least-squares stationary point need not be a root; branch/guard validity is outside a generic solver return code. | Use an adapter and canonical endpoint gate; do not delegate truth to the library. |
| LIT-NLS-FUNCTION | [NonlinearFunction official API](https://docs.sciml.ai/NonlinearSolve/dev/basics/nonlinear_functions/) | `f` is required; `jac`, JVP, VJP, sparsity prototype and color vector are optional. | Function mutation and shapes obey the interface. | Opaque or nonsmooth plugins may not support AD; sparsity can change across branch charts. | Align `EvaluationOracle` with optional capability fields and freeze sparsity per compiled chart. |
| LIT-NLS-NLLS | [Nonlinear least-squares solver guide](https://docs.sciml.ai/NonlinearSolve/stable/solvers/nonlinear_least_squares_solvers/) | Official guide exposes Levenberg-Marquardt, Gauss-Newton and trust-region methods for under/overdetermined systems. | Residual minimization is an appropriate local model. | Positive-residual local minima and rank-deficient manifolds. | LM-QR is an initial fixed control only; raw canonical residual decides acceptance. |
| LIT-LM | [Transtrum and Sethna, 2012](https://arxiv.org/abs/1201.5885) | Studies LM improvements for narrow canyons, flat models, uphill acceptance and geodesic acceleration. | Smooth nonlinear least-squares geometry and informative derivatives. | Nonsmooth primitives, invalid domains and strict guards. | Do not tune LM variants in the scaling card; hold the algorithm fixed and isolate scaling first. |
| LIT-SINGULAR-BROYDEN | [Decker and Kelley, 1985](https://doi.org/10.1137/0722034) | Proves local linear convergence of Broyden's method for a stated class of roots with singular Jacobian. | A special initial region and singularity hypotheses hold. | This is neither a global result nor an all-roots guarantee; arbitrary opaque systems need not satisfy the hypotheses. | Keep Broyden as a diagnosed local candidate, never a universal rescue. |
| LIT-NULLSPACE-NEWTON | [Hao, 2005](https://doi.org/10.1016/j.apnum.2004.09.029) | Uses approximate left/right nullspaces to form bordered systems with quadratic convergence near generalized regular singularities. | Reliable rank/nullspace estimates near an isolated singular root. | Manifolds, noisy rank transitions, unavailable derivatives and nonisolated roots. | Consider only after rank diagnostics trigger a preregistered singular-root experiment. |
| LIT-RANK-DEFICIENT-NLS | [Zhang, 2011](https://doi.org/10.1137/090780882) | Shows that ill-defined numerical rank can compromise nonlinear least-squares accuracy and warns against unstable truncated singular-vector selection. | Residual/Jacobian errors matter near a rank transition. | A fixed SVD cutoff does not provide a representation-independent repair. | Record rank/condition evidence and compare QR/subset/nullspace routes; do not silently switch by one cutoff. |
| LIT-LINEARSOLVE | [LinearSolve official solver guide](https://docs.sciml.ai/LinearSolve/stable/solvers/solvers/) | Recommends QR/SVD when precision matters; documents rank-revealing sparse column-pivoted QR and warns normal-form Cholesky is for well-conditioned matrices. | Matrix structure and element types match the selected factorization. | Severe rank defect, rapidly changing sparsity or unsupported arbitrary precision. | Dense column-pivoted QR is H0; sparse CPQR is an extension; SVD is a diagnostic control. |
| LIT-FORWARDDIFF | [Forward-mode AD in Julia](https://arxiv.org/abs/1607.07892) | Describes dual-number forward AD with competitive Julia performance. | Type-generic native Julia code and differentiable executed paths. | Foreign callbacks, hard type assertions, mutation incompatibility and nondifferentiable branches. | Compare analytic, ForwardDiff and central finite differences after scaling is frozen. |
| LIT-DI | [DifferentiationInterface paper](https://arxiv.org/abs/2505.05542) and [official preparation API](https://juliadiff.org/DifferentiationInterface.jl/DifferentiationInterface/stable/) | Defines a common AD frontend with reusable preparations and sparsity support. | Backend-specific preparation remains valid for unchanged function/type/shape. | Plugin/shape changes or a backend whose wrapper is slower/less reliable than its native API. | Cache preparations per compiled oracle; fall back explicitly, never silently. |
| LIT-SPARSE | [SparseDiffTools official documentation](https://docs.sciml.ai/SparseDiffTools/) | Coloring can reduce Jacobian evaluations from variable count to color count. | The structural sparsity pattern is sound and stable. | Hidden dense dependency, branch-dependent structure or wrong graph analysis. | Use compiler-derived sparsity; differential-test colored and dense Jacobians. |
| LIT-COLEMAN-MORE-COLORING | [Coleman and Moré, 1983](https://doi.org/10.1137/0720013) | Formulates sparse finite-difference Jacobian grouping as graph coloring and reports near-optimal practical heuristics. | The structural pattern contains every possible nonzero. | Missing dependencies silently alias multiple column effects into one residual row. | Color only compiler-derived conservative dependencies; dense-differential test before promotion and retry unusable groups column-wise. |
| LIT-SOBOL | [Sobol, 1967](https://doi.org/10.1016/0041-5553(67)90144-9) | Introduces low-discrepancy point sequences in a cube. | Bounded box and sequence quality in the active dimension. | Basin geometry can be poorly aligned; deterministic prefixes provide no seed distribution for empirical confidence. | Deterministic Sobol is a comparator, not the probabilistic-completeness lane. |
| LIT-OWEN | [Owen, 1997](https://doi.org/10.1137/S0036142994277468) | Scrambled nets retain equidistribution while supporting randomized variance analysis. | Results concern integration and square-integrable functions. | Root-basin hitting is not an integration-error theorem; points within a scramble are dependent. | Compare Owen-scrambled Sobol empirically, while attaching the simple capture proof only to IID insurance. |
| LIT-TGO | [Henderson et al., 2017](https://doi.org/10.1016/j.apnum.2016.10.007) | Uses Sobol samples and a k-nearest-neighbor topograph to select starts for constrained nonlinear systems. | Smooth systems, bounded sampling region and meaningful residual-minimization landscape. | Close roots, narrow basins, nonzero residual minima, invalid target values far from feasibility. | Test a soft ordering that defers rather than discards starts. |
| LIT-MLSL | [Rinnooy Kan and Timmer, 1987](https://doi.org/10.1007/BF02592071) | Analyzes stochastic multistart with clustering for multiple minima. | Bounded domain and regular, finitely many minima under the paper's conditions. | Zero manifolds, singular roots and targets sharing many configurations. | Permanent IID all-launch is the control; clustering needs a later separate card. |
| LIT-APOSMM | [Larson and Wild, 2018](https://doi.org/10.1007/s12532-017-0131-4) | Asynchronous multistart considers all sampled points and proves results for finitely many minima under stated regularity conditions. | Compact domain, finite separated minima and compatible local optimization. | Close-root suppression, nonzero local minima and feasible manifolds. | Excluded from M0-M4 baseline; reconsider only as a soft emitter after counterexamples are locked. |
| LIT-COCO | [Hansen et al., 2016](https://arxiv.org/abs/1605.03560) | Advocates anytime fixed-target runtime distributions and empirical cumulative comparisons for black-box optimization. | Targets and cost units are fixed before comparison. | Changing truth/tolerance after results, ignoring compile/screen cost or reporting best seed only. | Record prefix checkpoints, wall time and oracle work; use family-clustered paired comparisons. |
| LIT-SNE-I | [Kotsireas et al., Part I](https://arxiv.org/abs/2208.08530) | Surveys root-finding methods for one or many solutions. | Method-specific smoothness, dimension and initialization conditions. | No single method covers arbitrary black-box nonlinear systems. | Maintain failure-family routing and a minimal control rather than selecting a universal solver a priori. |
| LIT-SNE-II | [Kotsireas et al., Part II](https://arxiv.org/abs/2208.08532) | Surveys optimization transformations and multi-solution approaches. | Transformation-specific assumptions and meaningful merit landscapes. | Spurious stationary points and representation-dependent basins. | Treat `norm(F)^2` as a search model, never as the final truth predicate. |
| LIT-FILTER | [Fletcher and Leyffer, 2002](https://doi.org/10.1007/s101070100244) | Separates objective progress from constraint-violation progress using a filter rather than one penalty. | Smooth nonlinear programming model and suitable globalization. | Piecewise-smooth branch switches and undefined geometry domains. | Reserve filter/restoration for the later guard card; do not multiply guards into M0 residuals. |
| LIT-DEFLATION | [Farrell, Birkisson and Funke, 2015](https://doi.org/10.1137/140984798) | Modifies a residual to avoid convergence to known solutions. | Isolated known solutions and a suitable nonlinear iteration/preconditioner. | Same target from multiple configurations, close roots, manifolds and new stationary points. | Not an initial baseline; any future use must recheck the undeformed canonical residual. |
| LIT-KRAWCZYK | [Breiding, Rose and Timme, 2020](https://arxiv.org/abs/2011.05000) | Uses interval Krawczyk methods to certify isolated nonsingular polynomial roots. | Sound interval extension and isolated nonsingular square root. | Arbitrary opaque black boxes, singular/manifold roots, and target algebraic identity. | Outside M0-M4. Configuration certification must remain separate from target identity proof. |

## Review rule

Before an experiment adds a new algorithm family, its card must add a row (or
reference an existing row) with explicit assumptions and break conditions.
Secondary tutorials, blog posts and benchmark leaderboards cannot be the sole
justification for production promotion.
