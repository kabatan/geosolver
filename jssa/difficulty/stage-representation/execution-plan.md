# Q39 実行手順（段階2の許可後だけ）

現在は実行禁止。利用者が予測をcommit・pushしたことを確認し、**別タスクで明示的な実行許可**を受けてから以下を行う。lockのUTCはローカル時刻の記録で、commit・pushや第三者時刻証明の代わりにはならない。

1. 予測・選択・ソースのhashを検査。凍結srcの一致、既存Python/PyNomad/mpmath依存関係を確認する。インストール・ネットワーク利用は計画に含めない。足りなければ停止し、実行不能として記録する。
2. `diagnostic-design.md`のproxy／process内hook／結果adapterだけを出力ディレクトリ内へ実装。srcへの差分は0。実装hashと差分、利用者の許可をexecution manifestへ記録する。静的なB行対応、53bit境界、同一始点、analytic無効、全段A/Bの配線を検査する。数値smokeもこの段階まで行わない。設計を変える必要が出たら先に予測改訂を固定する。
3. 1問ごとにbundle・bounds・32尺度probe・8始点×3seedを保存。分類不一致・未定義Bはそのまま記録し、別問題で埋めない。
4. 前段A/Bを実行して候補台帳を封印。その同じ候補を後段A/Bへ渡す。各問・seedでは、UTF-8の`front|id|seed`のSHA-256先頭byteの偶奇で前段A/Bの提出順を交替。後段は`[A→A,A→B,B→B,B→A]`を、独立の`rear|id|seed`hash先頭byte mod 4だけ左へ巡回させる。並列時もこの提出順を保存する。cache・可変mp状態は各worker内に限定。
5. 同定前の桁測定を保存後、元の`assemble_exact_results`で検証・同定。公式採点は**凍結版の `benchmarks.research_runner.assess_campaign` をそのまま呼ぶ**。4条件を別campaignにし、raw出力を既存v2のcase/seed形式に写すだけにする。
6. L・R0・混合分解・次数観測も固定仕様で完了し、成功・失敗・timeout・NAを全件報告。新しいseed、選び直し、都合のよい再試行はしない。クラッシュ再開は未着手jobだけ。部分完了のjobは元記録を残して失敗として数える。

**採点を変えない。** `assess_campaign`は`ExactAnswer.canonical_key()`で答え集合全体を比較し、余分な値／欠けた値、正常終了を判定する（research_runner.py:537–703）。近似許容誤差の独自採点や「1値当たれば正答」へ置換しない。manifestのproblem/reference/source/dependency/config hash、rawの同フィールド、seed一意性・欠測チェックも維持する。source_hashに加えて診断wrapper hashとarmを別フィールドに保存し、凍結完成solverの成績とは表示しない。参考答は採点側だけが読む。Phase Cの予算切れとprocess強制終了も元のstatus規則へ正直に写す。

## 資源上限・見積り

最大**4 worker、各1物理コア**をaffinityで固定。OMP/OPENBLAS/MKL/NUMEXPR等は各1thread、worker子プロセスも同じaffinityを継承。独立コアが4本なければworker数を減らす。各worker RSS 2 GiBを上限、全体8 GiB以下。symbolic子プロセスを含む同時使用コアは4を超えない。

| 範囲 | 枠数と計算上限 | worker秒の保守的上限 |
|---|---|---:|
| 通常4条件・25問 | 前段1,200×6秒、後段2,400×8秒、同定・検証300×20秒 | 32,400秒 |
| L・7問 | 4条件分を丸ごと再計算した場合の上限。共通Aは再利用可 | 9,072秒 |
| R0・21問 | 前段候補1,008個×8秒、2由来×21問×3seed×20秒 | 10,584秒 |
| 混合分解・1問×3比較 | 通常4条件と同じ上限。共通Aは再利用可 | 3,888秒 |
| 尺度準備・次数・観測の後処理 | 準備25×20秒、次数21×10秒、桁観測とadapter採点等の追加枠1,200秒 | 1,910秒 |
| 合計 | import・起動・I/Oの余裕を別途確保 | 57,854秒（約16.1 worker時間） |

4コアが常時使える場合の計算枠は約4.0時間。起動・端数batch・I/O込みで**4〜6時間を予算見積り**とする。新規計測をしていないので速度の実測予想ではない。1コアなら約16時間＋余裕。追加枠を使い切れば観測NAとして停止し、無断で延長しない。後処理も最大4 worker・1コア規則に従う。

1コマンドは`batch-id`を指定した最大4 jobだけ、外側150秒で停止。jobの単位は「前段8始点（48秒まで）」または「後段8候補＋同定（84秒まで）」とし、準備・採点も分割する。全campaignを1本の長時間コマンドにしない。標準出力はjob要約のみ。

ファイルはすべて**5,000,000 bytes未満**。writerは4,000,000 bytesで分割、`RLIMIT_FSIZE=4,900,000`を補助に使う。1候補につき観測点64個以内、必要な入力・最終点は別の小さいレコードに必ず保持。各raw/candidateを問・seed・始点・armごとに保存し、全軌道や巨大な一括JSONは作らない。writerの上限エラーも失敗の記録対象。
