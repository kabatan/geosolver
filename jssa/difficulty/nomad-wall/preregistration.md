## 問いと先行する中止基準

問い：局所 LM にあった不連続な hard feasibility 罰則による障害を、既定の完成 solver の第1段 NOMAD（disco_mads）にも帰せるか。

最初にコード監査だけを行う。呼出し経路、BB_OUTPUT_TYPE、目的関数、hard 制約の数値化、callback の成功／失敗、候補収集・最終検証を区別する。

**S0（必須中止）：既定 NOMAD が progressive barrier 等を使い、hard 不許容というだけでは評価を失敗させず、目的関数にも LM と同じ不連続な一定罰則を加えていないなら、292問の介入実験を行わず終了する。** PB という設定名だけでは判定せず、実際の値と呼出しを確認する。非有限な作図や計算例外を拒むこと、最後に元の許容条件で解を採否することは、単独では LM と同じ壁の証拠にしない。

予測 P0：NOMAD は専用の制約出力を使うため、LM の hard 行 1e4 と同一機構ではなく、S0 に該当する可能性が高い。この場合「Aの中心を担えるか：現時点では担えない」と報告する。PB があらゆる境界効果を消すという主張はしない。

## S0 に該当しない場合のみ実施する比較

母集団は minima/basins-323.csv の n_vars >= 1 の292問。選定は id と n_vars だけを用い、各 id の UTF-8 文字列 `Q14-nomad-wall-20261023|<id>` の SHA-256 を昇順に並べた先頭24問とする。同値なら id 昇順。成功率、既存の壁分類、所要時間、原問の答えを選定に使わない。選定表と入力ハッシュは実行前に保存する。選定後の除外・補充をしない。

条件 B は凍結版の通常動作。条件 N は NOMAD の探索中の hard 条件の扱いのみを緩和し、元の hard 条件を候補の採否・精密化・最終検証に残す。目的の等式部分、guard、作図、探索箱、出発点生成、乱数、予算、局所探索、厳密同定、採点は同一とする。EB なら hard 制約だけを有限の違反量を持つ PB に変更し、一定罰則ならその hard 罰則だけを探索目的から除く。実装上それだけを分離できなければ、交絡を隠さず未実施として報告する。監査後、成績を一切見る前に差し替え箇所を implementation.md に固定する。

公開 CLI → 本番 worker の完成 solver で比較する。sitecustomize を両条件に導入し、実 worker の NOMAD 呼出しと実効パラメータを記録する。seed は 0、1、2、各180秒・cores=1、外部監視188秒。最大4並列、BLAS等は1スレッド。問題・seed ごとに B/N を対にし、上記 SHA-256 整数と seed の和が偶数なら B→N、奇数なら N→B。開始点の受け渡しと元の最終判定が保たれることを観測する。全144実行の外部監視枠は4並列で約113分、起動等を含め2〜3時間を見込む。高負荷下の時間は参考値に限る。
