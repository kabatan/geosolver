# 初回失敗の計上と未起動分の補足実行

キャンペーンの最初の `--run` 終了後に固定。元の予測・対象・成功基準は変更しない。

初回スケジュールの144スロットに対し、raw が残ったのは121件。23件の内訳は次のとおり。

- 22件（11対）：ヘルパーが `campaign.py` または `selected-cases.csv` を開けず、solver CLI の起動前に失敗。元ログを保持する。
- 1件：HMMT-2020-FEB-GEO-08 / seed 1 / N。NOMAD の全200評価ログはあるが raw が無く、最終成否は不明。

**事前登録の「エラーも失敗」に従い、主解析ではこの23件を全て失敗とする。** 欠けた raw の場所には solver 出力を捏造せず、`observed_solver_result=false` と原因を明示した失敗記録を作る。元の121 raw はハッシュを保存し、一切変更しない。不明な時間と CPU は null とする。集計の時間中央値は欠測を除いた参考値とし、正答の分母144からは除外しない。

作業を完了するため、CLI 未起動の22件だけを `completion/` に補足実行する。選定は結果の良否でなく、初回ログが「ヘルパーのファイル読取り失敗」で、raw と audit の双方が無いことだけによる。元の条件・seed・180秒・元の callback patch を使い、B/N を同一 CPU で順次実行、最大2対並列（事前登録の上限4以内）。正常・誤答・solver 内のエラーとなった実行、audit がある最終結果欠測1件は再実行しない。

主解析の P1/P2 は初回の失敗を保持したまま判定する。補足では未起動22件を埋めた場合の正答数を別に示し、主解析へ混ぜない。両方で結論が同じかを報告する。単純な時間比較や環境障害による見かけの救済を、NOMAD の罰則除去の効果とは呼ばない。

この手順は事後の運用上の補足であり、新しい事前登録実験ではない。原因は FileNotFoundError として観測されているが、ファイルが一時的に見えなかった根本原因までは確定していない。src/、選定表、凍結したキャンペーン・介入コードは変更していない。

## 実施後の追記（上の計画・基準は変更しない）

補足でも子ヘルパーから空の一時フォルダを確認できないエラーが発生したため、`complete_sequential.py` で未起動分を1プロセスから順次実行した。ディレクトリ内にマーカーを置き、既に得られた成否はそのまま保持した。既存の片側にCPU記録がある対はそのCPUを引き継いだ。`completion-sequential-receipt.json` に切替時の4 rawのハッシュと終了状況を記録した。

22枠の補足で取得できた raw は21件。aime-2003-1-7 / seed 1 / B はhookログのみ残り、最終結果が得られなかったため、明示した欠測記録を作り失敗扱いにした。Nもrequestファイル欠落による `invalid_worker_request` で失敗した。これらを再実行して成功に置き換えていない。補足結果の主解析への混入も行っていない。
