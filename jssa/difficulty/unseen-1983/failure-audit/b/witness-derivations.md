## AIME-1996-13

`A=(0,0), B=(sqrt(30),0)`とし、三辺の長さから

```
C=(7 sqrt(30)/20, sqrt(930)/20)
M=(27 sqrt(30)/40, sqrt(930)/40)
```

を得る。`D=tM`とおくと、直角条件は`(-tM)·(B-tM)=0`。
`M·M=57/4, B·M=81/4`なので、非零の根は`t=27/19>1`。
面積比は`D.y/C.y=t/2=27/38`。従って`m=27,n=38,u=-7,v=5`とすると、
`27(-7)+38(5)=1`。全整数条件・正値条件を満たし、目標は65。

`t=0`はADの非退化条件で除外される。Cは上半平面にあり、Mは線分AD内にある。原文の線分条件を満たす枝である。

## AIME-1996-15

`α=∠DBA`とする。三角形ABCの角は`2α,3α,180°-5α`。
対角線が互いを二等分する条件と正弦定理から
`sin(5α) sin(α)=sin²(2α)`。
`0<α<36°`の枝では`α=15°`となる。

```
A=(0,0), B=(1,0)
D=((1-sqrt(3))/2, (sqrt(3)-1)/2)
C=B+D, O=C/2, r=7/9
```

この配置では`∠CAB=30°, ∠DBA=15°, ∠DBC=30°, ∠ACB=105°, ∠AOB=135°`。
全等式・不等式・非退化条件を満たす。数学的な目標は
`floor(1000×7/9)=777`で、上の整数境界778までの余裕は`2/9`ある。

ただし、凍結版の`safe_eval_expr_hp('(1000*r) // 1', context)`は
`unsupported operand type(s) for //: 'mpf' and 'mpf'`を返す。
公開DSL検証は合格するため、転記の誤りではなく、許可演算子と高精度評価の実装の不整合である。
`floor-operator-probe.json`に再現結果を保存した。

## AIME-1997-04

`A=(0,0), B=(10,0)`。CからA,Bへの距離は13なので`C=(5,12)`。
DからA,Bへの距離が等しいため`D.x=5`。Cの下にある外接枝では
`D.y=4-r`。距離ADの条件より

```
25+(4-r)^2=(5+r)^2
r=8/9, D=(5,28/9)
```

となる。Cの上の枝`D.y=20+r`では距離AD条件に正の解がない。
`m=8,n=9,u=-1,v=1`とすればBézout条件も成立する。
6組すべての中心間距離が半径和と一致し、4円は外接する。目標は17。

## HMMT-2022-FEB-GEO-07

公式解説の対角線上の枝を使い、`P=(q,q), q=5-sqrt(69)/2`とする。
`0<q<10`。`PA+PC=10sqrt(2)`なので、距離和の条件から
`PB=PD=13sqrt(2)/2`。これを二乗すれば`(q-5)^2=69/4`を得る。
四外心は

```
O1=(5,q-5), O2=(q+5,5), O3=(5,q+5), O4=(q-5,5)
```

であり、両対角線の長さが10なので面積は50。
辺の二乗を指定順に並べると

```
[169/2, 169/2-10sqrt(69), 169/2, 169/2+10sqrt(69)]
```

となる。第2最大値は`169/2`（第3最大値と同値）。DSLの「全6組のminのmax」もこの値を返す。
`a=169,b=2,h=1,k=-84`で`169h+2k=1`、目標16902。
四外心を定義する三角形はいずれも非退化である。

探索上の障害：通常の探索箱は`a∈[0,40], k∈[-10,10]`。
NOMADの25%拡張でも`a≤50, |k|≤15`。
Bézout証人は一般に`h=1+2z, k=-84-169z`なので、どの整数証人でも`|k|≥84`。
つまり整数証人の選び方だけでは箱内に正解を入れられない。
ただし高精度refinerは数学的な境界を使うため、箱外の正解があることだけからパイプライン全体の不可能性までは主張しない。

また第2・第3辺が同値なので、min/maxを含む残差は正解で滑らかとは限らない。近傍からの失敗を単に探索箱だけへ帰属させず、精密化・最終検証も別に記録した。

## HMMT-2023-FEB-GEO-06

`A=(0,0),B=(1,0)`。三角形ABDの角は`73°,77°,30°`なので

```
dx=2 sin(77°) cos(73°)
dy=2 sin(77°) sin(73°)
D=(dx,dy)
s=(dx²+dy²-1)/(2((dx-1)cos(30°)+dy sin(30°)))
C=s(cos(30°),sin(30°)), n=68
```

と置く。CはAから30°の半直線とBDの垂直二等分線の交点である。
数値的には`C≈(2.16632073,1.25072586), D≈(0.56975647,1.86358945)`。
全8個の凸性の外積が正であり、順序ABCDの厳密な凸四角形となる。
元のAngle関数への代入で`∠BCD=68°`、その他の全条件も確認した。
公式解説の円周角による計算`2(180°-2×73°)=68°`とも一致する。

## 実験と比較の読み方

- `runs/natural-900-*.json`：元DSL・元solverを公開APIでseed 201、900秒、1コアで新規実行。180秒の比較対象は採点済みassessmentの同一seed。各問1実行の診断であり、5 seedの成績改善率とはしない。
- `local/*-float.json`：凍結版の局所探索関数をそのまま呼ぶ。正解そのもの1点と、`x0=x*+ε max(1,|x*|)U[-1,1]`で全変数を摂動した6点。`ε=10^-4,10^-2`、乱数seedは2900,2901,2902。整数変数も摂動する。LMの既定上限80評価を変更しない。各起点30秒。
- `local/*-hp.json`：`ε=10^-4, seed=2900`の1点を凍結版の高精度refinerへ直接注入し、元のPhase C（最終検証・厳密化）へ渡す。探索箱の選別を通さない診断であり、自然求解ではない。refinerへ90秒、Phase Cまで含め120秒の上限。内部APIの周囲の精度は公開workerと同じ180桁にそろえる。
- `runs/near-180-*.json`：凍結版の全パイプラインを実行し、探索起点の選択関数だけを同じ近傍点に差し替える。探索法・条件・検証・厳密化は元のまま。正解を使った介入なので凍結版の通常成績とは混ぜない。
- `*-expanded-box-control.json`：上記に加えて探索箱を正解近傍が入るよう広げた介入。箱の改善だけで自然求解できたとは解釈しない。
- `local/*-exact-oracle.json`：閉形式から計算した550桁の既知配置を精密化・最終検証へ渡す追加診断。近傍からの収束成功と区別する。
- `runs/worker-memory-900-HMMT-2022-FEB-GEO-07.json`：元のworker.executeを900秒枠で実行し、結果をメモリから要約。答えなし、実行約802秒。NOMAD後の追加局所探索でも、642/619個の終点のうち採用された候補はそれぞれ0個だった。全artifactをファイル化せず、正規化したJSONの大きさ4,542,788 bytesとhashだけも記録した。公開APIの書出し／読戻しまで成功した試行とは区別する。
- `runs/natural-900-HMMT-2022-FEB-GEO-07-io-observed.json`：監査出力の大きさを理由に保存を中止した試行の失敗記録。solverの正誤は保存されなかったため不明。これを答えなしとは数えない。通常APIの初回artifact_missingの直接原因は確定できていない。
- `development-features.csv`：開発323問の埋込みDSLに対する静的な同一尺度の集計。`IsInteger_calls`はASTの呼出回数、Bézout条件は全4因子が整数変数である2積の和=1を検出する。修正履歴や開発への適応の因果関係はこの集計からは判断しない（Q29bの担当外）。
- `derived_point_constructions`はスクリプト内に列挙した点作図関数の呼出数に限る補助指標で、全消去点数を厳密に測ったものではない。主比較は自由変数数・等式数・不等式数・条件種類で行う。

各プロセスは1コア、同時に最大4計算。ファイル単位4,900,000 bytes未満を強制する。封印tarは一切読まない。元DSLとsrc、採点済み資料のhashは`manifest.json`で固定する。
