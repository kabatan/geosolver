# 汎用規則（段階A）

対象は入力DSLの意味である。問題文・ID・参照答え・過去の座標や消去式から条件を追加しない。既存 `algebraize.py` と `run_exact.py` は読み込み専用で、別ファイル `strong_translate.py` に拡張する。厳密計算の実装として、許可された Singular の経路を採用する。

## R1：目標への射影

常に新変数 T と `T - target = 0` を追加する。変数順はDSL変数の名前順、補助変数の名前順、T。全非零因子による飽和後、Singular の `eliminate(J, T以外の変数の積)` を一度実行する。非零の一変数式全ての最大公約多項式を取り、SymPyで実根を厳密に列挙する。消去式が0だけなら `nonfinite_target`。単位イデアルは `algebraically_empty`。

消去の根は複素配置や符号違いも含む候補集合であり、それだけでは解答としない。飽和イデアルの辞書式Gröbner基底も同じSingular呼出しで計算し、図の復元に使う。消去と復元を含め、1問の壁時間は合計600秒である。

## R2：必須の非零条件

`f != 0` は分母を記録して分子を多項式化し、その既約因子で順に `sat(J,ideal(f))` を行う。重複・非零定数は除く。順序は次数、式の文字列表記の順。因子を既存等式に登場する変数だけに限定しない。

厳密不等式 `a>b` / `a<b` は `a-b != 0` を含意するので飽和する。**非零は正負を表さない**。符号・閉区間・凸性・枝・交点の実在は元DSLの最終検証に残す。閉不等式を非零に置き換えることはしない。これにより境界の正しい解を落とさない。

以下の表で `D(U,V)=|U-V|²`、`N(l)=|l.direction|²`、`C(U,V,W)=cross(V-U,W-U)`。全命令に共通して、引数・戻り値の直線には `N(l)!=0`、円には `radius²!=0` と、明示半径があれば `radius!=0` を課す。正半径という符号は別途検証する。入れ子の匿名オブジェクトにも同じ規則を適用する。

| DSL命令・構文 | 機械的に追加する条件／等式と検証への持越し |
|---|---|
| `/`、負の整数乗、全有理式 | 分母の分子・分母因子≠0。明示の割り算では約分前の除数≠0も記録 |
| `<`, `>`, `!=`（条件欄・predicate内の比較・連鎖比較） | 左辺−右辺≠0。`>=`, `<=` は飽和しない。符号は復元時と最終検証 |
| `And` | 各必須条件の和集合。`Or`, `Not` は条件を強める危険があるため理由コード付き変換不能 |
| `Bound(x,(lo,hi),inclusive=False)` | 有限の各端点との差≠0。既定の `inclusive=True` は端点を除かない。値の符号は最終検証 |
| `Point`, 座標属性、`Vector`, `Dot`, `Midpoint`, `Centroid` | 固有の非零条件なし（有理式の分母は共通規則） |
| `Line(A,B)`, `Segment`, `Ray` | `D(A,B)!=0`（戻り値の方向から導出） |
| `Line(a,b,c)` | `a²+b²!=0`（方向と分母から導出） |
| `Circle(O,r)`, `Circle(O,P)`, `CircleThroughPoint` | `r²!=0` または `D(O,P)!=0`。rが明示されればr≠0も追加 |
| `Center`, `Radius` | 円の共通規則 |
| `Polygon` | 固有条件なし。図形についての宣言・使用命令があれば、その規則を追加 |
| `Triangle` | 3頂点の `C!=0` |
| `Distance`, `Length`, `Perimeter`, `sqrt`, `abs`, 多角形の `Area` | 距離0・面積0は一律には除かない。根号 `s²*den-num=0`、den≠0。主値s≥0は復元にも利用。直線・円の引数は共通規則 |
| `Intersect` / `IntersectLines`（直線×直線） | 方向の外積≠0。交点座標の定義等式 |
| 同（直線×円） | 有効な直線・円、交点の接続等式。判別式≠0は課さない（接点が許される）。実在・n/near/farの枝は元DSL検証 |
| 同（円×円） | 中心間距離²≠0と両円の接続等式。接点を除かない。実在・選択枝は元DSL検証 |
| 同（`exclude=P`） | 結果とPの距離²≠0も追加。除外点が既知交点なら既存の代数的反射・他方の根の公式を使用 |
| `FootOfPerpendicular`, `ClosestPoint`, 直線への `Reflect` | 射影先直線の方向≠0・式の分母≠0。点中心のReflectは固有条件なし |
| `PerpendicularLine`, `ParallelLine`, `PerpendicularBisector` | 入出力の方向≠0（垂直二等分線ではD(A,B)≠0） |
| `Angle`, `AngleBisector` | 角を作る2本のベクトルの長さ²≠0。二等分線は結果の方向≠0も追加。一直線のAngleは一律には除かない |
| `Circumcenter`, `Circumcircle`, `CircleThroughThreePoints`, `Orthocenter` | 三点の外積≠0、分母≠0、結果が円なら共通規則 |
| `Incenter`, `Incircle`, `Excenter`, `Excircle`, `IncircleContactPoint` | 三点の外積≠0、辺長の（符号付き）和など式の全分母≠0、結果が円なら共通規則 |
| `ContactPoint`, `Polar` | 円・直線の共通規則と射影式の分母。PolarはPと中心の距離²≠0 |
| `Tangent`, `TangentLine` | 円と結果直線の非退化。接点の円上条件と直交等式で存在を緩和。実在・枝は最終検証 |
| `PointOnLine`, `PointOnSegment` | 直線の方向≠0、線分の端点間距離²≠0。線分の区間・端点は最終検証 |
| `Rotate`, `Degrees`, `sin`, `cos`, `tan` | 三角定数はR3。tan等の分母≠0。未対応の角演算は変換不能 |
| `OnLine`, `OnSegment`, `OnCircle`, `Parallel`, `Perpendicular`, `IsTangent` | 参照直線・線分・円の非退化と、既存変換器の接続／内積／接触等式。区間・内外接の区別は最終検証 |
| `Collinear`, `AreConcyclic` | 既存の行列式等式。述語だけから全点相異・非共線を勝手に仮定しない |
| `ConvexPolygon`, `AssumeConvex` | 全頂点対の距離²≠0、全ての連続三頂点の外積≠0。向きの一致と自己交差なしは最終検証 |
| `SimplePolygon` | 全頂点対の距離²≠0。一直線の連続辺は機械的に除かず、自己交差は最終検証 |
| `AcuteTriangle` | 非共線、全3頂点の内積≠0（正も記録）。`ObtuseTriangle`は非共線だけ。一つの頂点を人が選ばない |
| 未知命令、`IsInteger`, `RightTriangle`等の元変換器未対応命令 | 変換不能。条件を黙って削除して求解しない |

「交点が存在する」は一般には非零だけでは表せない。例えば直線と円の接触は存在するが判別式が0である。ここは接続等式と実図の最終検証で扱い、判別式≠0を追加する誤りを避ける。したがってR2は**含意される非零条件の飽和**であり、実閉体の完全な量化消去ではない。

各入力の `*.work/translation.json` に導出元命令・式・演算子を記録し、結果JSONに実際の飽和因子を残す。

## R3：定数

有理数はQ係数。有限小数は有理数として読む。有理数倍πのsin/cos、およびRotateの実代数的定数には最小多項式と新変数を作る。元の式・最小多項式・意図した根の80桁表示を記録する。射影では共役根も許すが、復元時に数体上の厳密比較で意図した根を選び、最後は元DSLの定数でも検証する。表示の小数値を方程式の係数には使わない。根号は既存の二乗等式と主値の条件を使う。

π単体・πを係数に持つ目標・円面積は `NONALGEBRAIC_PI`。他の非代数的／非実の定数は `NONALGEBRAIC_CONSTANT`。πを因子として取り除いた別目標は作らない。角度のπはsin/cosや角の等式という文脈でのみ許す。記号角の非整数係数や角度値の目標など、既存変換器の未対応形は理由コード付きで停止する。

## R4：DSL未知数0

定数・構文が変換可能かを同じ変換部で確認した後、代数ソルバーを一切呼ばず、空の座標列を凍結版 `verify_final_candidate` に渡して直接評価する。補助根号変数の数でこの分岐を決めない。結果の `algebra_solver_calls` は0。πなどR3で禁止した入力をこの分岐で救済しない。

## 図の復元と結果の意味

辞書式基底の後方からTを固定して厳密な一変数実根を列挙する。自由座標には全入力共通の順序 `(0,1,-1,2,-2)` の有理標本を使う。最大4096節点。この操作は代数ソルバーの再実行でも問題別パラメータの選択でもないが、自由な解集合の完全探索ではない。参照解、過去の座標、数値最適化、geosolverの探索部は使わない。

復元したDSL変数を100桁作業精度で凍結版最終検証器に渡し、返却答えが対応するTと一致した配置だけを採用する。主値根号、厳密不等式、代数定数の根の選択は復元の枝刈りにも使う。

| 区分 | 意味 |
|---|---|
| `verified_complete` | 全ての射影実根が、許容図の証人を持つか、有限・厳密な枝の全列挙で矛盾した |
| `verified_subset` | 証人のある値は得たが、他の射影根の可否は未解決。答え集合の完全一致とは扱わない |
| `lift_unresolved` | 射影根はあるが、許容図を確認できなかった |
| `nonfinite_target` | Tを一変数の非零多項式に閉じ込められない |
| `algebraically_empty` | 飽和後の代数系が空 |
| `direct_verified` / `direct_unresolved` | R4の直接評価の検証成否 |
| `unsupported` | 理由コード付き変換不能 |
| `timeout`, `resource_limit`, `worker_error`, `error` | 計算の打切り・失敗。空の答え集合とは同一視しない |

自由標本の失敗、最終検証器の不合格、根の扱いの未対応は `unresolved` にする。これらからT全体の不存在を結論しない。`verified_complete` も凍結版の数値最終検証契約に対する記録であり、形式証明器による証明ではない。

## 人が問題別に調整していない根拠と実行範囲

求解ワーカーの入力はIDとDSLだけ。IDはファイル名・記録用で、変換／求解の分岐には使わない。親が元JSONLから `answer`, `problem_statement`, 過去結果等を除いて `input.json` に保存する。唯一のID列挙は段階Aの5問許可リストであり、変換規則ではない。定数、順序、標本、予算は全入力で共通。既存posthocの式・座標・飽和済みイデアルを読み込むコードはない。

開発前の合成入力テストを `smoke_checks.py` に残す。開発5問は凍結したコードで各1回だけ実行し、実行時のコードハッシュを結果に残す。集合の参照値照合は報告作成側だけで行う。これは既に見た5問での動作確認であり、未知問題の性能評価ではない。

各問で600秒（変換・代数計算・復元・検証の合計）、各プロセスの仮想アドレス空間8 GiB、問ごとの子孫プロセス合計RSS8 GiBを0.1秒間隔で監視する。RSSの瞬間的な超過はこの監視間隔まで検出が遅れ得る。4並列・各1 CPU。2,900,000 byteのファイル上限を課す。問固有の新規プロセスグループだけを終了させ、他タスクには触れない。`.work` ディレクトリの新規作成が試行台帳で、同じ出力先の再実行は拒否する。再試行・フォールバック予算・システム導入はない。
