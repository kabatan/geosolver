# 事前登録15：素朴な数値最適化から工夫を順に足すと、性能はどこで上がるか（S8）

固定日時：この文書の commit・push の時刻。下の「実行前に固定するもの」を push するまで本計測はしない。

## 目的

本人の問い：「工夫のない素朴な数値最適化では幾何の問題は難しいのに、solver はなぜ高い成功率で速く解けるのか。秘密があるのか、それとも基本のアルゴリズムが単体で強いのか」。1つずつ外す比較（S4.4、S4.6、S4.7）は、ほかの段が補うので差が出にくかった。そこで、素朴な版から工夫の群を solver の処理の順に1つずつ足し、どの群で成功と速さが上がるかを測る。あわせて、素朴な版にそれぞれの群を1つだけ足した版も測り、群ごとの単独の効果も見る。

## 構成

工夫の群（既存のスイッチで止める。正確な環境変数の対応は「実行前に固定するもの」で決める）：
- G1 探索：NOMAD による1段目（止めると局所探索の多点出発。GEOSOLVER_ABLATE_NO_NOMAD または SEARCH_MODE）
- G2 探索の重ね：第2探索と救済の探索（NO_SECOND_ATTEMPT、NO_RESCUE）
- G3 候補の選び方：散らして選ぶ（NO_DIVERSE_SELECTION）
- G4 式の書き直し：残差書き換え一式（NO_RESIDUAL_REWRITE）、尺度座標（NO_SCALE_CHART）
- G5 代数：代数的前処理（NO_ALGEBRAIC）
- G6 微分：解析的なヤコビ行列（NO_ANALYTIC_JAC）

どの構成でも、入力（作図と条件）、最終検証、PSLQ による同定は凍結版のまま。作図で変数を減らすことは入力の書き方そのものなので、ここでは止めない（S4.5 を参照）。

| 構成 | 内容 |
|---|---|
| N | 素朴：G1〜G6 を全て止める |
| N+1 … N+6 | 素朴に G1〜G6 のどれか1つだけを戻す |
| C1 | N + G1 |
| C2 | C1 + G2 |
| C3 | C2 + G3 |
| C4 | C3 + G4 |
| C5 | C4 + G5 |
| BASE | C5 + G6（凍結版の既定） |

N+1 は C1 と同じなので1回だけ実行する。合計 N、N+2〜N+6、C1〜C5、BASE の12構成。

## 対象と実行

- 対象：開発外34問（S3）と、機構を調べる72問（S4.6）の計106問。
- seed 601〜603、180秒、1コア。構成の順は問題と seed で回す。2台の PC に問題単位で分け（割り当ては sha256 順で実行前に固定）、同じ問題の全構成は同じ PC で行う。
- 解けた：3 seed 中2回以上で答えの集合が完全に一致。費用 C：正解なら実時間、それ以外は180秒。

## 実行前に固定するもの（本計測の前に push）

1. 各群と環境変数の対応表、および組み合わせの動作確認（各構成で2問を1回ずつ動かし、スイッチが効いていることを記録で確かめる。正誤は記録しない）。ある群を止めると他の群が働かなくなる依存関係があれば、それも記す。
2. 2台への問題の割り当て。

## 予測

- B1：N で解ける問題は106問中60%以下（BASE は90%以上）。
- B2：C1〜BASE の累積で、解ける問題が最も増えるのは N → C1（NOMAD）。
- B3：単独で戻したとき（N+k）に解ける問題が最も増える群と、累積で最も増える群は同じ。
- B4：費用 C の平均は、N が BASE の3倍以上。
- B5：G4（式の書き直し）は、単独（N+4）では解ける問題を3問以上増やさないが、C3 → C4 では費用を10%以上下げる。

## 読み方

- B1 が外れて N でも90%近く解ければ、「基本のアルゴリズム（作図による入力と、多点出発の局所探索と最終検証）だけで強い」と書く。
- B1 が成り立てば、差を作った群を累積と単独の両方から示す。累積と単独で順位が違えば（B3 外れ）、群どうしの補い合いがあると書く。
- 外れた予測もそのまま報告する。106問のうち開発外34問は易しめ、72問は差の出やすい問題を多めに選んだ組なので、全問題の平均とはしない。
