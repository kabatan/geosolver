変換規則 Q38-stage1-v1。対象は `60db4b679b04167175c51c479c87c22fa663fda0` と同じ `src/`、同じ `benchmarks/cases.jsonl`。実装は `prepare.py`、定数は `rules.json`。数学的に同じ問題でも有限時間の数値探索が同じになるとは仮定しない。

| mode | 変更するもの |
|---|---|
| original | 元DSL。対照として3 seedを新たに測る計画のみ |
| point_names | 元の作図順に点名を列挙し、1個左に循環させる全単射。宣言名と全参照を同時置換 |
| variable_order | `variables` の配列だけを逆順。名前と式は保存 |
| condition_order | `conditions` 全体を逆順。各条件の中身は保存 |
| orders_combined | `variables` と `conditions` の両配列を逆順。点名は保存 |
| combined | point_namesと同じ改名＋変数順・条件順のハッシュ置換 |

5変換は原本と別々の5本。各問で6文書が相互に異なることを検査する。全変換で問題IDは元のままとし、mode別のコーパスに分ける。改名は新しい点を作らず、既存の名前の間だけで行う。作図に含まれる線・円・scalarの名前は変更しない。点の認識は根の関数が `rules.json:point_roots` に載る作図だけ（今回選ばれた40問の点作図を覆う明示リスト）。別のDSLへの一般的な型推論器ではない。

ハッシュ順は UTF-8 の `salt + "|" + 元の0始まり添字` の SHA-256 昇順、同値なら添字順。saltは `Q38/variables/v1/<id>`、`Q38/conditions/v1/<id>`。変数・条件が偶然恒等置換なら1個左へ循環する。作図行の順序は全modeで元のまま固定する。未定義参照・変換の重複があれば停止し、結果を見て問題を差し替えない。

保存するもの：変数の集合・個数、作図の行順、自由点と作図点の役割、原点・軸・尺度の入力表現、式中の数値の綴り・JSON数値の値と型、各演算と引数順、左右辺と比較演算子、条件の重複数、target、交点selector、向き、内外・順序・開閉境界、整数条件、答えと採点情報。変数の増減、定数の丸め、式の簡約、項や関数引数の交換、式の追加削除はしない。JSONの空白は全mode共通の書式にする。

名前の書換えはPython ASTの **束縛された `Name` 節点の位置だけ** に施し、その他のUTF-8バイトを保存する。関数名、`.x` などの属性、keyword名、文字列中の `'A'` や `'BC'`（三角形の局所selector）は変更しない。`near=A` の値は参照なので改名する。単純な文字列全置換も `ast.unparse` による式全体の再生成もしない。後者は数値の綴りを変え得るため。

数学的同値性は次の十分条件で検査する。

1. 改名の逆写像を適用し、変数集合が同一、作図が行順も含め同じ名前→同じ式の依存DAGであることを確認する。凍結版の公開DSL validator/compilerに渡し、前方参照・構文・名前解決も検査する。
2. 各式をAST化し、位置情報以外の全節点を比較する。数値リテラルの元の綴りも別途比較する。等式、不等式（`!=`を含む）、predicateを別々の**多重集合**として比較し、条件の脱落・複製も拒否する。predicate内部のAnd/Or等は分解せず、構文木全体を保存する。
3. targetも同じASTであることを要求する。さらに全配列を逆置換したJSONが、式の文字列と数値型も含め元文書に完全一致することを独立に確認する。

これは一般の式の同値性を数値点で推測する方法ではない。各作図の値を依存順に帰納すると、定義可能な任意の元の変数代入に対して、改名後の対応する点・条件・targetは同一となる。変数順は `new[j] = old[variable_new_to_old[j]]` で対応する。全単射なので逆方向も成立し、定義域、解集合、答え集合が対応する。並べ替えに伴う浮動小数の評価経路の差は、ここで禁止している数学的変更とは区別する。

`transformations.json` に全240文書の置換・逆写像・ファイルSHAを保存する。`static-validation.json` は全240文書の検証記録。新しい正解図の探索や数値代入はしていない。元DSLの解の存在・原文との一致を新たに証明したとは主張しない。保存済み正解図を使う追加検算が必要になった場合も、上の変数置換と点名写像で代入を移し、全等式・不等式・targetを評価するだけに限る。局所探索や補正は段階1の対象外。

選定は開発群323問と既存 `minima/basins-323.csv` の結合。`status=ok`、DSL変数数と記録が一致、2変数以上を適格とする。249問が適格、残り74問（status不適合31、残る2変数未満43）は理由付きで `selection-universe.csv` に残す。既存成功率pを `0`, `0<p<0.1`, `0.1<=p<0.9`, `0.9<=p<=1`、変数数を `2–3`, `4以上` に分け、8層から各5問。層内は SHA-256(`Q38/select/v1|<id>`)昇順、同値ならID辞書順。pは元の局所探索の実測値であり、完成solverの正答率ではない。既存の出発点数が200でない問も保存値をそのまま使う。

層の母数は順に、2–3変数が9/9/57/63、4以上が19/17/62/13。標本は難しい局所探索層を厚くした目的抽出であり、40問の割合を323問全体の割合と呼ばない。未使用群、Q34の問題名や結果、今後の実行時間・正誤は選定に使わない。`selection.csv` に40問・p・次元・順位を固定する。
