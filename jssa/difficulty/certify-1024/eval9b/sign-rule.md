# 9b：±の機械判定（実行前固定）

DSL の `target` 文字列を Python `ast.parse(..., mode='eval')` で構文木にする。式を評価せず、問題ごとの判断、条件式からの符号推論、変数・構築名の別名展開はしない。

非負形の文法は次のとおり。

- 非負の原子：関数名が `Distance`, `Length`, `Perimeter`, `Area`, `Radius`, `sqrt` の直接呼出し。`sqrt` は実数の主値として扱う。引数内の式の符号は推論しない。
- 非負の原子の和・積を許す。非負の数値リテラルを和の定数項・積の係数に使ってよい（例：`2*sqrt(...)` は同じ非負量2個の和）。ただし式全体には少なくとも1個の非負の原子を必要とする。
- AST の `BinOp(Add)` と `BinOp(Mult)` だけを合成として認める。括弧はASTに残らない。負号、除算、べき乗、差、その他の関数・属性・名前だけの式は認めない。原子の引数内にはこの制限を適用しない。キーワード引数は認めず、空の呼出しも認めない。
- 数値リテラルは有限な非負の int / float（boolを除く）に限る。構文解析不能な式も非負形に数えない。

文法に合えば CSV は「非負形で正の根」、説明は「非負の量なので正の根」。それ以外は CSV は「solver数値で選択」、説明は「±の選択はsolverの数値で選んだ」。後者は事前登録9の同じ保存済みsolver値を指し、追加の数値探索・証明条件は導入しない。

非負は厳密には0を含む。負の値を除く理由を与えるだけで、一般のpにある複数の非負根の選択、一意性、実図の存在、答え集合の完全性は証明しない。qが非所属でも同じ構文判定を記録するが、C7の分母・分子にはqの認証成功例だけを使う。
