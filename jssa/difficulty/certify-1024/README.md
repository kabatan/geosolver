# certify 段階A：dev5だけの動作確認

保存済みの答えの最小多項式 p(T) が、入力DSLから作った飽和イデアルJの根基 √J に属するかを検査する仕組みを作った。**2問で所属と独立検算まで確認**した。評価用の問題には実行していない。開発5問の結果であり、未知問題の成功率を示すものではない。

## 結果

「秒 / 要素数」は次数順序基底の計算時間＋正規形の計算時間、および基底の要素数。飽和・証拠抽出・検算は別計上。区間ごとの計時は1ms単位で、0.000は処理がなかったという意味ではない。詳細は [per-problem.csv](per-problem.csv)。

| 問題 | 判定と実行状態 | べき法：秒 / 要素数 | Rabinowitsch：秒 / 要素数 | 全体秒 | 独立検算 |
|---|---|---:|---:|---:|---|
| AIME-2005-I-01 | πのため変換不能 | — | — | 1.360 | 対象外 |
| AIME-2012-I-14 | 所属、m=1 | 0.000 / 5 | 0.000 / 1 | 0.971 | 両方○ |
| HMMT-2011-FEB-GUTS-01 | 実装エラー、判定できず | 無効 | 無効 | 1.318 | 不可 |
| HMMT-2019-FEB-GUTS-17 | Rab法で非所属。後処理でメモリ上限 | 0.035 / 64 | 87.237 / 120 | 384.089 | 非所属の独立検算は未実装 |
| HMMT-2023-FEB-GUTS-03 | 所属、m=1 | 0.000 / 7 | 0.000 / 1 | 1.240 | 両方○ |

- HMMT-2019のp〜p⁴は全て正規形が非零。べき法だけでは未決だが、Rab法は終了して非所属となった。総合実行状態は `resource_limit` のまま残す。飽和204.764秒、RSS監視ピーク8.019 GiB。判定後の不要な式の構築で上限を検出して終了した。
- 所属した2問の飽和時間は順に0.001、0.005秒。証拠抽出はべき法/Rab法の順に0.000/0.000、0.038/0.001秒。独立検算は0.012/0.008、0.040/0.037秒。
- タイムアウト0、所属の証拠を検算できた問2、変換不能1、実装エラー1、資源上限1。全問各1回、再試行0。実装エラーを非所属に数えていない。

## p(T)の出典と枝

変換可能な4問すべてで、既存 `unseen-2/{a,b}/execution/runs/<ID>/301.json` の `solver_result.answers[0].value.minimal_polynomial` を取得できた。上表の順に **T−375、3T−1、75T²−120T−436、T²−21**。係数は高次から並ぶ。元ファイルのSHA-256、JSON内の位置、値は [candidates.json](candidates.json) に保存した。

今回は厳密法からの代用は0件。見つからない場合、既存の厳密消去式から答えを含む既約因子を取り、`exact_elimination_factor` と明記する経路も実装したが、dev5でこの代用経路は実証していない。保存記録はsolverの同定結果であり、内部の特定のPSLQ呼出しまで追跡したという意味ではない。

**実根のどれを採るかはsolverの保存された高精度値で選ぶだけで、証明の対象外。** 4問とも対応する根を選べたが、その小数値や選んだ根をJの条件には追加していない。実図の存在、解の一意性、答え集合の完全性は証明していない。AIME-2005-I-01はπを含むため変換不能とし、別目標への置換や解決は試みていない。

## 構築と検算

既存 `exact-strong-1024/strong_translate.py` と `run_strong.py::prepare` をimportして再利用した。元のファイルは変更していない。R1の目標変数と定義等式、R2の非零因子、R3の代数定数を引き継ぐ。R4の直接評価には分岐せず、変換可能ならJを作る。依存ファイルのハッシュは実行manifestに記録した。

Fを目標定義も含む元の等式、hᵢを非零因子とし、既存処理と同じ順序で `J=sat(J,ideal(h_i))` を適用する。明示的な環は全てSingularの **dp（degrevlex、次数逆辞書式）**。T以外の消去や辞書式基底は作らない。飽和手続きの内部処理はSingularのライブラリに任せる。

1. G=std(J) を作り、p, p², p³, p⁴の正規形を全て保存する。どれか0なら所属。全て非零でも根基への非所属とは言えない。
2. J+⟨1−yp⟩の基底を作り、1の正規形を調べる。0なら所属、非零ならこのJの根基には属さない。正しく終了した計算に限る。
3. 所属時は元のFと逆数条件に対して `lift` の係数を保存する。修正版では各hᵢに変数zᵢを付けてK=⟨F, 1−zᵢhᵢ⟩とし、次を確認する。

   - べき法：ΣAⱼFⱼ + ΣBᵢ(1−zᵢhᵢ) = pᵐ
   - Rab法：ΣAⱼFⱼ + ΣBᵢ(1−zᵢhᵢ) + C(1−yp) = 1

Kを元変数へ縮約するとJになる。初期版のAIME-2012の証拠は同値な `1−z∏hᵢ` を使う。両形式を検算器で扱える。

**Singularを呼ばない `verify_certificate.py`** が、Python側で先に保存した元のF・hᵢと照合し、SymPyの有理数係数多項式として上の恒等式を展開する。Singularが返した飽和後のJだけを信頼する検算にはしていない。独立なのは恒等式の検算であり、DSL翻訳そのものの形式証明ではない。非所属について飽和や基底の正しさを独立に証明する仕組みは未実装。

## 制限と開発中の失敗

1問600秒、仮想アドレス空間8 GiB、子孫込みRSS 8 GiB、1 CPU、逐次実行。並列数は指定の最大2以下。変換・飽和・両手法・証拠抽出・検算を同じ枠に含めた。RSSと壁時間は0.1秒ごとに監視し、その問のプロセス群だけを終了するため、検知までの小さな超過はあり得る。出典の収集と報告作成は構築処理として枠外。各ファイルを2,900,000 byte以下に制限した。

初期版には二つの不備があった。

- Singularでは `x^2/4` が `x^(2/4)` と解釈され、HMMT-2011で構文エラーになった。エラー後も0の正規形マーカーが出たが無効である。CSVでその所属マーカーや基底値を採用していない。修正版は整数多項式全体を括弧に入れてから分母で割り、エラーのある出力を棄却する。
- 非所属でも証明書用のKを作り、HMMT-2019で非零因子の積の展開がメモリ上限に達した。修正版は所属時だけKを作り、因子ごとの逆数変数を使って大きな積を展開しない。

**失敗した問を再実行していない。** 初期版で4問を実行した後、ソース固定の検査で処理を止め、未実行だったHMMT-2023だけ修正版で実行した。従って5問を同一版の性能測定として扱えない。初期版は `executed/` に保存し、コピー元・SHA-256を `development-changes.json` に記録した。

`smoke_checks.py` は合成入力だけで、m=2、m=5、非所属、飽和必須、複数の逆数条件、有理係数、単位イデアルの7例を確認した。証明書の改変、エラーログの無効化、初期版証明書との互換も確認した。m=5ではべき法は未決、Rab法だけ所属となり、独立検算も通る。

## 予測固定時に決めること

- **成功の提案**：固定したsolver記録由来pについて、変換完了、Jが非単位、Rab法で所属、元の等式からの証明書を少なくとも一方で独立検算でき、べき法との矛盾がないこと。これは「多項式関係の認証」であり、答え全体の正しさの証明とは分ける。
- Jが単位なら全ての式が属するが、矛盾からの空虚な証明なので成功から除く。非単位でも実解の存在は保証しない。
- 非零は符号・区間・凸性・根号の主値を表さない。Jは元の実条件より広い複素解を持つため、正しい実数の答えのpでも非所属になり得る。非所属をsolverの誤答と同一視しない。
- 既約因子を選ぶ行為と消去式の積全体が消えることを混同しない。厳密法の代用因子は主指標のsolver認証から除き、別集計する。
- 全問を母数とする率、変換可能な問を母数とする率を分ける。未変換・時間上限・資源上限・実装エラー・検算不能の扱い、複数答えを全て要求するか、600秒内の処理順を事前に決める。枝の選択可否と証明の成否は別欄にする。
- 全問評価は別タスク。コード・依存物・候補取得規則・成功定義・予測を先に固定する。

## ファイルと使い方

`certify.py` が候補取得からCSVまでを処理する。`runs/*.work/` に入力、変換、Singularスクリプト・ログ、基底・正規形、成功時の係数と検算結果がある。`run-manifest.json` と `continuation-manifest.json` が各実行版を記録する。

使用環境は `/tmp/q38-58e3993-venv/bin/python`、SymPy 1.14.0、Singular 4.4.1。PATH先頭は `/tmp/q6-tools/bin` のwrapper。導入・昇格コマンド、commit/pushは行っていない。

```bash
# この出力先では実行済み。既存台帳があるため再実行しない。
PYTHONDONTWRITEBYTECODE=1 /tmp/q38-58e3993-venv/bin/python jssa/difficulty/certify-1024/certify.py --prepare
PYTHONDONTWRITEBYTECODE=1 /tmp/q38-58e3993-venv/bin/python jssa/difficulty/certify-1024/certify.py --run-dev5
```

`*.work` の排他的作成で試行を記録し、同じ問の再実行を拒否する。開発中の続行は `--finish-unattempted-dev5` で台帳のない問だけを実行した。評価用IDを許可するオプションはない。`--report` は保存済み記録からCSVを作るだけ。

検算器は `verify_certificate.py <証明書JSON> --model <translation.json>` でも使用できる。実行時には既に各問の600秒枠内で検算済み。
