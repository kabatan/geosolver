# Q43c の所見を主張にする場合の確認設計（未実施）

これは探索結果を見た後の設計案で、今回の予測の事前登録ではない。今回の200試行には適用せず、問題・seed・予算・採点を変更しない。新規の実験はこの継続では起動しない。

検証する主張は「条件の解を得る難しさと、そこで問う量を厳密な形式に同定する難しさは別であり、後者だけで完成solverの成功が変わる」。一般の幾何の難易度や、人間には解けない現象を主張しない。

1. 全担当の使用履歴を照合し、solver出力をまだ見ていない入力だけから20問を確保する。今回の20問と、他タスクが既に使った unseen_a/b は確認群と呼ばない。各問の原問・長さ・面積・角・比を今回と同じ点選択規則で作り、5つの量の正答集合が有限で、対象の点・角・分母が定義されることを実行前に独立に確認する。この確認は交換による問題の未定化を除くためで、solver結果による選別にはしない。選択順は `SHA256(431024:q43c-confirm-v1:id)` の昇順。不適格理由と全候補一覧も固定する。20問確保できなければ「設計未成立」として始めない。
2. 20問の入力、参照する正答集合、スケジュール、以下の予測と閾値、凍結版・採点器のハッシュを実行前に保存してcommitする。一般の逆三角関数など、参照値を凍結採点器の形式に変換できないものは実行前に記録し、正答率の分母を区別する。採点器を拡張して埋め合わせない。今回は探索なので、現在の記録を遡って「予測的中」にしない。
3. 将来の確認では、現行と同じ凍結solver、180秒・1 core・2並列で20×5×2＝200試行を使う。外部seedは43101/43201とし、内部の連続5 seedが重ならないよう実行前に固定する。今回の43101/43102はそのままで、試行を追加しない。順序は事前に固定し、失敗の置換や追加試行をしない。共有負荷を記録する。時間差は副指標とし、速度の因果主張を主要な結論にしない。
4. 主要な予測を次の3つに限定する。P1：各seedで、5 targetすべての `numeric_feasible` が一致する問題が18/20問以上。P2：各seedで、targetによって `public_solved` が分かれる問題が6/20問以上で、そのうち少なくとも5問は両seedで同じ成功・失敗の組になる。P3：原問で答えが出たのに交換後に出なかった試行の75%以上で、凍結版の `numeric_feasible=true` を記録する。P3の分母が0なら未成立。参照形式が対応するtargetでは正答集合との一致も併記し、非対応では正答率を算出しない。値が返ることと正答を混同しない。
5. P1〜P3のどれかが外れれば、この一般化は採用しない。係数が大きい1問や、単純なπの倍数だけが成功することしか残らなければ、答えの同定機能の制約を示す補足結果に留める。Aの中心成果へ昇格させる条件とはしない。

多項式の係数上限と追加探索の関係は、今回の保存済み記録とコードで説明する観察である。係数上限を緩めたり、探索を変更した介入で原因を切り分けたわけではない。そうした介入を今回の再開実験に混ぜない。
