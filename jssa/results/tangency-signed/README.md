# 実験②：符号付き・平滑な残差の書き換えの有無（同じ候補を精密化）

## 何を止めたか（1行）

高精度の精密化で使う「接条件・距離ゼロ・半径の契約の書き換え」（`mpmath_refiner._smooth_zero_constraint_residuals`）を、環境変数 `GEOSOLVER_ABLATE_NO_SIGNED_TANGENCY=1` で丸ごと止めました。この書き換えには、接条件（符号付きの距離や二乗距離）のほかに、距離ゼロ→座標差、半径の契約の補助式も含まれます。接条件だけを分けて止めたわけではありません。

## 方法

- solver本体（60db4b6）は変えていません。実験用ブランチ `search-mode-ablation`（`67ad79a` + 環境変数の切替）で、`NO_SIGNED_TANGENCY` のスイッチを足しました。
- 対象は、接条件（`IsTangent`）を含む24問のうち、探索で候補が作られて精密化が走る12問です。seed 0、1問180秒、1コア。
- 各問題で、主探索が終わり精密化に入る直前に、同じ候補の集合を、書き換えなし・ありの両方で精密化しました（各90秒を上限）。その後は通常どおりに続けています。
- 順序の影響を見るため、「なし→あり」と「あり→なし」の2順序で、問題ごとに別のプロセスで実行しました。結果の桁数は2順序で同一で、時間も1.3倍以内で一致しました（上限に達した実行を除く）。
- 桁数は、精密化後の残差のノルム（元の評価器で測った値）の `-log10` です。大きいほど精密です。負の値は、残差が1より大きいことを意味します。
- 列は `per-case.csv`（問題×順序）と `per-candidate.csv`（候補ごと）にあります。

- 書き換えありでは、最良の桁数が300桁を超えた問題が11問です（HMMT-2022 は119桁）。書き換えなしでは、5問です。
- 書き換えなしで最良の桁数が50桁未満にとどまった問題は7問で、8〜48桁で止まっています（AIME-2018-II-14、HMMT-2008、HMMT-2022、HMMT-2023、JMO-2013、JMO-2024、aime-2002-2-14）。
- 差がない問題が4問あります（AIME-2015-II-15、HMMT-2009、HMMT-2010、HMMT-2020-09）。aime-2001-2-7 は、最良の桁数は書き換えなしの方が12桁多く、時間は書き換えありの方が約12倍短い問題です。
- 時間はまちまちです。書き換えなしが速い問題（HMMT-2009、JMO-2013、JMO-2024）もあり、速度への効果は一方向ではありません。ただし、書き換えなしで止まる問題では、収束せず上限や時間を使い切る例が目立ちます。
- 候補ごとに見ると、書き換えありの方が桁数の多い候補が増える問題と減る問題が混ざります（per-candidate.csv の `more/less`）。

## 読み取れること

- 接条件を含む問題では、書き換えが効く問題群（7問）と、効かない問題群（4問）に分かれます。効く問題では、書き換えなしの精密化は残差を8〜48桁までしか下げられません。書き換えありでは、同じ候補が119〜502桁に達します。
- 「二乗残差のままだと8桁前後で止まる」という以前の観察（接条件の単純な例）と整合する問題が、JMO-2024-PRE-06（8桁）です。

## 注意

- 12問×1 seed の観察です。因果を言うには、止めたものが接条件だけではない点に注意してください。
- 「あり」は凍結版の既定動作で、本計測と同じ設定です。
- 候補は seed 0 の主探索の結果で、探索自体は書き換えの有無によらず共通です。
- 90秒の上限に達した実行は、`with_deadline_hit` / `without_deadline_hit` の列で見られます（4実行：HMMT-2008 の「なし」が2順序、HMMT-2023 の「なし」と「あり」が各1順序）。
