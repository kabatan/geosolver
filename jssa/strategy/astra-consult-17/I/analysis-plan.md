# astra-I：既存データ再解析の固定手順

2026-10-23。背景資料、既存の集計、AIME-2010-II-14 の記録例、各データのスキーマを読んだ後、以下の集計を実行する前に保存した。既存の研究全体を見ているので、これは新規の独立した事前登録ではなく、探索的再解析の手順の固定である。新しい局所探索は行わない。失敗しても閾値・主評価を変更しない。

## 1. 短い診断で出発方策を選ぶ

- 対象：start-feasibility-1023/predictions.csv の150問。seed2-plain/feasible の保存済み列を使用する。
- 問題ごとの共通評価長 M=min(40, 通常の保存済み試行数, 許容点優先の保存済み試行数)。M<40 も除かず件数を示す。両方200試行の95問でも感度分析する。
- 提案規則：最初の min(20,M) 個を通常で探索する。出発点の許容判定 F/I ごとに、観測可能な数値候補率 q を測る。数値候補は `ans` が存在して有限であること（元の記録器では等式・枝・箱の検査を通った後にだけ記録される）。正解との一致を判断材料にしない。
- F/I がともに2個以上あり、(候補_F+0.5)/(数_F+1) > (候補_I+0.5)/(数_I+1) のときだけ、その後を許容点優先にする。それ以外と同率は通常。20個未満で保存列が終わった場合は切り替えない。
- 比較：全 M 個通常、全 M 個許容点優先、上の規則。診断20個も試行枠・費用に含め、その候補は捨てずに成功の集計にも含める。切替後は保存列の index 20 以降を使い、診断の結果を評価尾部へ混入させない。
- 補助：正解ラベルを使う同じ規則（実装不可能な対照）、各問題で事後的に当たり数が多い一律方策を選ぶ oracle（実装不可能な参考）。結果を提案規則と混同しない。
- 主に記録する量：問題平均の当たり割合、少なくとも1当たりがある問題数、記録された探索秒数と費用の上下界、許容点優先への切替数、候補に混じる wrong_answer。単一の数値候補であり、集合一致・高精度検証の正答とは呼ばない。
- `records.sec` は再抽選を含まない。各保存列の D=elapsed−sum(sec) には再抽選・採点・未完了試行等が混ざる。部分列の費用は sum(sec) 以上、sum(sec)+D 以下。混合列では使用した元の列ごとに D を最大1回足す。点推定は D を記録数で均等配分する便宜値に限定し、上下界を必ず併記する。費用差の上下界は同じ元列で共通の試行の費用を相殺する。外部計測されていない初期化は含まれない。
- 20試行の診断費用（秒、nfev）と、M に達しない問題を記録する。保存されなかった試行を成功/失敗として補完しない。

## 2. 安い入力特徴による探索構成選択

- 使用可能な別実験：results/search-mode-ablation/per-run.csv（323問×3構成、seed0）。これは第2探索を切った実験であり、凍結既定版や実行中のクラウド A/B と同一視しない。
- C=180秒内に正答なら時間、それ以外180秒。主比較は disco_mads 対 scipy_multistart の2構成。mads も含める3構成は感度分析。
- 特徴：変数数 d と、既存 seed0 出発点の hard feasibility 比率 φ。正解・成功率・本実行後の段階情報は使わない。d=0 は通常経路を選び、φ のために探索しない。
- モデル：費用の総和を最小化する深さ2までの貪欲決定木。葉20問以上。分割候補 d=0.5,1.5,...,6.5、φ=0.025,0.1,0.25,0.5,0.75,0.9,0.975。分割して費用が厳密に下がらなければ葉にする。同率は記載順。葉は訓練群の平均 C が最小の構成を選ぶ。
- 競技名×年のグループを SHA256('astra-I|'+group) の先頭8桁の整数 mod 5 で5分割。同一問題の3構成は分けない。訓練側だけで木と一律構成を選び、残り1 fold の予測を連結する。年不明は問題 id をグループとする。
- 比較：既定構成、一律 LM、一律 mads、訓練側で選ぶ最良一律、d のみの木、d+φ の木、事後最良 oracle。モデルの深さ・閾値を検証結果から変更しない。
- φ の計算は局所探索せず、既存の出発点を再生成して hard feasibility を再評価する。現在の環境で特徴評価時間と初期化時間を測る。過去の費用計測とは計算環境が同一と保証できないため、まず診断費用ゼロの楽観的結果を示し、実測費用×1・×4 を加えた感度分析を併記する。これを完成solverでの新しい実測改善とは呼ばない。
- 補助として先頭20通常探索の費用を完成solver本計測の費用と比較するが、別環境の記述的比較と明記する。

## 3. 不確かさと判定

- 問題を単位とする paired bootstrap 10,000回、乱数 171023。CV の区間は固定済みの out-of-fold 予測に条件付ける探索的区間で、学習の不確かさやハードウェア差を網羅しない。
- 一律の最良方策に対して、診断費用込みで10%以上安く、正答数を失わず、費用差の区間が負にあることを、本検証に進む強い根拠の目安とする。ただし局所探索の結果だけでは完成solverに関するこの基準を満たしたと判定しない。
- cloud/out/A が無い場合は「見つからない」と書く。smoke 3問は実装確認だけに使う。これまでの事前登録4の成否は判定しない。
