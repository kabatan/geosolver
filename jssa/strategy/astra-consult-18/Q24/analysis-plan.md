# Q24 開発群の再解析手順（探索的）

これは未使用26問への最終規則ではない。既存の開発群323問、その p、msolve 比較、Q21f の選定6問を既視とする。新規局所探索・数値配置生成・厳密解法は実行しない。小計算は JSON/CSV と DSL の構文・AST の走査に限定する。

1. `121/122` を H/sources の出典付き比較表から再集計する。現在の benchmarks 以下も探索する。msolve の集合一致、正次元、未対応、未実行、時間切れ、エラーを混ぜない。
2. basins-323 の p を raw-323 から再集計し、分母・打切り・ゼロ変数を確認する。完成solverの成功と局所探索の hit を区別する。
3. 理論は有限予算の成功集合と開始分布、1試行費用、複数答の被覆費用に分ける。測度の恒等式を未知 p の予測式と呼ばない。条件数や解近傍の半径から大域的な盆を保証しない。
4. DSLのみから安く求まる、変数数、条件の依存関係、非線形作図の深さ・種類、明示の分母・平方根・接条件を候補にする。学習器や大きな閾値探索は使わない。人が読める少数の規則の全試行を保存し、選択を開発群だけで行う。既存の多項式変換の N,D とHC経路数は開発群での説明・比較に用い、未使用群の特徴として外挿しない。
5. 全誤分類、予測保留、真の逆転の見逃しを問題IDつきで保存する。局所側は高成功 p>=0.9、低成功 p<=0.1、中間を別にする。msolve側は集合一致＋変換/計算/filter合計<=1秒を「観測上軽い」、timeoutを「予算内未完了」、positive_dimensional/free_parameterを「列挙設定との不適合」と呼ぶ。errorは原因未分離である。
6. 多数派、変数数だけの規則と比べる。開発群での適合は確認実験ではない。Q21f 6問は選定標本なので一般化の分母にしない。
7. 最終規則と判定閾値、評価できない場合の扱いを `preregistration.md` に固定し、ハッシュを記録する。その後にのみ Q18 audit の合格IDとDSLを読み、同じコードで入力由来の分類予言を生成する。数値的な p 推定はしない。26問の結果は今回検証しない。
8. 最終登録文・規則・予言表のSHA-256を記録する。commitはユーザーの指示により行わない。ローカル固定であって公開事前登録ではない。

既存の進行中実験は読み取りだけ。大きな生ファイルの複製はせず、出典パスとハッシュを残す。成果物は Q24 内に限定する。
