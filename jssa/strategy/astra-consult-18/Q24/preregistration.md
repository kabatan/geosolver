# Q24 事前登録文案：規則固定部分

状態：開発群の探索的検査を終え、未使用26問の入力を読む前に固定する。これはローカルの文案であり、公開登録・commitではない。Q19の封印・中身・結果は参照しない。この作業では未使用群のsolver実行、局所探索、数値的な配置生成、pの推定を一切行わない。

## 1. 主張と単位

中心仮説は「有限予算内に正しい答えへ至る開始点集合の測度と1試行費用が、局所探索の再出発費用を決める。その集合を削る要因を入力の構造から予告できる」である。前半は既知の枠組み、後半が検証対象。

対象は `jssa/difficulty/unseen-1983/audit/audit.csv` のQ18合格26問。IDの辞書順、合格全件を使う。解析不能・未対応を都合よく除外・補充しない。入力だけから得る定性的な分類予言であり、各問の成功率の数値推定ではない。

完成solverと単発局所探索、msolveの比較構成と厳密法一般を区別する。ここでいう厳密側は開発群のmsolve翻訳器・版・設定による費用である。正次元や自由パラメータは「全配置列挙との不適合」であり、時間的な重さとは別の予言にする。

## 2. 開発群と選択経緯

開発群は既存323問（局所探索を要する292問）の `basins-323.csv` と `raw-323`、出典を確認したmsolve比較CSV、Q21fの既視の6問。元の問題・p・比較結果を見た探索的開発であり、この群での成績は確認実験ではない。候補はR0、R1、R2の3本だけ。学習器・閾値の総当たり・新しい局所探索を使わない。

- R0：変数数だけ。局所側はd<=2なら高成功、d>=5なら低成功、他は保留。厳密側は同じ条件で軽い／重い／保留。
- R1：下記の機構由来の候補。
- R2：R1の高成功を「hazard_gates=0」に狭め、d>=3かつhazard_depth>=2も低成功にした候補。

R1を固定する理由は、検査した機構を最も直接表す候補だからである。成績の良い規則として推奨する選択ではない。局所分類はR0が96/172、R1が79/146、R2が62/146。R0とR1が共に分類する137問では72対74で、差は2問。R1の時間的逆転は「厳密重・局所高」的中0、外れ2、評価不能1、「厳密軽・局所低」1/1（既知例）。前者の実在4問は全て見逃した。従ってAの核の判定は不可のまま登録する。未使用群に適用して分類数が少なくても緩めない。

## 3. 入力のみの特徴

実装の厳密な定義は `static_features.py`。標準ライブラリの `ast.parse` だけを使い、式を評価しない。幾何・数値最適化・代数変換のライブラリをimportしない。

- d：DSLが宣言する変数数。
- active：条件または目標量の祖先の作図・式のうち、宣言変数へ構文的に依存するもの。目標量の計算も含む。
- nonlinear_gates / nonlinear_depth：固定した非線形プリミティブと、両辺が変数依存の積、変数依存の除算、非自明な冪の個数／最長依存深さ。多項式の次数ではない。
- hazard_gates / hazard_depth：固定した交点・中心・射影・sqrt・tan等、および変数依存の分母等の個数／深さ。境界への距離でも危険領域の体積でもない。0でも安全は保証しない。
- active_tangent：変数依存のIsTangentの数。重根を証明する判定ではない。
- unmatched_variables：等式と変数の依存関係の二部グラフで、最大マッチングが覆わない変数数。And内の既定の等式述語を展開する。数値ランク・実数解の次元の測定ではない。
- dynamic_trig：未知量に依存するsin/cos/tan/atan。integer_predicates：IsInteger。未対応を予告する保守的な印で、翻訳器の対応範囲の完全な判定ではない。

演算名集合、優先順序、閾値を含むコードをSHA-256で固定する。式の代数的簡約はせず、等価なDSL書換えに不変とは主張しない。

## 4. 最終規則R1（先に該当した項目を採用）

共通：d=0なら探索不要、方向予言なし。

局所側：

1. active_tangent>0 または d>=5 → 低成功。
2. d<=2 かつ hazard_depth<=1 → 高成功。
3. それ以外 → 保留。

厳密側：

1. dynamic_trig>0 または integer_predicates>0 → 適用範囲外予告。
2. unmatched_variables>0 → 列挙不適合予告。
3. nonlinear_gates>=12 または nonlinear_depth>=4 → 重い予告。
4. d<=2 かつ nonlinear_gates<=4 → 軽い予告。
5. それ以外 → 保留。

二方向の主予言は「厳密重・局所高」「厳密軽・局所低」。別枠で「列挙不適合・局所高」を記録する。後者の的中を時間的逆転の的中に加算しない。

完成solverについては、局所高→完成solver軽、局所低→完成solver困難、という**別の移行仮説**を同時に固定する。これは理論の帰結ではなく、開発群でも後者は21/73しか当たらない弱い予言である。R1が局所側を保留する問では完成solverも保留。一次予言の失敗をこの副予言で救済しない。

## 5. 将来の評価ラベルと欠測

以下は将来の評価方法の文案であり、本作業では実行しない。Q19を開ける許可でもない。

局所側の一次ラベルは `probe_basins.py` の凍結局所処理・推定箱内一様開始・元のguard/hard/答え照合に合わせる。残差閾値1e-8、答え相対許容1e-6。新規検証を別途行う場合のseedは240024、要求200開始、1問120秒、出発点の再抽選・構成点への置換なし。200件完了した問だけを一次精度の分母にし、打切り問は未評価として全件表示する。全要求開始数を分母にし、未完了を失敗と数えた運用上の感度分析も併記する。d=0はp=1とせず探索不要。

- 高成功：保存200件のhit割合>=0.9。
- 低成功：同<=0.1。
- 中間：それ以外。高／低の予告に対する中間は外れ。

これらは有限標本の観測ラベルであり、真の無限時間盆の体積を認証しない。区間推定は参考情報とし、区間を見て閾値を動かさない。多答問題ではp_anyとp_minを別記し、p_any高だけで答え集合を網羅できたと判定しない。

厳密側は出典比較と同じ翻訳器（b0575a0の構成）、msolve 0.9.4、1問1800秒・アドレス空間5GiBを比較対象とし、変換＋msolve＋filterの合計を測る。版や翻訳器を揃えられない場合は別の追試として扱う。

- 軽い：answer_set_matches かつ合計<=1秒。
- 重い：timeout、またはanswer_set_matchesかつ合計>10秒。
- 中間：answer_set_matchesかつ1秒超10秒以下。
- 列挙不適合：positive_dimensional / free_parameter。
- unsupported / error / not_run / 時間欠測：費用判定不能。重いへの読み替えは禁止。

完成solverの副評価は、5 seedを揃えて答え集合一致と時間を見る。新規試験ならseed240024～240028、既存の封印記録を将来使う場合はその事前固定seed群で別記し、混ぜない。全seed正答かつ中央値<=10秒を軽い、1 seed以上の失敗または中央値>=60秒を困難、それ以外を中間とする。失敗と遅延の内訳を残す。Q19が完成solverだけの記録なら、局所側や厳密側の一次予言は評価不能であり、完成solver副予言だけを評価できる。

実時間の方法間比を主張する将来試験では同一機械・同時負荷・並列数を揃える。開発群の異なる並列数・同時ジョブの時間から厳密な速度優位を断定しない。

## 6. 当否の報告と棄却条件

全26問について入力特徴、両側の分類、完成solver副予告、方向、保留を出す。局所／厳密／完成solverそれぞれの混同行列、全外れID、全未評価ID、全保留IDを残す。局所分類は同じ対象でR0・常に高成功・常に低成功・常に中間とも比較し、保留数を減らした分母だけを使って優秀としない。

「双方向の予測能力が示された」と呼ぶ必要条件を次の全てに固定する。

1. 時間的な各方向で、予告かつ評価可能な問が3問以上ある。
2. 各方向で両側的中率>=0.75。観測された真の逆転に対する各方向の再現率>=0.5。
3. 全26問中、一次の両側が評価可能な割合>=0.8。未対応や打切りが多い場合は「支持不足」。
4. 共に分類する問題上で、R1の局所正解率がR0を10ポイント以上上回る。小標本でこの差が出ても統計的確証とは別に扱う。
5. 「完成solverとの逆転」と呼ぶには、副評価でも各方向3問以上かつ的中率>=0.75を満たす。局所側だけの的中で代用しない。

評価可能数が足りなければ「支持不足」、数が足りて当たらなければ「棄却」。規則が出す方向予告が3問未満でも追加の問題選択・閾値緩和はしない。この基準を満たしても、既知性・代替可能性・solverの中心性の問題が別途残るので、それだけでA判定を有望へ変更しない。

1. 本文書、`static_features.py`、開発群のデータ・全予告表・監査結果のSHA-256と時刻を `rule-lock.json` に記録する。この時点まで未使用群のaudit/DSLを読まない。
2. 合格IDとDSLだけを読む。選定に必要のないauditのコメント、公式答え、実行結果は使わない。数値評価せず同一R1を適用する。
3. 入力のハッシュと特徴・分類を `unseen26-predictions.csv` に保存し、`preregistration.md` に全件表を追記する。追記は機械的な入力適用だけで、固定本文を変更しない。
4. 最終登録文、規則、予告表、入力manifest、固定記録のSHA-256を保存する。commit・pushはしない。

読み取り対象や構文形式への対応の不具合があれば記録し、規則の変更が必要になる場合はこの登録を無効として残す。出力の見栄えを理由に再学習しない。
