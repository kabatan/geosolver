# Q36：実問題の値ごとの出やすさ（段階1、保存データのみ）

**冒頭判定：Aの核としては現状不可、機構の分析として縮小して残す。** 局所探索の値分布の偏りは再現している。しかし、完成solverで欠けた値の同定が欠測であり、同じ答え集合を保った対照や指数差をこの実問題群で示したわけでもない。

| 4基準 | 判定 | 保存データから言える範囲 |
|---|---|---|
| 直感に反する | △ | 一つの値への成功率89%でも値分布は約6倍偏る。ただし「まれな値は集めにくい」自体は直感的。図の端に近い方が頻出する反例はある |
| 深い理論が要る | × | 今回の事実は非一様なクーポン収集と探索箱で説明可能。深い理論が不可欠という証拠はない |
| 広がりと再現 | △ | 開発群8問、うち比較可能な非零の2値偏りは5問。seed 0/1で強い偏り2問が再現。2026年群に複数答は0問 |
| solverならでは | △ | 整数用探索・代数的前処理等による回収はこの実装の分析になるが、非一様な局所探索そのものは他の最適化にも生じる |

今回、ネットワーク・新規solver実行・局所最適化・精密化は使っていない。`src/`、既存データ、他タスクの出力は変更していない。予測はこの既存データを見て設計した**将来の実行に対する予測**であり、既存seedを未見の検証群とは呼ばない。固定内容は [prediction.md](prediction.md)、固定時刻・SHA-256は [prediction.lock.json](prediction.lock.json)。commit・pushは利用者が行い、別タスクの明示的な実行許可を受けるまで計算を開始しない。

## 対象と欠測の監査

`benchmarks/cases.jsonl` の323問と `new2026/cases.jsonl` の20問を全件調べた。配列だけでなく、`64,96,220` のようなカンマ区切り参照答も展開し、保存rawの参照値数と照合した。対象は開発群8問・23個の問題×値。2026年20問はすべて参照答が1個で、この仮説の外部検証には使えない。[全343問の一覧](input-census.csv)

例示された **AIME-2013-II-15 r1 は手元の版で確認できない**。現在のAIME-2013-II-15は角度変数 `alpha,beta`、参照答 `37/24-sqrt(35)/18` の1値であり、`r1` は変数でもtargetでもない。別の問題や別targetへ黙って読み替えなかった。この版は複数答の集計から除外した。対応版が後日得られれば、入力ハッシュを固定した別の登録が必要となる。

完成solverの `attribution.csv` と `per-case.csv` は問題×seedが重複なしの969行で、正答953行・行ごとの採点一致を再確認した。しかし**両表に返答値は入っていない**。記録された元の `jssa-main-j6-20261022` ディレクトリは存在せず、調べたローカルGit参照にも該当するrun JSONのパスはなかった。したがって、集合一致なら各値の出現を推定できるが、部分欠答なら欠けた値の名前は分からない。別実験の値や公式解でその穴を埋めていない。[実行別表](full-solver-runs.csv)、[値ごとの回収回数の下限・上限](full-value-coverage.csv)

`basins-323.csv` の `n_basins` は座標のクラスタ数で、答えの種類数ではない。実際にHMMT-2013-FEB-GEO-04は2値なのにseed 0の `n_correct_basins` は65である。今回の計数はrawの `cls==hit` と `ref` を使い、保存 `ans` も元の許容誤差で照合した。保存集計との一致も検査した。

数表の完全な値・分母・区間は [local-value-counts.csv](local-value-counts.csv)、問題別は [per-problem.csv](per-problem.csv)。HMMT-2011と2019の打切りは時間予算によるため、固定標本数の実験と同等の厳密な二項推測はしない。CSVのWilson区間は独立同分布を仮定した記述的な目安である。

`p_i = 値iのhit数 / 全開始点数`、`p_any = Σp_i`、`q_i = p_i/p_any` を区別する。AIME-2007-I-15は `p_any=0.8925` に対し小さい値の `q=52/357=0.14566`、大きい値との頻度比5.87倍。HMMT-2013-FEB-GEO-04は `p_any=0.3925`、大きい値の `q=20/157=0.12739`、頻度比6.85倍である。まれな値のqの記述的95%区間はそれぞれ `[0.11284,0.18602]`、`[0.08400,0.18858]`。いずれもseed 0/1で同じ側がまれだった。

HMMT-2010の160は0/400だが、正しい値に届いた総数自体が4なので、条件付きの偏りはまだ弱い証拠である。0/400を「確率0」とはしない。固定独立400試行なら片側95%上限は約0.00746。aime-2000は全値0なので「特定の値だけがまれ」と分類しない。

完成solverは該当24回中17回で全値回収、4回が部分欠答、3回が返答なし。部分欠答はAIME-2007、HMMT-2010、HMMT-2013に集中するが、**その4回がまれな側を欠いたとはまだ言えない**。例えばAIME-2007の各値はそれぞれ2〜3回、HMMT-2013の各値はそれぞれ1〜3回の出現としか分からない。問題単位の対応を値単位の的中に数えない。

## 「図の上での割合」でどこまで説明できるか

引き込み域の割合は、開始分布μ・座標・箱・探索法・停止判定を固定した `μ{start: hit(value=i)}` である。図のユークリッド面積や、解集合上の一様な割合とは違う。正次元の図には自然な「一様分布」が自動的には定まらない。今回のpはこの局所probeに依存し、NOMADや代数的前処理の分布へそのまま移せない。

単純な位置の説明を一つだけ点検した。seed 0のhit座標を探索箱の各軸で[0,1]に正規化し、**各値に1点だけ**、平均座標に最も近い保存hitを代表として選ぶ。保存開始点を最も近い代表の領域に割り当て、その割合をgとする。solverを再実行せず、開始点も新しく発生させていない。これはVoronoi領域の標本割合であって、実際の引き込み域ではない。代表座標・箱は [geometry-model.json](geometry-model.json) に固定する。

| 問題・値 | 位置による割合g | seed 1の実測q |
|---|---:|---:|
| AIME-2007、小さい値 | 0.055 | 0.147 |
| HMMT-2009、小さい値 | 0.285 | 0.444 |
| HMMT-2011、35/11 | 0.264 | 0.491 |
| HMMT-2013、大きい値 | 0.190 | 0.110 |
| HMMT-2019、小さい値 | 0.580 | 0.264 |

`g≤0.20` と `q≤0.20` の旗はこの5問10値では一致するが、**この閾値は既存結果を見て選んだ**。独立検証ではない。連続的な確率としては最大誤差0.316で、HMMT-2019では多数派の向きも逆になる。尺度・回転の自由度を持つ解の集合を1点で表す弱点を含み、一般的な「図の割合が確率になる」という結論は不可。[全値の表](geometry-proxy.csv)

もう一つの簡単な規則「境界に近い図ほどまれ」も失敗する。AIME-2007でEの辺CA上の位置 `AE/AC=2ex/s` は、まれな小三角形で0.05677、頻出する大三角形で0.99046。近い端までの距離は0.05677対0.00954で、**頻出側の方が端に近い**。これは一つの境界指標への反例であり、あらゆる幾何指標を否定するものではない。

明確な位置による説明はaime-2003-1-7にある。targetは `30+2*sqrt(225+x²)`、正のxに対し周長64,96,220の配置はそれぞれ `x=8,12*sqrt(6),20*sqrt(22)`。最後は93.8083で保存探索箱 `[0,60]` の外なので、この箱と `left_box` 判定を守る局所probeでは220のhitは出ない。これは有限標本の未観測より強い説明である。それでも完成solverは3/3で全値回収し、記録された採用元は `search/integer_square_difference`。**局所分布だけから完成solverの欠答を必然とする規則への反例**になる。採用元は実行全体の代表候補の情報であり、全ての値の生成経路を個別追跡した証拠ではない。[位置の検算](geometry-checks.csv)

## クーポン収集との関係と、残る予測

独立な開始点なら値iをB回で一度も得ない確率は `(1-p_i)^B`。正しい図だけをB枚集めるなら `(1-q_i)^B`。全値回収の失敗確率は包除原理で求まる。二値なら `(1-q_1)^B+(1-q_2)^B` である。

保存qを代入した「正しい図20枚でも片方を逃す」確率はAIME-2007で0.04292、HMMT-2013で0.06553。公平な二値抽出なら `2*(1/2)^20≈0.00000191`。これは同じ答えの個数でも分布が効くことの**独立抽出モデルの計算**であり、完成solverの失敗率の予測値ではない。前処理・候補間依存・検証・停止・救済が異なるため、`refine_attempted=20` を独立な正解図20枚と扱うこともできない。

相談18候補1の同一条件・同一答え集合を保つ人工対照や指数差を、今回の実問題で再現したとは主張しない。既知の非一様クーポン収集を新理論と数えない。ネットワーク禁止のため外部文献は新規照合せず、上の式を直接用いた。相談18の候補説明はローカルの [元回答](../../gpt-pro-consult-18-answer.md) にある。

将来の検証では、まれな値の名前、qの0.20閾値、完成solverでの部分欠答の方向、別経路で回収する対照を事前に固定する。手順・資源上限は [next-stage-plan.md](next-stage-plan.md)。もし局所の偏りが再現しても完成solverが両値を安定回収すれば、完成solverの難しさの原理としては支持されない。これを成功に読み替えない。
