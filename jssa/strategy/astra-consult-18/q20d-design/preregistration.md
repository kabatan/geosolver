## 主張と反証可能な範囲

「一つ一つの長さは求められるのに、同じ図の長さの和を厳密式にできない」例を、平方類の独立性から設計できるか。局所探索の難しさ、人間の実測難度、一般の計算量下界は別である。次数上限や体論を再発見したことをAの核とはしない。完成solverには定数幾何の厳密式を扱う別経路があり、次数だけからその全挙動は確定しない。

## 問題（結果で差し替えない）

共通図は O=(0,0), U=(u,0), V=(u,1), W=(u,2), X=(2u,3), Y=(u,4), Z=(u,3)。条件は OV=√2 と 0<u<2。この正の長さuは三平方で1になる。幾何的には、単位長と共通の長さuを脚に用い、必要な整数倍を取った直角三角形群である。入力の座標式はこの構成を直接表す。

以下8入力は id と target 以外をバイト上の正規化で一致させる。答えはsolverへ渡さず独立採点用の `references.json` にのみ入れる。

| ID | 求める量 | 参照値 | 次数 |
|---|---|---|---:|
| R1 | OV | √2 | 2 |
| R2 | OV+OW | √2+√5 | 4 |
| R3 | OV+OW+OX | √2+√5+√13 | 8 |
| R4 | OV+OW+OX+OY | √2+√5+√13+√17 | 16 |
| DEP | OV+OV+OW+OZ | 2√2+√5+√10 | 4 |
| S5 | OW | √5 | 2 |
| S13 | OX | √13 | 2 |
| S17 | OY | √17 | 2 |

DEPは4距離項だが、√10=√2√5なので体は四次。R4との項数の対照となる。R1〜R4の項数は同一ではない。

対照 FIXED4 は同じR4でu=1を作図時に固定し、変数を0個にする。探索条件を一致させた主対照には含めない。定数幾何から厳密式を提案する経路の確認に使う。

対照 CUBIC は正の2つの平均比例長u,vを 1:u=u:v=v:2 で定め、uを問う。DSLには u²=v, uv=2 を距離の積で書き、0<u,v<2とする。答えは立方根2、次数3。この対照の変数数・制約は主族とは異なる。作図可能性の順序と完成solverの成否の順序が一致しない例になるかを見るだけで、人間には三次の方が難しいという実験にはしない。

## 固定した予言

- P1：共通8入力の局所探索は、同じ16開始点で全てhit、かつ対応する終点座標・残差・評価回数が一致する。厳密な浮動小数一致と、座標差1e-12以内の両方を報告する。前者が崩れても勝手に後者へ合格基準を変更しない。
- P2：完成solverは R1,R2,R3,DEP,S5,S13,S17 の全7入力で2seedとも正しい厳密値を返す一方、R4は2seedとも正しい数値候補を得ても厳密同定に失敗する。数値候補が得られない場合は「同定だけの限界」という予言の失敗とする。
- P3：FIXED4は2seedとも正しい厳密値を返す。R4と同じ次数16なので、これが成立すれば「次数16を表現できない」一般論ではなく、数値からの再同定経路に限定した結果とする。
- P4：CUBICは2seedとも正しい厳密値を返す。P2のR4失敗と合わせて、定規・コンパスで作図できるかが成功順序を決めないことを示す。
- P5：R4失敗時、数値だけを渡す通常の同定部と、同じ値に入力から保った根号式を候補として添える同定部を比較する。前者は失敗、後者は正しい式を返すと予測する。これは完成solverの改良・未知問題での自動救済ではなく、入力情報を保持する対照である。根号式候補は人が設計から導いたものである。

P2がそのまま成立しなくても、R3などを対象外にしない。失敗例を結果から追加しない。上記は機構の小検証の合否であり、Aの判定は追加基準(f)〜(h)も含めて行う。

## 実行と採点

- Python `/home/kabatan/work/solver/.venv/bin/python`、`PYTHONPATH=src`、`PYTHONDONTWRITEBYTECODE=1`。src変更、pip、git fetch、commit、pushなし。全出力・一時ファイルはこのフォルダ内。
- 同時計算は最大1 solver job、BLAS/OMP等は1 thread。局所部と完成solverは同時に走らせない。実行前後にsrcハッシュを照合する。
- 局所部：凍結版 `_collect_local_start_record`、既定LM評価上限80、既定許容誤差。`infer_problem_bounds` の箱を記録し、共通8入力で同じことを確認。`default_rng(20261023)`で16点を一度作り全入力に使用。各入力20秒で打切り、少数終了ならそのまま報告。
- 完成solver：公開CLI、seed `202610231, 202610232`、各60秒・1core。2seed目は入力順を逆転。10入力×2seed=20実行。最長約23分（起動猶予を含む）。外側上限68秒を設けて自分のプロセス群だけを終了する。再試行で成功へ付け替えない。
- 成功は返答が1個で、参照の実代数値と一致すること。可能なら標準の `ExactAnswer` の正準キー、さらに100桁の独立数値照合を使う。数値候補だけなら完成solverの成功には数えない。全候補・棄却理由・同定法・精度・時間を保存する。
- 局所hitは残差≤1e-8、guard/hard/boundsを通り、参照値との相対誤差≤1e-6。数値候補の存在は、保存された最終確認済候補の値が参照値と相対1e-60以内で一致し、数値検証が通ったものを優先し、ログにその根拠がなければ未確認とする。微小残差だけで座標の60桁を保証しない。
- P5：R4の保存された高精度候補を使用。通常の `identify_answer` と `geometry_hint` 付きの同じ関数を、それぞれ1回、同じ250桁・30秒上限で実行。元の数値確認による誤差幅が250桁に足りないなら利用可能精度に下げ、その値を記録。新しい局所探索は行わない。
- 作業総量は2時間以内。メモリは1jobのアドレス空間2GiB目安、1ファイル上限20MiB。負荷・環境エラー・時間切れは数学的失敗と分ける。

## 解釈上の固定線

人間実験は行わない。「人間には短い解法がある」と「人間集団に易しい」を区別する。これは1つの設計族に対する多目標の比較で、8種類の自然問題の一般化ではない。代数次数の指数増大は古典的事実、次数を超えて同定できないことも既知の制約。成立しても、それだけではAの核に昇格させない。普通のCASが根号式を保持して容易に扱えることを弱点として記す。
