# 公開CLIの時間枠に関する実装訂正（完成solverの求解開始前）

2026-10-23、初回記録を読んだ後、訂正版を走らせる前に記す。

元の `preregistration.md` と `registration-lock.json` は変更しない。初回は局所部128回が実行され全てhit、同じ開始点で終点座標・残差・評価回数が一致した。完成solverの20要求は全て `SolveOptions` の設定検査で失敗した。`time_limit_seconds must be between 180 and 900` と記録され、result.json は20回とも存在しない。幾何の探索・高精度化・同定には一度も入っていない。したがってこの20件をR4の予測失敗や他の問題のsolver失敗へ数えない。

原因は実験runnerが公開CLIの最小時間180秒を確認せず60秒を指定したこと。srcの不具合ではない。初回ログは `runs/` に全て残す。

訂正は公開CLIの時間枠を全10入力・2seed共通に **180秒、外側上限188秒** とする一点。入力、予言の方向、seed、順序、採点、メモリ、1ジョブ・1コアは変えない。局所部は繰り返さない。出力先を `runs-180/` とし、初回記録を上書きしない。訂正コードは `rerun_public.py`、訂正の時刻とハッシュは `correction-lock.json` に保存する。

P2〜P4は180秒条件下の検証として報告し、「元の60秒の完成solver実験が成功した」とは書かない。結果を見て予算を増やした実験ではなく、**完成solverの結果が一件もない段階での実行設定の訂正**である。ただし局所部P1の結果は既知であり、この時系列も隠さない。

P5も `runs-180/` に保存された最初のR4候補を使う。出力は `identification-180/` と `identification-input-180.json` に分け、初回の候補なし記録を残す。P5の30秒上限は公開CLIの設定ではないため変えない。

最大約63分の逐次実行であり、依頼の2時間以内に収まる。外部負荷等で作業開始から2時間に近づいた場合は追加実行を始めず欠測として残す。完成solverの結果が出た後に対象・予言・入力を変更しない。
