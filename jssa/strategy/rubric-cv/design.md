# 採点基準づくりと交差検証（本人 10/24 16:19 JST の指示）

本人：「新しい GPT-Pro に採点基準を作ってもらい、それを別の新しい GPT-Pro に渡して、評価が人間と一致するか確認する」。

## 材料
award-benchmark の目隠しテストと同じ17作品（応用数学15＋情報・技術のA 2）。正解の段階は am-anchors-key.md にある（A3・B4・C3・D7）。音律（69_HAM023AM）の概要の文字化けは、事前に直す。

## 手順（3分割の交差検証）
1. 17作品を、段階が偏らないように3組（6・6・5）に分ける。分け方は作品コードの sha256 順で、段階ごとに順番に割り当てる（seed なし、機械的に）。
2. 組ごとに「作る側」の新しいチャットを1つ開く。残り2組（約11作品）の概要と実際の段階、公式の審査観点（01-official-criteria.md）を渡す。頼むこと：段階を分ける採点基準を作る。観点、各段階の目安、点数から段階への換算を含め、A4で2ページ以内。
3. 組ごとに「使う側」の新しいチャットを2つ開く。採点基準と、その組の作品の概要（段階は伏せる）だけを渡す。頼むこと：基準どおりに各作品を採点して段階をつける。作った側のチャットは見せない。
4. 合計で、作る側3チャット、使う側6チャットになる。全部 Web 検索なし、一時チャット。

## 合格の基準（実行前に固定）
- 使う側6回の、未見の作品での段階一致率の平均が50%以上（偶然は約25%、前回は16%）。
- 順位と実際の段階のスピアマン相関の平均が0.5以上。
- 同じ組での2回の判定が、70%以上の作品で一致する（ばらつきの確認）。

## 合格したら
17作品すべてで最終の採点基準を作る（新しいチャット1つ）。それを使って geosolver の本文（v15）を3回、別々の新しいチャットで採点する。
採点基準と v15 の手直しは切り離す。v15 は採点基準を見ながら書き直さない（基準への過適合を避ける）。

## 不合格なら
概要だけでは段階を見分けられない（情報が足りない）可能性を報告する。GPT-Pro の判定は、弱点を見つけるためだけに使う。

## 記録
各チャットの送信全文と回答を runs/ に保存する。正解との照合は作業者がスクリプトで行い、GPT-Pro には照合結果を見せない。
