# 補足資料 S3・S4（v11 本文4章・5.3節に対応）

## S3 開発外の問題での評価（本文4章）

### S3.1 開発群の入力が開発中に変わったこと

開発用323問の入力（DSL）は、solver を作る途中で直されたものがある。修正台帳（commit c30f97d9）と旧・新の DSL、移行元の Git 差分を照合すると、作図・変数・条件・求める量の変更または新規作成を確認できたのは、重複を除いて84問以上だった。残り239問について「修正なし」を保証するものではない。

修正の多くは、原文の書き移しの誤り・符号・求める量の訂正である。一方、solver への適応と言える例もある。

- JMO 2009 予選2：自由点の形式で退化した偽の解4を受け入れたのを見て、交点の指定を変えた（変数4→1）。台帳自身が「solver 側の問題を入力の表現で避けた」と記している。
- 旧302問の自由度の圧縮：性能の低下を見て、自由な座標を作図やパラメータの式に置き換えた。HMMT 2019年2月 幾何10番は38→0変数、AIME 2025 II-12 は20→1変数。圧縮前の DSL が残っていないので、効果の大きさは再検証できない。
- HMMT 2020年2月 幾何5番などは、公式解説の図の分け方を入力に使っている。これは solver が見つけた解法ではない。

修正の有無と局所探索の当たりやすさ p の関係は単純ではない（修正を確認した84問の平均 p 0.471、それ以外 0.594。難しい問題ほど修正の対象になりやすいので、修正の効果の推定にはならない）。以上から、本文では開発群の成績を「開発に使った集合での成績」とし、主な根拠を開発外の問題に置いた。

出典：jssa/difficulty/unseen-1983/failure-audit/c/answer.md、history-evidence.md。

### S3.2 開発外34問の作り方と予測

- 問題の選び方：開発用323問・2026年20問・S3.3 の54候補のどれにも含まれない、平面幾何の求値問題。AIME は2001〜2019年、HMMT は2010〜2025年の2月大会（Guts と Team を含む）。問題文と答えは公式の資料（AIME は公式の解答冊子か AoPS Wiki、HMMT は公式 PDF）で確かめ、確かめられない問題は使わなかった。
- 書き方の規則：2026年20問と同じ規則（benchmarks/new-2026/authoring-rules.md）。求める量は幾何の量そのもので、「m + n」「切り捨て」などの答えの形式は採点の側で変換する。解法から来る定数は入力に入れない。
- 入力を作る間は solver を一度も動かさず、正しい図の代入による数値の検算だけを行った。
- 予測と成立基準（実行前に公開）：AIME は 76/85 を点予測とし、73/85以上かつ3回以上正解の問題が15/17以上で成立。HMMT は 78/85 を点予測とし、77/85以上かつ16/17以上で成立。
- 実行：凍結版 60db4b6、seed 301〜305、180秒、1コア。採点は既存の採点器のまま。

### S3.3 最初に作った未使用26問と、その失敗の原因

開発外34問の前に、AIME 1983〜1999年と HMMT から54候補を集め、問題文と答えを公式の資料で確かめられた26問を対象に、予測を固定してから凍結版で解いた（seed 201〜205）。結果は130回中85回正解（65%）で、予測（85%以上）を下回った。誤った値を返した実行は0回だった。

失敗した10問のうち9問は、この時の入力の規則が「m + n」「a + b」「100a + b」「切り捨て」などの答えの形式を、整数の変数（既約であることを示す整数 h, k による ha + kb = 1 を含む）や床関数として入力に書き込んでいた。成功した16問には、整数の変数も床関数もなかった。開発群・2026年20問・開発外34問の規則（幾何の量そのものを求める）とは食い違っていた。

原因の確認（失敗5問を個別に調査）：
- 正しい図を100桁で入力に代入すると、5問とも全ての条件を満たした。入力の数学的な誤りは0問だった。
- 整数の変数の値が探索の初期範囲（上限20）の外にあった（例：HMMT 2022年2月 幾何7番では |k| ≥ 84）。900秒にしても、範囲外の4問は答えが出なかった。正解から0.01ずらした出発点からは10/10で正解した。
- AIME 1996-15 は、床関数が高精度の評価で実装されておらず、評価の段階で落ちた（実装の不具合）。

書き直し（失敗を見た後の事後の作業）：整数が問題の本質である AIME 1983-12 を除く8問を、答えの形式だけを外す機械的な規則で書き直し、予測を公開してから新しい seed で解き直した。保存処理の不具合で欠けた実行は、保存側の上限だけを直して再実行した。8問の計40回のうち38回正解し、残る2回は出力ファイルの大きさの上限による異常終了だった。凍結版・元の入力での65%は変えず、書き直した結果は別に扱う。

出典：jssa/difficulty/unseen-1983/prereg/result.md、failure-audit/a,b,d。

### S3.4 誤った値を返した実行

開発外の34問（170回）と2026年20問（60回）では0回。開発群（969回）では2回で、どちらも JMO 2014 予選9で起きた。この問題は、与えた入力の全ての条件を満たしたまま、求める値が連続的に動く図の族を持つ（値1と2の両方を取る図がある）ことを別の調査で確かめた。入力の条件の不足であり、solver の数値の誤りではない。開発群では、答えが複数ある問題で一部の値だけを返した実行も4回あった。

## S4 素朴な多点出発との差（本文5.3節）

### S4.1 局所探索で一度も当たらない21問

箱から一様に選んだ出発点から凍結版の局所探索を1回行う方法（本文6.1の p の測り方）で、seed 0 で当たり0回だった29問のうち25問は seed 1 でも0回だった。2つの seed で当たり0回、かつ完成 solver が3回とも正解した問題は21問（予測「20問以上」を事前に固定）。局所探索の出発は計6,971回、完成 solver は63/63正解した。

答えの出どころ（候補を出した段階）は、1段目の探索（NOMAD）49回、第2探索（SciPy の多点出発）7回、救済の探索（NOMAD）7回で、代数的前処理によるものは0回だった（「過半数が代数的前処理」という予測は外れた）。局所探索と完成 solver は、出発点・探索法・予算・精密化・採点の段階が違うので、この差を一つの仕組みに帰すことはできない。開発群の43問（局所探索で14,422回中1,859回当たり、完成 solver は129/129）では、第2探索を外すと5問が解けなくなり、その5問はどれも第2探索が答えを出していた。

出典：jssa/strategy/astra-consult-18/Q27f/answer.md、jssa/difficulty/capability-attribution/。

### S4.2 浮動小数の丸めへの強さ

局所探索の出発点を最後の1桁（1 ulp）だけずらすと、12問中3問で行き先が変わった。一方、完成 solver を同じ seed で、浮動小数の丸め方だけを変えて（演算の順序、53ビット演算までの丸め）実行すると、答えの集合が変わった組は24組中0組だった。候補の座標や精密化の失敗は変わることがあったが、最終的な答えの取りこぼしにはつながらなかった。なお、10/21 に別の計算機で同じ seed でも落とす根が変わったことがあり、計算機の違いによる揺れが全くないとは言えない。

出典：jssa/difficulty/fractal-basins/answer.md。
