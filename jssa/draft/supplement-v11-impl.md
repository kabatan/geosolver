# S1 solverの数理と実装（v11 に対応、10/24 の案）

本文3章の仕組みを、式と擬似コードで説明する。すべて凍結版（kabatan/geosolver の 60db4b6）のコードで確かめた。各節の末尾にファイル名を書いた（`src/geosolver/` は省略）。数値の定数はコードの既定値で、323問の本計測もこの値で動いている。実験の数値は補足 S2 の再掲である。 v10 の S1（理論）の参照は、S1.8 以降へ順に後ろへ回す前提で S1.8〜S1.13 に振り替えた（v10 の S1.k → S1.(k+7)）。

記号は本文3.1と同じにする。探索変数 u ∈ ℝ^d、作図 h、等式の残差 F(u) = (F_1(u), …, F_m(u))、不等式などの許容判定 G、求める量 τ。求めるのは集合 { τ(u) ｜ F(u) = 0, G(u) を満たす } である。

## S1.1 作図による変数消去

### S1.1.1 入力と評価

入力は、探索変数の名前、作図の列 y_1 = h_1(u), y_2 = h_2(u, y_1), …、条件、求める量からなる（例は本文図1の AIME 2021 I-11）。1点の評価は次のとおりである。

```
evaluate(u):
    ctx ← {u}
    for (名前 y_k, 式 h_k) in 作図の列:          # 書いた順に1回ずつ計算
        ctx[y_k] ← h_k(ctx)                     # 交点がない・直線が決まらない等なら失敗
    r_i ← 左辺_i(ctx) − 右辺_i(ctx)   (i = 1..m)   # 等式の残差
    return r, 許容判定 G(ctx)
```

作図は中点・交点・垂線の足・外心などの関数で、点は常に作図の上にある。等式は「左辺 − 右辺」を残差にする（high_precision_expressions.py）。不等式、点の並び（ConvexPolygon など）、交点の枝の選び方は許容判定 G に入り、残差には入らない。

### S1.1.2 何が消えるか

作図で決まる点 y を自由な変数に戻すと、変数は (u, y) になり、作図を表す等式 Q(u, y) = 0 が加わる。作図で計算すると、y = h(u) を代入した

  F(u) = C(u, h(u))

だけが残る。例題 AIME 2021 I-11 のDSLでは、等式は AB = 4、BC = 5、CD = 6、DA = 7、4点の共円の5本である。AB = 4 は A = (0,0)、B = (4,0) の作図で自動的に満たされる冗長な1本なので、5本は独立な等式の数ではない。4つの垂線の足をすべて自由点にすると変数は 4 + 8 = 12、DSLに書かれる等式は 5 + 8 = 13 になる（足1つにつき「直線上にある」「垂直」の2本）。作図で計算すれば変数は4、等式は5のままである。

開発用323問の探索変数の数 d は、0が31問、1が43問、2が73問、3が65問、4が55問、5が26問、6が20問、7が9問、9が1問だった（benchmarks/dsl から数えた）。d = 0 の31問は作図だけで図が決まり、探索をしない。8月の書き直しの前は、8変数以上の問題が44問あった（S3）。

作図で計算するときのヤコビアンは連鎖律で J_E = C_u + C_y H（H = ∂h/∂u）になる。自由点の系との違いは補足 S1.10 の命題1で扱った。

### S1.1.3 評価できない点

作図は定義域を持つ。円と直線が交わらない、2点が一致して直線が決まらない、三角形がつぶれる、といった点では評価が失敗する。この失敗は「隠れた制約」で、事前に式で書けない。1段目の探索（S1.2）はこれを NOMAD の DiscoMADS に任せ、局所探索では大きな罰則に置き換える。

交点が2つある作図は、Intersect の引数（n 番目、ある点を除く、ある点に近い・遠い）で枝を選ぶ。どの枝を選んだかは記録され、最終検証（S1.5.2）で同じ枝のままかを確かめる（intersections_selection.py、final_verifier.py の same_branches）。

### S1.1.4 探索の箱

各変数の探索範囲は [−s, s] で、s は「その変数に関係する等式に現れる数の最大値の2倍」と10の大きい方（上限20000）である。不等式から下限や上限が決まる変数（例：cy > 0）は、その側を固定する（problem/domain_bounds.py の search_bounds）。

## S1.2 探索の流れ：NOMAD → 局所探索の多点出発 → 範囲を分けた再探索

### S1.2.1 全体

1問の流れは次のとおりである（engine/standard/orchestration/run_external_pipeline.py）。

```
solve(問題, seed):
    結果1 ← 試行(1段目: NOMAD, seed 1個, 代数的前処理あり)
    if 結果1 で答えが1つ以上採用された:
        return 結果1
    結果2 ← 試行(第2探索: hybrid_legacy_nomad, seed 5個, 代数的前処理なし)
    return 採用数が多い方（同数なら精密化の最良残差が小さい方、さらに同じなら評価回数が多い方）

試行(探索法, seeds):
    if 代数的前処理が使える: 候補 ← 代数的前処理（S1.6）
    else:
        出発点 ← 一様乱数 50点 × seed数 ＋ 構造を使った標本
        候補 ← 探索法(出発点)                       # 最大20個
    精密化（S1.3） → 最終検証と同定（S1.5）
    if 採用がない（または全てが精密化の途中で止まった候補） and 残り時間 ≥ 8秒:
        候補 += 範囲を分けた再探索（S1.2.4） → 精密化 → 最終検証と同定
    return 採用された答え
```

本文の「第2探索」は、2回目の試行（`hybrid_legacy_nomad`）を指す。1回目で答えが出たときは走らない。代数的前処理の候補が一部しか検証を通らなかったときは、1回目の試行で通常の数値探索も走らせ、両方の採用を合わせる。

### S1.2.2 1段目：NOMAD（DiscoMADS）

目的関数は、残差の尺度をそろえた2乗和に、許容判定の罰則を足したものである（engine/standard/search/nomad_blackbox_adapter.py）。

  f(u) = Σ_i (r_i(u) / σ_i)² + 10⁶ · [u が許容判定を満たさない]

作図が評価できない点では、NOMAD に「評価失敗」を返す。DiscoMADS の隠れた制約の設定（DISCO_MADS_HID_CONST、そのときの出力値 10²⁰）で扱われる。

**残差の尺度 σ_i。** 最初の乱数の点（1回目の試行では50点）で各等式の |r_i| の中央値を求める。中央値の最大と最小の比が10未満なら尺度はかけない（σ_i = 1）。10以上なら、σ_i = max(中央値_i, 中央値の幾何平均) とする（run_initial_probe.py）。長さの2乗の式と角度の式のように、単位の違う等式が混ざったときに、片方だけが目的関数を支配しないようにするためである。幾何平均で下を押さえるので、もともと小さい等式を拡大しすぎない。

**設定。** seed 1個、評価の上限200回、出発点は乱数50点（と構造を使った標本）のうち、不等式を満たす点を優先し、その中で f が最小の点。箱は両側に幅の25%ずつ広げる（不等式で決まる側は広げない）。

### S1.2.3 候補の選び方

探索で評価したすべての点から、精密化に回す候補を選ぶ（build_guard_feasible_ledger.py）。

```
F ← 評価した点のうち、評価でき、許容判定を満たす点（f の小さい順）
台帳 ← [F の先頭]
while |台帳| < 160:                       # max(20×8, 64)
    台帳 に、すでに選んだ点から最も遠い点を加える（距離は箱の幅で割った座標で測る）
候補 ← 台帳から同じ「最も遠い点」の規則で20個選び、f の小さい順に並べる
```

残差だけで上位20個を取ると、同じ谷に落ちた点ばかりになる。最良の点を1つ残したうえで、離れた点を優先して選ぶので、答えが複数ある問題でも別の解の近くの点が残りやすい。

### S1.2.4 第2探索（hybrid_legacy_nomad）

1回目の試行で答えが採用されなかったときだけ走る（engine/standard/orchestration/run_search.py）。

```
第2探索(seeds = s, s+1, …, s+4):
    A ← NOMAD(DiscoMADS)を seed ごとに1回ずつ（出発点は乱数250点から5個）
    T ← 残り時間
    B ← 局所探索の多点出発(出発点 = A の上位5点 ＋ 5個の出発点, seeds, 時間 T/2)
    C ← 局所探索の多点出発(出発点 = 5個の出発点, seeds + 5, 残りの時間)
    return A ∪ B ∪ C から S1.2.3 の規則で20個
```

局所探索の多点出発は、seed ごとに次を行う（engine/standard/search/scipy_multistart_backend.py）。

- 出発点：与えられた点、スクランブルした Halton 列の320点、箱の内側の格子状の点。各 seed の最初の数点を先に回し、深い点は後に回す。
- 各出発点から、等式が変数以上なら LM 法（SciPy の `least_squares(method="lm")`、評価の上限80回、許容誤差10⁻¹⁴）、変数の方が多ければ Powell 法（反復400回）。
- LM 法に渡すベクトルは、残差に2成分を足したものである。

  ( r_1/σ_1, …, r_m/σ_m, 10·g(u), 10·p(u) )

  g(u) は不等式の違反量の和、p(u) は許容判定を破れば10³、満たせば 10⁻⁶ / (許容判定の最小の余裕) である。作図が評価できない点では全成分を10¹⁰にする。
- 時間の半分を使い切ったら、上下限付きの TRF 法（Halton 24点、許容判定を満たす点から順に）に切り替える。

### S1.2.5 範囲を分けた再探索

どの候補も最終検証を通らなかったとき、残り時間が8秒以上あれば走る（run_rescue_search.py、select_rescue_boxes.py）。

```
代表 ← 台帳の先頭 ＋ 「最も遠い点」で最大6個
for 各代表 c:
    半径_j ← 箱の幅_j × clamp(0.5 × (c から最も近い他の代表までの距離), 0.02, 0.35)
    c を中心とする小さな箱で NOMAD（MADS）、評価80回まで、上位6点を残す
合計8秒まで
```

広い箱では見落とした谷を、候補の近くの小さな箱で探し直す。代表どうしが近いほど箱は小さくなる。

### S1.2.6 その他の経路

d = 1 の問題では、まず1変数の根の挟み込み（格子と Brent 法）と、平方数の差を使う整数の枝の列挙を試す。不等式に有理数の境界があるときは、その境界上の点を候補に加える（finite_guard_search.py）。整数であることが条件の問題では、整数値に固定して閉じ直す経路がある（integer_targets.py）。どれも候補を出すだけで、精密化と最終検証は同じである。

### S1.2.7 各部分の役割（S2.2 の再掲）

外す実験（seed 0、323問）では、第2探索を外すと、第2探索が答えを出していた10問のうち9問を失った。1段目の NOMAD を局所探索の多点出発に替えると、正解の数はほぼ同じ（両方正解313問）で、両方正解の問題の時間比の中央値は1.7倍だった。再探索が答えを出していた9問では、外すと1問を失い、逆に3問が新しく解けた。【開発外34問での同じ実験（事前登録6の実験2）の結果を追記。】

## S1.3 多倍長での精密化

### S1.3.1 流れ

候補1つの精密化は次のとおりである（engine/standard/refinement/mpmath_refiner.py、refiner_config.py）。

```
精密化(x):
    if 120桁での残差 < 10⁻¹⁵ かつ 許容判定を満たす:          # すでに良い点
        仕上げ(x) を試す。目標に届けば終わり、届かなければ下へ
    if 等式の数 ≥ d > 1 かつ 許容判定を満たす:
        x ← 減衰なしのニュートン法（120桁、12回まで）。失敗したら元の x のまま
    for (桁数, 目標) in [(50, 10⁻²⁰), (100, 10⁻⁵⁰), (120, 10⁻⁸⁰)]:
        x ← LM法(x, 桁数, 目標)
        if 残差 > √目標 かつ 目標に届かずに止まった: break
    仕上げ(x)

仕上げ(x):
    if 120桁での残差 ≤ 10⁻¹⁰ かつ 許容判定を満たす:
        for (桁数, 目標) in [(120, 10⁻⁸⁰), (250, 10⁻¹⁵⁰), (350, 10⁻²²⁰), (500, 10⁻³²⁰)]:
            x' ← ニュートン法(x, 桁数, 目標, 最大 max(80, 2×桁数) 回)
            if x' が全ての元の等式で目標を満たし、許容判定も満たす: x ← x'
    return x
```

### S1.3.2 多倍長の LM 法

1回の更新は

  (JᵀJ + λI) δ = −Jᵀr

を mpmath の LU 分解で解く（levenberg_marquardt_step.py）。SciPy の LM 法と違い、λ にかける対角行列は単位行列である。λ の初期値は10⁻⁶で、改善すれば λ/4（下限10⁻¹²）、しなければ 4λ にする。δ に対しては、刻み幅を1, 1/2, 1/4, … と20回まで半分にし、箱の中にあり、許容判定を満たし、残差のノルムが減る最初の点を受け入れる（line_search.py）。止まるのは、80回反復、相対的な改善が10⁻¹⁰未満の更新が5回続いたとき、受け入れに12回続けて失敗したときである。

J は中心差分で求める（finite_difference_jacobian.py）。刻みは

  h_j = max(1, |x_j|) · 10^(−min(桁数/2, 30))

である。中心差分の打ち切り誤差は h² 程度、丸め誤差は 10^(−桁数)/h 程度なので、120桁では J の相対誤差は 10⁻⁶⁰ 程度に収まる。変数に依存しない行がわかっている問題では、互いに影響しない列をまとめて1回の差分で求める。角度を含む問題では、折れ目で中心差分が0になるときだけ片側の差分を使う。

### S1.3.3 なぜ段階的に桁を上げるか

正則な解の近くでは、ニュートン法の誤差は e_次 ≈ (L/2s) e² で減り（s は最小特異値、L はヤコビアンのリプシッツ定数、S1.9）、正しい桁数は1回ごとにおよそ2倍になる。そのため、浮動小数点の候補（15桁程度）を最初から500桁で計算する必要はない。安い50桁で谷の底に近づき、100桁、120桁と上げてから、仕上げで250〜500桁に伸ばす。ただし J に相対誤差 η があると、ニュートン法の誤差は1回で κη 倍程度（κ は条件数）までしか減らない。120桁の中心差分では η は10⁻⁶⁰程度なので、この制限は目標の10⁻⁸⁰に対して強くない。仕上げでは、解析的な微分が使える問題ではそれを使う。

### S1.3.4 特異なヤコビアンと、変数が等式より多い系

回転のような自由度や重複した等式があると、J は正方でなかったり特異だったりする。仕上げでは、全体のニュートン法が使えないとき、または結果が確認を通らなかったとき、次の方法に切り替える（`_run_rank_aware_findroot`）。

```
J の各行・各列を最大成分で割って大きさをそろえる
完全ピボット選択のガウス消去で、独立な行の組 R と列の組 C を選ぶ
   （ピボットが 最大成分 × 10^(−min(25, max(12, 桁数/3))) 以下になったら止める）
C 以外の変数を固定し、R の等式だけでニュートン法を解く
最後に、元の全ての等式で残差が目標以下かを確かめる
```

選び方は局所的な座標の取り方にすぎず、条件を加えたり外したりはしない。採否は元の全ての等式で決める。

## S1.4 接する条件の符号付き残差

### S1.4.1 問題

入力の IsTangent(直線, 円) の値は |d − r|（d は中心から直線までの距離、r は半径）、IsTangent(円, 円) の値は min(|d − (r₁+r₂)|, |d − |r₁−r₂||) である（geometry/mp/mp_api.py）。値が0になる集合は正しいが、絶対値のため0の点で微分できない。中心差分は折れ目の両側の傾きを打ち消して0に近い値を返すので、LM 法やニュートン法は解の近くで正しい向きを失い、「近いが精度が上がらない点」で止まる。

もう1つの問題は二重根である。接点 P を「直線と円の交点」として作図すると、接する図では2つの交点が重なる。補足 S1.12 のとおり、P の位置のずれを h とすると R − d = h²/(R + d) で、残差は h の2乗でしか変わらない。残差 δ まで下げても、座標は √δ の精度にしかならない。

### S1.4.2 置き換え

精密化（S1.3）の間だけ、残差を、0になる集合が同じで、解で単純な0を持つ式に置き換える（mpmath_refiner.py の `_smooth_zero_constraint_residuals`、engine/standard/problem/tangency_contacts.py、geometry/mp/signed_tangency.py）。優先順は次のとおりである。

| 元の条件 | 置き換え後の残差 | 使う条件 |
|---|---|---|
| IsTangent(Line(A,B), 円)、または Distance(中心, Line(A,B)) = 半径 | ((O − P)·(B − A)) / \|AB\| | 接点 P が円の上と直線の上にあることを、作図か別の等式から示せるとき |
| IsTangent(円₁, 円₂) | ((O₁ − P) × (O₂ − P)) / r₁ | 2つの円に共通の点 P があると示せるとき |
| IsTangent(円₁, 円₂) | d − (r₁+r₂) と d − \|r₁−r₂\| のうち絶対値が小さい方（符号付き） | 上の条件が示せないとき |
| IsTangent(直線, 円) | δ² − r²（δ は正規化した直線の式に中心を代入した符号付きの値） | 接点が示せないとき |
| Distance(P, Q) = 0 | (P.x − Q.x, P.y − Q.y) の2行 | 両方が点のとき |

1行目は「接線は接点で半径に垂直」を使う。P が円の上かつ直線の上にあれば、この内積が0であることと接することは同値で、0は単純な根になる。2行目は「2円が共通点で接するなら、2つの半径は一直線上にある」を使う。δ² − r² = (δ − r)(δ + r) は、r > 0 なら δ = ±r で単純な0を持つ。

接点の証明は、入力の構文だけで行う。たとえば P が Intersect(直線, 円) として作図されている、P が直線を作る2点のどちらかである、OnCircle(P, 円) = 0 という等式がある、といった場合である。示せないときは置き換えない。

このほか、Circle(B + r·v, r) の形の円が別の円に内接する条件では、半径 r > 0 が作図の定義域から言えるので、r を割った後の等式 2((B − O)·v + R) + r(v·v − 1) = 0 を補助の行として加える（positive_radius_contacts.py）。元の行はすべて残す。

### S1.4.3 何が保証されるか

置き換えは精密化の一歩を決める残差だけを変える。最終検証（S1.5.2）は元の条件で行い、0になる集合が同じ符号付きの形（IsTangent を符号付きの値に、絶対値をその中身に書き換えたもの）で残差の小ささを判定する。置き換えで、元の条件を満たさない点が採用されることはない。

### S1.4.4 効果（S2.7 の再掲）

接する条件を含む24問のうち、探索で候補が作られる12問で、同じ候補の集合を置き換えありとなしで精密化した。置き換えなしでは7問で最良残差が8〜48桁にとどまり、ありでは119〜502桁に達した。残りの5問は両方で同程度だった。

## S1.5 最終検証と PSLQ による同定

### S1.5.1 流れ

精密化した候補は、残差の小さい順に次を通る（assemble_exact_results.py）。

```
for 候補 x（残差の小さい順）:
    検証(x, 桁数の段 = 80, 120, 180, 250, 350, 500)     # S1.5.2
    if 不合格: 捨てる
    if 求める量が数だけの式でない:
        確認(x, 桁数の段 = x の桁数より上の 250, 350, 500)   # もう一度、独立に
    同定(τ(x), τ の誤差の上限)                          # S1.5.3
    同定できたら採用
```

### S1.5.2 検証

各段の桁数で、次を行う（engine/standard/evaluation/final_verifier.py）。

1. 元の等式を「左辺 − 右辺」に正規化し、IsTangent を符号付きの値に、絶対値をその中身に置き換える（0になる集合は変わらない）。
2. 各等式の大きさと微分を測り、大きさをそろえた J で、独立な行と列を S1.3.4 と同じ方法で選び、ニュートン法の修正を最大8回行う。修正は、全ての等式のずれが減り、交点の枝が変わらないときだけ受け入れる。
3. 正規化した残差 max_i |r_i| / max(|r_i|, 項の大きさ, Σ_j |∂r_i/∂x_j| s_j) が10⁻³⁰以下であること（s_j は箱の幅、|x_j|、1 の最大）。
4. 不等式、点の並び、直線が定まる、三角形がつぶれない、交点の枝、作図の定義域について、余裕が誤差の100倍より大きいこと。余裕が誤差より小さく判定できないときは「未確定」で、合格にしない。
5. 求める量 τ とその誤差の上限を計算する。

連続する2つの段で合格し、桁数が180以上になった時点で合格とする。最短では120桁と180桁で合格する。

### S1.5.3 同定

τ の値と誤差の上限 ε から、正しい桁数 D = −log₁₀(ε / max(1, |τ|)) を求め、同定に使う桁数を min(検証の桁数, D + 10) にする。30桁未満なら同定しない（runtime/symbolic_operations.py）。

整数係数の多項式 a₀ + a₁τ + … + a_nτⁿ = 0 を、PSLQ でベクトル (1, τ, …, τⁿ) の整数関係として探す（exact/polynomial_search.py）。

```
for n = 1, 2, …, 最大次数:
    a ← PSLQ((1, τ, …, τⁿ), 許容誤差 10^(−桁数/2)（100桁以下では 10^(−3×桁数/10)）, 係数の上限)
    a を因数分解し、τ に最も近い実根を持つ既約因子を選ぶ（近さが同じなら棄却）
    相対残差 |Σ a_k τ^k| / Σ |a_k τ^k| < 10^(−3×桁数/5)（100桁以下では 10^(−2×桁数/5)）なら採用
    （τ を 10^k 倍した値でも同じことを試し、係数を戻す）
```

最大次数と係数の上限は、精密化の残差で3段階に分ける（identify_answer.py）。残差 ≤ 10⁻⁷⁰ なら次数8・係数10⁸、≤ 10⁻⁵⁵ なら次数6・係数10⁷、それ以外は次数4・係数10⁶。323問の公式の答えの次数は最大4だった（S2.7）。

候補の式が得られたら、SymPy で多項式の実根を厳密に表し、τ に最も近い根を選ぶ。その根と τ の差が ε 以内でなければ棄却する。多項式の残差でなく根までの距離で判定するのは、(x − 72)² のような重複した関係では残差が誤差の2乗になり、精度を実際より高く見せるからである。0と同定される場合は、τ が誤差の範囲で0であるときだけ採用する。

多項式で同定できないときは、A·π + B（A, B は有理数）の形を探す。求める量が角度や π を含むときは、多項式の前に有理数かどうかを先に試す。求める量が数だけの式（√2 など）なら、その式をそのまま答えにする。ほかの候補ですでに同定した式があれば、まずそれと誤差の範囲で一致するかを確かめる。

### S1.5.4 何を保証しないか

PSLQ が返すのは、指定した次数と係数の範囲で見つかった関係で、真の答えである証明ではない。保証しているのは「検証済みの τ と、選んだ代数的数の差が、計算で確かめた誤差の上限以内にある」ことまでである（本文7章）。必要な桁数の目安は補足 S1.13 にある。

## S1.6 代数的な前処理

### S1.6.1 対象

次を満たす問題では、数値探索の前に、作図と条件を多項式にして、有限個の解を厳密に列挙する（engine/standard/search/algebraic_branches.py）。

- 探索変数が1〜12個。
- 作図と等式で使う関数が、点・直線・円・交点・中点・垂線の足・外心・距離・面積・接する、などの定められた範囲にある。等式が比較や条件分岐を含まない（不等式は別に扱うのでよい）。

### S1.6.2 手順

```
代数的前処理(問題):
    各等式を、座標の多項式 P_i(u) = 0 にする:
        分母を払う
        √c を含む式 a + b√c = 0 は、a² − b²c = 0 に置き換える（絶対値も同様）
        元の √ や絶対値が非負であることは別に記録する
    （次数8、項60個を超えたらやめる）
    定数係数の行の組み合わせで、1次式の行を作って加える        # 距離の2乗の差など
    1次式の行で変数を消す（行の簡約）
    残りを、変数を共有しない組に分ける
    各組で:
        変数7個以下、次数4以下なら、辞書式順序のグレブナー基底を求める
        0次元（解が有限個）でなければやめる
        最後の変数だけの多項式 f を取り、平方因子を除く（次数16まで）
        他の変数が f の変数の1次式で書ければ、f の実根から全解を作る
        書けなければ、T = Σ kⁱ x_i（k = 1, 2, 3）を加えて同じことを試す
    各実根を数値の点にし、候補として渡す
CPU 時間0.5秒、全体1.5秒を超えたら、この経路をやめて通常の探索に戻る
```

### S1.6.3 何が保証されるか

多項式にするとき、分母を払い、√を2乗するので、元の問題にない根が加わることはあるが、元の実数解が失われることはない（各操作は元の等式から導かれる必要条件である）。したがって、列挙した根の中に元の問題の全ての解が含まれる。余分な根は、通常の精密化（S1.3）と最終検証（S1.5）で落ちる。前処理は候補を出すだけで、採否は数値探索で見つけた候補と同じ基準で決まる。

一部の枝が検証を通らなかったときは、浮動小数点での不合格は「解がない」ことの証明ではないとして、同じ seed の通常の数値探索も走らせ、両方の採用を合わせる（S1.2.1）。

### S1.6.4 効果（S2.2 の再掲）

代数的前処理が答えを出していた97問のうち74問は、外すと1.5倍以上遅くなった（中央値2.3倍）。ほかの226問では変化がなかった。

## S1.7 尺度座標

### S1.7.1 考え方

長さを決める条件が比だけの問題では、図全体を t > 0 倍しても条件は保たれ、求める量（比や角度）は変わらない。このとき、探索変数の1つを1に固定してよい。凍結版は、これを入力の構文から証明できたときだけ使う（engine/standard/problem/positive_scale_chart.py、engine/standard/search/scale_chart.py）。

### S1.7.2 証明の規則

全ての式に「長さの次数」を付けて確かめる。探索変数は次数1、数は次数0（0は任意の次数）。和・差は両辺の次数が等しいこと、積・商は次数の和・差、√ は次数の半分、sin・cos・tan は引数が次数0であることを要求する。点の座標は次数1、直線の式 ax + by + c は c だけが次数1、円の半径は次数1である。

次の全てが成り立てば、尺度座標を使う。

1. 全ての作図が、t 倍に対して t 倍の図を返す（定義域も t 倍で保たれる）。
2. 全ての等式の左辺と右辺が同じ次数を持つ（同次式）。
3. 全ての不等式が同次で、t > 0 倍で真偽が変わらない。
4. 求める量の次数が0。
5. ある探索変数 x について「x > 0」が条件にある。

このとき、許容な図 u に対して u/x も許容で、x 成分は1、求める量は同じである。逆に x = 1 の許容な図は元の問題の許容な図である。したがって、x = 1 に固定した問題の答えの集合は、元の問題の答えの集合と一致する。

### S1.7.3 使い方

x = 1 に固定して変数を1つ減らした系を、代数的前処理（S1.6）に渡す。得られた根は、x = 1 を加えた点として、通常の探索の候補に加える。通常の探索は置き換えず、そのまま走る（run_search.py）。

### S1.7.4 効果（S2.2 の再掲）

凍結版で尺度座標だけを外しても、時間比は1.15〜1.17倍で、計測の負荷の差と区別できなかった。10月の改良で v5（この固定を加えた版）の正解が319から322に増え、時間の中央値が4.4秒から3.1秒に下がったが、その理由はこの表からは分からない（S3）。【開発外34問での NO_SCALE_CHART の結果（事前登録6の実験2）を追記。】
