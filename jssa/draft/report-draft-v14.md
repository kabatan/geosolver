# 作図による幾何の求値 ― 数値計算で解くための工夫と、その効き方

## 要旨

幾何の求値問題を、作図と条件で書いた入力から、定理を探さずに解く solver を作った。数値探索で図を見つけ、高精度化し、答えを √ などを含む式として同定する。数値計算で求値をするときの障害を、候補を見つける・精密化する・式にする、の3段に分け、工夫の効き方を、完成した solver から工夫を外す比較と、変更する段の入力をそろえた比較で調べた。中心の結果は「接する」条件の扱いである。円周上の点を通る直線の接触を中心からの距離で書くと、残差は接線からのずれの2乗でしか変わらない。solver は入力の作図から接点を確かめ、接点で半径と接線が垂直という残差に自動で直す。接する条件を含む12問で、同じ候補から接する条件の残差だけを替えて精密化すると、接点を使わない符号付き残差では目標値が8桁以下しか合わなかった3問で、接点を使う残差は340〜484桁合った。効果は問題によって異なり、変わらない問題、逆に悪くなる問題もあった。ほかに、候補を散らして選ぶと答えが複数ある問題での取りこぼしが減ること、調べた同定の失敗では係数の上限が制約になっていたことを示した。完成した solver は開発に使っていない34問で170回中161回正解し、記録の残る169回で誤った値を返さなかった。

## 1 はじめに

LLMの数学の力を競う大会（AIMO）で、私はLLMが長さや角度を求める幾何の問題（求値問題）を苦手とすることを知った。数学オリンピックで幾何を学んできた経験から言えば、人間が苦労するのは補助線や定理を見つける部分である。しかし、図を正確に作れれば、答えは計算で求まるはずである。そこで、問題を作図と条件で書いた入力から、計算だけで答えを求める solver を作った。【本人確認：AIMOを見た時期と、目的の書き方。】

ただし、数値計算で求値をするのは簡単ではない。条件を満たす図に当たらない、当たっても精度が上がらない、値が分かっても式にならない、という障害がある。本稿の問いは、(1) solver はそれぞれの障害をどんな工夫で越えたか、(2) その工夫は、どの問題で、どの段に、どれだけ効くか、(3) 完成した solver は開発外の問題でどこまで解け、厳密法とどう違うか、である。

## 2 先行研究と位置づけ

AlphaGeometry [1, 2] は記号的な推論で証明や値の計算をする。図を座標の多項式で表して厳密に解く方法 [3, 8] は、答えの正しさを保証できる。数値的な方法では GMB [4] が最も近く、作図に当たる直接計算で変数を減らし、条件を満たす図を数値的に生成する。GMB にも接点を指定する条件や接線の表し方はある。数値から代数的な関係を復元する PSLQ [7] も既知である。本研究の新しさは、接点を使う発想そのものではなく、入力の構文から適用できるかを確かめて残差を自動で直す仕組みと、その効果を求値の精度で測ったことにある。加えて、答えの集合を取りこぼさない候補の選び方、同定の限界を、実際の出題問題で調べる。

## 3 solver の設計

問題は、探索変数 u、作図 h、等式 F(u) = 0、不等式 G(u) > 0、求める量 τ で書き、集合 { τ(u) ｜ F(u) = 0, G(u) > 0 } を求める。中点や交点などは作図で u から計算するので変数にならない。

## 4 実験の設計

比較は2種類ある。1つは、完成した solver から工夫を1つ外す比較で、他の段が補う分も含めた最終的な効果を見る。もう1つは、変更する段の入力をそろえる比較で、同じ候補の集合から精密化だけ、同じ高精度値から同定だけを比べ、その段での効果を見る。前者には開発群323問から機械的な規則で選んだ72問を使った（遅い・不安定な問題48、速い問題16、答えが複数ある問題の全件8。S4.6）。差が出やすい問題を多めに選んでいるので、全問題の平均とはしない。各問は3 seed、180秒、1コアで解き、3回中2回以上で答えの集合が完全に一致すれば「解けた」とした。費用は、正解なら実時間、それ以外は180秒として平均した。予測はすべて実行前に公開した。solver は凍結版（60db4b6）で、スイッチ以外は変えていない。

## 5 工夫はどの障害に、どう効くか

### 5.1 候補を見つける：探索の重ね方

素朴な方法（箱から一様に選んだ出発点から局所探索を1回）では一度も正しい図に当たらない問題が、292問中25問あった。そのうち21問を完成した solver は3回とも解き、答えを出した段は NOMAD、第2探索、救済の探索に分かれた（S4.1）。ただし72問の比較では、第2探索を外しても解けた問題は69問から67問に減っただけで、第2探索が動いたのも216回中13回だった。遅い問題で4問以上減るという予測は外れた（S4.6）。局所探索の当たりやすさを上げる工夫も、完成した solver の費用は下げなかった（S5.5）。前段を改善しても、全体の性能に移るとは限らない。

### 5.2 候補を散らして残す：答えの集合を取りこぼさない

答えが複数ある問題では、図の候補が同じ谷に集まると、別の答えの図を落とす。そこで solver は、残差の小さい候補だけでなく、互いに離れた候補を残して20個を選ぶ。この選び方だけを「残差の小さい順に20個」に替えると、答えが複数ある8問（24回）で集合が完全に一致した回数は19回から13回に減り、一部の値だけを返した回数は2回から8回に増えた。答えが1つの64問では、解けた問題の数は63問と64問で、時間の比の中央値も0.98倍だった（S4.7）。この問題群では、散らす選び方は単一値の問題の時間をほぼ変えずに、複数値の取りこぼしを減らした。

### 5.3 接する条件の残差を直す

単位円と、円上の点 T = (1, 0) を通り方向 (s, 1) の直線を考える。接する条件を「中心から直線までの距離＝半径」で書くと、残差は 1/√(1+s²) − 1 = −s²/2 + O(s⁴) で、接する s = 0 で1次の変化が消える。円周上の点を通るように直線を作図すると、このように接線からのずれが残差に2次でしか現れない。このときニュートン法は誤差を毎回およそ半分にしか減らせない。一方、「接線は接点で半径に垂直」を使った残差 (T − O)·(s, 1) = s は1次で変わり、1回で解ける。solver は、接点が円と直線の上にあることを入力の作図から確かめられる場合に限り、この形に自動で直す（S1.4）。直線を平行に動かす作図では元の残差も1次で変わるので、この書き換えが効くのは作図の仕方による。また書き換えても、系全体の特異性が必ず消えるわけではない。

接する条件を含み、探索で候補が作られる12問で、同じ保存候補から、接する条件の残差だけを3通りに替えて精密化した（各90秒、事前登録10）。T0 は元の残差 |d − r|、T1 は接点を使わない符号付き残差（直線と円では δ² − r²。δ は符号付きの距離で、例では −s² + … と2次のまま）、T2 は入力から接点を確かめられる条件で接点を使う残差（既定）である。距離0の座標差と半径の補助式は固定した。T1 は距離の2乗も使うので、T0 との差を絶対値の除去だけの効果とはしない。

3問では T0・T1 とも8桁以下にとどまったが、T2 では340〜484桁に達した。別の1問では8→161→485桁と段階的に上がった。一方、1問は T1 で6桁から159桁に上がり、T2 による追加の改善はなかった。残る7問は、5問が同程度、1問は T0 の方が27桁良く、1問は3通りとも候補が通らなかった（図2、S4.11）。大きく改善した5問で T1 が T0 より40桁以上良いのは1問以下という予測は、2問で外れた。したがって、接点を使う残差には、接点を使わない符号付き残差では得られない精度の改善があるが、その効果は問題による。

この結果を受けて、原因を調べる追加の記述的な計測を行った（S4.12）。計測を考えたのは同じ候補での2通りの比較（S4.8）の結果を見た後で、計算と公開は3通りの比較の結果を見る前である。予測を定めた検証ではない。高精度の参照の図が得られた8問で、全ての残差のヤコビ行列を差分で評価した。接点を使う式で改善した3問では、T1 の最小特異値は差分の幅によって変わるほど極めて小さく、T2 では0.008〜0.2だった。差のなかった4問では T1 と T2 の最小特異値は同程度で、小さくなかった。T1 で159桁に達した1問では、T1・T2 とも小さいままだった。この観測は、接点を使う式が、系全体で1次の変化が失われる方向を回復するという説明と整合する。ただし、解での階数を厳密に示したものではない。条件を1本ずつ勾配で分類する事前の方法（事前登録11）は外れた。1本ずつの勾配が0でなくても、系全体で探索変数の各方向の変化を捉えられるとは限らない。

最終検証も、符号付きの残差とニュートン法の修正を使う。精密化の直後に書き換えありだけが通った5問を、同じ候補のまま最終検証まで追うと、4問では書き換えなしの側も通り、差が残ったのは1問だった（S4.8）。完成した solver から精密化の残差書き換え一式（接する条件、距離0の座標差、半径の補助式）を外すと、72問で解けた問題は69問から68問とほぼ変わらず、費用の平均は26.8秒から33.1秒に増えた（S4.7）。増えた6.3秒のうち3.3秒は両方が正解した実行の余分な時間、3.0秒は外した側だけが失敗した実行の分だった。半数以上の問題で影響が出るという予測は外れた。後段の修正まで通すと前段での差は小さくなり、この問題群では、書き換え一式の寄与は解けた問題の数より費用に現れた。

### 5.4 式にする：図は同じで、求める量だけ難しくする

AIME 2014 II-10 の答え 3042147√3 の最小多項式は x² − 27763975108827 で、2次だが係数が14桁ある。solver は5回とも図を見つけたが、同定で落ちた。保存した高精度の値で、係数の上限を10⁸のまま桁数を120・250・500と上げても同定は全て棄却され、上限を10¹⁴、10²¹に上げると正しい式が得られた。

AIME 2019 I-12 では、同じ図のまま、求める量だけを原問・長さ・面積・角・比に替えた（S5.7）。原問と比は同定できたが、長さと面積は、桁数を120・250・約350と上げても全て棄却され、上限を10²¹にすると両方とも正しい式が得られた（真の最大係数は長さで1.3×10²⁰、面積で3.1×10¹⁴）。図を得る難しさを変えずに、式にする難しさだけが変わる。

計画した78条件のうち、実施した54条件では正しい式が50、誤った式が0、棄却が4だった。24条件は、必要な桁数の座標が得られず実施できなかった（S4.9）。調べたこれらの同定の失敗では、桁数ではなく係数の上限が制約になっていた。上限を上げると誤った式の危険も増えるので、上げるだけでは解決しない。

### 5.5 目標値が満たす多項式を厳密に認証する

数値で得た答えについて、目標値の最小多項式が、入力の等式と非零条件から従うかをグレブナー基底で厳密に調べ、証拠の恒等式を別のプログラムで検算した。開発外で変換できた21問では、当初の規則で認証できたのは4問で、予測（50%以上）を下回った。失敗の多くは「距離は負にならない」が等式に入らないためだったので、結果を見て規則を拡張し、同じ問題群で確かめると計11問となった。うち8問では符号の条件と合わせて値が1つに決まったが、許容な図の存在は別に確かめる必要がある。残る3問は認証だけでは値を1つに絞れなかった。また当初の認証では、強化版の厳密法（6章）が解けなかった問題を新たに認証した例はなく、時間の短縮も確認できなかった。この方法の成果は、一部の問題で検算できる多項式関係の証拠を付けられることで、図の存在や答えの集合の完全さを示すものではない（S4.10）。

## 6 完成した solver は何ができ、厳密法とどう違うか

開発に使っていない34問（AIME 17問、HMMT 17問）を、入力を書き、予測を固定してから5 seed で解いた。170回中161回正解し、失敗は答えなし8回と記録の欠測1回で、記録の残る169回では誤った値はなかった。入力を原文と照合すると、答えから得た定数は0問で、解法の関係式が入った問題が5問あった。その5問を除いた29問でも、145回中141回正解した（S3.2）。開発外の問題には答えが複数ある問題がなく、集合の回収は開発群でしか確かめていない。また最初に作った別の26問では、答えの形式（m + n など）を整数の変数として書いた入力規則のために、130回中85回にとどまった（S3.3）。

比較のため、同じ34問を多項式に自動変換して msolve [8] で解くと、正しい答えの集合が出たのは23問だった。そこで、入力から機械的に決まる規則で、求める量への消去、非零条件による飽和、三角関数の定数の代数化、未知数0の場合の直接評価を行う強化版の厳密法を作った。規則の開発に使った5問を除く開発外29問（上の29問とは別の組）では20問を解き、従来の msolve で解けなかった開発群122問では39問を解いた。後者は従来法の失敗例に限った評価である（S4.3b）。

solver が解けて強化版が解けなかった問題は、開発外で8問、開発群で82問だった。この90問のうち52問は、π や角度を含むなど今回の変換器が扱えない入力で、残る38問は変換後に未解決だった（時間切れ15問など）。変換器が扱えないことは、厳密法一般の限界とは区別する。両方が解けた58問では、実行時間の中央値は強化版0.9秒、solver 2.7秒だった。強化版も、多項式の部分は厳密に計算するが、枝の選別と成功の判定には solver と同じ数値検証を使った。以上から、今回の実装では、両方が解けた問題の速さと、時間内に扱える入力の範囲に違いがあった。

## 7 限界

solver は、すべての答えを見つけたことを保証しない。工夫の比較は開発群の72問と12問など限られた問題で行い、seed も3つ以下である。同じ72問・同じ seed を2台の PC で解くと、216回中4回で結果が違った（3回は180秒の上限の近く）。開発外の34問は少数で、HMMT は17問中16問が Guts である。入力はAIが作ったので、入力作成まで含めた未知問題の評価ではない。時間は共有機の負荷の下での参考値である。外れた予測と主張の修正は各節に示し、主なものを S5.4 にまとめた。

## 8 結論

数値計算で幾何の求値をするための障害を、候補を見つける・精密化する・式にするの3段に分け、工夫の効き方を2種類の比較で調べた。中心の結果は、入力から確かめた接点を使って接する条件の残差を自動で直す工夫である。接点を使わない符号付き残差では精度が上がらなかった問題で、同じ候補から目標値の精度を数桁から数百桁へ改善できた。ただし効果は問題によって異なり、系全体の数値的な性質による説明は追加の分析として示した。後段の修正まで通すと前段での差は小さくなり、書き換え一式の寄与は費用に現れた。候補を散らして選ぶと、複数値の取りこぼしが減った。調べた同定の失敗では係数の上限が制約で、図が同じでも求める量によって式にする難しさが変わった。今後は、同じ考えを接する条件以外の、正しい図で系が特異になりやすい条件に広げることと、同定の係数の上限を、誤った式を増やさずに問題に応じて変える方法を調べたい。
