## 要旨

幾何の求値問題を、定理を使わず数値計算で解くsolverを作った。作図で決まる点を変数にしない表し方で、探す変数を図の自由度まで減らし、見つけた図を数百桁まで精密化して、答えを √ などの式に直して確かめる。コンテストの323問では969回中953回正解し、時間の中央値は5.2秒だった。完成後に出題された20問でも18問を毎回解いた。図を多項式で表して厳密に解く方法（msolve）は、解けた201問ではずっと速かったが、残る約4割は解けず、solverはそれらもほぼ解いた。この差を説明するため、難しさを二種類に分けた。厳密法の計算量は方程式の代数的な大きさで決まり、solverの計算量は「1回の局所探索で正しい図に当たる確率」で決まる。後者は探索変数の数とともに下がり、同じ問題でも作図を変数に書き換えると下がった。人間にとっての難しさは、solverの時間をほとんど予測しなかった。数値的に図を作る既存手法GMBと同じ36問で比べると、条件を満たす図を出した回数は108回中101回と29回だった。

## 1 はじめに

LLMの数学の力を競う大会（AIMO）で、私はLLMが長さや角度を求める幾何の問題（求値問題）を苦手とすることを知った。数学オリンピックで幾何を学んできた経験から言えば（IMO 2025 金メダル）、人間が苦労するのは補助線や定理を見つける部分である。しかし、図を正確に作れれば、答えは計算で求まるはずである。そこで、幾何の知識を使わず、計算だけで答えを求めるsolverを作り、人間やLLMが幾何を解く助けにしようと考えた。【本人確認：AIMOを見た時期と、目的の書き方。】

本研究の問いは二つである。(1) solverをどう設計すれば、コンテストの求値問題を速く、厳密な答えで解けるか。(2) そのsolverにとって何が難しいのか。それは厳密な方法や人間にとっての難しさと、どう違うのか。

## 3 solverの設計と制作

### 3.1 問題を「値の集合」を求める問題として表す

問題は、探索変数 u（d 個の実数）と、作図、条件、求める量で書く。たとえば三角形は、頂点を (0,0)、(1,0)、(x,y) と置き、u = (x,y) とする。中点や交点などの点は、作図の命令で u から計算する。条件は等式 F(u) = 0 と不等式 G(u) > 0 で書く。不等式は「点は線分の内側」「2つの交点のうち遠い方」のように、条件を満たす図が複数あるときにどれを指すか（以下、枝）を決める。求めるのは、次の集合である。

  { 求める量 τ(u) ｜ F(u) = 0 かつ G(u) > 0 }

答えが1つの問題も、「すべての値を求めよ」という問題も、同じ形で書ける。

### 3.2 設計の柱

**作図で変数を消す。** 作図で決まる点は変数にせず、u の関数として計算する。こうすると、探す変数の数は図の自由度に等しくなる（323問の中央値で3個）。これが探索のしやすさを大きく左右することは、5章で理論と実験の両方から示す。

**条件を「ずれ」として扱う。** 等式のずれと不等式の違反をまとめたベクトル r(u) を作り、その大きさを0にする u を探す。角度や面積、接する、といった条件も、多項式に直さずそのまま計算できる。広く探す部分には微分を使わない探索法 NOMAD [9] を、出発点から近くの解へ下りる局所探索には Levenberg–Marquardt法（LM法）[10] を使う。見落としがあれば、設定を変えてもう一度探す（第2探索）。条件が1変数の方程式に直せる場合は、探索の前に式で直接解く [8]。

**二段階で精度を上げる。** まず通常の精度（約16桁）で図を見つけ、次に多倍長計算で数百桁まで精密化する。精密化の最後にはニュートン法を使う。解が単根なら、ニュートン法は1回ごとに正しい桁数がおよそ倍になるので、数百桁でも十数回で済む。

**答えを式に直して確かめる。** 数百桁の値 a に対し、1, a, a², …, aⁿ の間の整数係数の関係を PSLQ [11] で探す。見つかればそれが a の満たす多項式になり、そこから √ などの式が得られる。最後に、その式で表した図が条件と枝を満たすかを120〜500桁で確かめる。これは数学的な証明ではないが、偶然一致する可能性は極めて小さい。

**答えを集める。** 多くの出発点と第2探索で、答えが複数ある場合も集める。すべて集めたことの保証はしない。

## 5 solverにとっての難しさ：理論と検証

### 5.1 二種類の難しさ

厳密な方法は、方程式系をまるごと扱う。その計算量は、方程式の次数の積（ベズー数。解の個数の上限）のような代数的な大きさとともに増える。一方、solverが必要とするのは、条件を満たす実際の図に1回たどり着くことだけである。ランダムな出発点から1回の局所探索で正しい図に当たる確率を p、1回の時間を t とすると、探す時間はおよそ

  T ≈ t / p

になる（実際の探索はNOMADなので、これは目安の模型である）。つまり、二つの方法の難しさは別の量で決まると予想できる。

msolveが解けた201問で確かめた。ベズー数と探索変数の数は、互いにほとんど連動しなかった（順位相関0.12。順位相関は大小の並びの一致の度合いで、1なら完全に一致、0なら無関係）。msolveの時間はベズー数と強く連動したが（0.69）、探索変数の数とはほとんど連動しなかった（0.28）。solverの時間は、探索変数の数と連動し（0.57）、ベズー数ともある程度連動した（0.50）。つまり、探索変数の数は厳密な方法の難しさにはほぼ効かず、solverの難しさには効く。二つの方法は、別の量に弱い。

### 5.2 当たる確率は探索変数の数で決まる

探索変数がある292問で、出発点を200個ずつ選んで p と t を測った。出発点を選び直しても p はほぼ同じだった（順位相関0.99）。数値探索で解いた193問では、t/p は実際の時間と順位相関0.69で合った（図3右）。p の中央値は、探索変数1個で1.00、3個で0.72、5個で0.15、6個以上で0.11だった（図3左）。外れた探索の多くは、ずれが0でない谷底（局所解）で止まるか、探す範囲の外へ出ていた。

### 5.3 作図で変数を消すと、なぜ当たりやすいのか

作図で決まる点 y = h(u) を、あえて自由な点 y にし、等式 y − h(u) = 0 を足したとする。正しい図の集合は変わらないが、探す空間は d 次元から d+2 次元に広がる。局所探索は、元の条件のずれと、新しい等式のずれの二乗和を減らす方向に動く。すると、二つのずれを同時には減らせず、その釣り合いで止まる点（新しい局所解）が生じうる。作図で消していれば、y は常に h(u) に等しく、探索は d 次元の上だけを動くので、このような点は生じない。

この考えから、二つの予測が立つ。(a) 作図を自由な点に書き換えるほど p は下がる。(b) 書き換えた点を正しい位置 h(u) から出発させても、探索は途中で y ≠ h(u) の領域に出るので、p の低下は完全には消えない。

これを確かめるため、直接入力の問題から、探索変数が1〜4個で書き換えられる作図が3つ以上ある15問を、結果を見る前に規則で選んだ。各問題で、中点・交点・垂線の足・外心を k か所（k = 0〜3）書き換えた。結果は予測(a)と一致した（表5、図4）。p の中央値は k = 0〜3 で 0.96、0.77、0.40、0.38 と下がり、時間は中央値で3.43倍まで増えた。この傾向は検定でも偶然とは考えにくかった。正解の数はほとんど変わらず、書き換えはsolverを「解けなくする」のではなく「遅くする」。書き換えた点を正しい位置から出発させると、k = 2 では p が0.40から0.76に戻ったが、k = 3 ではほぼ戻らず（0.39と0.42）、予測(b)とも一致した。ただし、書き換えると等式も増えるので、これは探索変数の数だけの効果ではない。言えるのは、「作図で決まる点を、自由な点と等式で書き換えると、同じ問題でも当たりにくく、遅くなる」ことである。

### 5.4 枝の指定と重根

p は二つの確率の積に分けられる。

  p ＝（等式を満たす図にたどり着く確率）×（その図が正しい枝である確率）

323問では、等式を満たして枝だけを間違える外れ方はほとんどなく、後者は1に近かった。しかし、2026年のHMMT 2月 幾何5番は3回とも解けなかった。等式を満たす図には出発点の約99%でたどり着いたが、正しい枝（小さい円が弦の外側にある、など）は約0.3%だった。95%の確率で一度当てるには約1000回の探索が要る。人間なら図を見れば明らかな配置が、solverには大きな難しさになる。

もう一つは重根である。単根ではニュートン法の誤差は1回ごとに2乗になる（10⁻⁸ → 10⁻¹⁶）。しかし x² = 0 の x = 0 のような重根では、誤差は1回ごとに半分にしかならない。100桁を得るのに、単根なら十数回で済むところ、約330回かかる。実際、HMMT 2009年2月 幾何9番で条件 f = 0 を同じ意味の f² = 0 に書き換えると、精密化が進まず、5回とも解けなくなった。「接する」条件は書き方によって重根になるので、solverは確かめる段階で書き方を変えて避けている。

### 5.5 人間にとっての難しさとの関係

実際の正答率から推定された人間の難度（Easy2Hard [12]）がある131問で比べた。人間に難しい問題ほどsolverも遅い傾向はあった（順位相関 AIME 0.56、HMMT 0.32）。しかし、人間に難しい問題は探索変数も多く、その影響を除くと相関は0.28と0.25に下がった。さらに、1年ずつ除いて予測式を作り、除いた年で試すと、入力の形（探索変数・等式・不等式の数など）だけの予測は順位相関0.80、0.70で当たり、人間の難度を加えても0.80、0.71とほとんど変わらなかった。人間の難しさは補助線や定理の発見にあり、solverの難しさは探索変数と枝と重根にある。両者は無関係ではないが、別の量である。たとえば HMMT 2019年2月 幾何10番は人間には難問だが、作図だけで図が決まる（探索変数0個）ので1.5秒で解けた。逆に AIME 2015 I-7 は人間には易しめだが、探索変数が5個あり149秒かかった（図5）。【本人：この2問が人間にとってなぜ難しい／易しいかを一文ずつ。】

## 6 限界

solverは、すべての答えを見つけたことも、答えの式の正しさも、数学的には保証しない。323問は開発に使った問題であり、開発に使っていない問題での成績は2026年の20問と自動生成の88問で示した。厳密な方法との比較は、今回の多項式の作り方とmsolveに限ったものである。また、浮動小数のごく小さな違いで探索の道筋が変わるため、OSやCPUが違うと一部の問題で結果が変わった。比較はすべて同じPCで測った。

## 7 結論

作図で変数を消し、条件をずれとして扱い、数百桁の精密化と式への変換で答えを確かめるsolverを作った。コンテストの求値問題の大部分を数秒で解き、完成後の新しい問題でも20問中18問を毎回解いた。厳密な方法は小さい問題では速いが、323問の約4割は解けず、solverはそこもほぼ解いた。この違いは、厳密な方法の難しさが方程式の代数的な大きさで、solverの難しさが当たる確率で決まることから説明できた。当たる確率は探索変数の数で下がり、作図を変数に書き換えると同じ問題でも下がった。人間の難しさとは別の量である。今後は、作図で決まる点を自動で見つけて表し方を小さくすることと、枝の指定が厳しい問題の探索の改良に取り組みたい。【本人確認：次の一手。】
