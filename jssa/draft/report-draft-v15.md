# 作図情報を用いた幾何の数値求値 ― 残差の設計と精密化の関係 ―

<!-- v15 骨格版（10/24 16:30）。【 】は S7・S8・S9 の結果で埋める。方針：jssa/strategy/v15-design-branches.md、相談25 回答3。 -->

## 要旨

幾何の求値問題を、作図と条件で書いた入力から、定理を探さずに解く solver を作った。数値探索で図を見つけ、高精度化し、答えを √ などを含む式として同定する。この solver の設計を7つの論点に整理し、主要な選択を別の選択に替えたとき、どんな性質の問題で、どの段の精度・時間・答えの回収が変わるかを調べた。比較は、同じ入力から1つの段だけを比べる方法と、完成した solver から工夫を外す方法の2通りで行い、予測はすべて実行前に公開した。最も詳しく調べたのは残差の形である。円周上の点を通る直線の接触を中心からの距離で書くと、残差は接線からのずれの2乗でしか変わらない。solver は入力の作図から接点を確かめ、接点で半径と接線が垂直という残差に自動で直す。同じ候補から残差だけを替えると、接点を使わない符号付き残差では8桁以下だった3問で340〜484桁に達した。正しい図での系の性質から、効く問題を未使用の問題で2問、事前に当てた。【S7：接点以外の書き換えでの結果を1文】。ほかに、候補を散らして選ぶと答えが複数ある問題での取りこぼしが減ること、調べた同定の失敗では係数の上限が制約だったことを示した。一方、局所的な改善は完成した solver では後段が補い、主に時間の差として残った。【S8：素朴な最適化からの積み上げの結果を1文】。完成した solver は開発に使っていない34問で170回中161回正解し、記録の残る169回で誤った値を返さなかった。

## 1 はじめに

長さや角度を求める幾何の問題（求値問題）で人間が苦労するのは、補助線や定理を見つける部分である。しかし、図を正確に作れれば、答えは計算で求まるはずである。そこで、作図と条件で書いた入力から、幾何的な考察なしに計算だけで答えを求める solver を作った。LLM や人間が幾何の問題を解くのを支援することが目的である。今回確かめたのは、用意した入力から答えを求める計算の部分であり、利用者の解答を助けられるかはまだ調べていない。【本人確認：動機の書き方（10/22の回答に基づく）。】

ただし、工夫のない数値最適化で幾何の問題を解くのは難しい。条件を満たす図に当たらない、当たっても精度が上がらない、値が分かっても式にならない。完成した solver は、これらを多くの選択の組み合わせで越えている。本稿の問いは、それぞれの選択を別の選択に替えると、どんな性質の問題で、どの段の精度・時間・答えの回収が変わるか、そしてその差は完成した solver まで残るか、である。差が出ない場合、別の選択の方がよい場合、後段が補う場合も、答えに含める。

## 2 先行研究と位置づけ

AlphaGeometry [1, 2] は記号的な推論で証明や値の計算をする。図を座標の多項式で表して厳密に解く方法 [3, 8] は、答えの正しさを保証できる。数値的な方法では GMB [4] が最も近く、作図に当たる直接計算で変数を減らし、条件を満たす図を数値的に生成する。GMB にも接点を指定する条件はある。数値から代数的な関係を復元する PSLQ [7] も既知である。本研究の新しさは、個々の部品ではなく、入力の構文から適用できるかを確かめて残差を自動で直す仕組みと、設計上の選択の効き方を、実際の出題問題で、求値の精度と答えの回収で測ったことにある。

## 3 solver の設計

問題は、探索変数 u、作図 h、等式 F(u) = 0、不等式 G(u) > 0、求める量 τ で書き、集合 { τ(u) ｜ F(u) = 0, G(u) > 0 } を求める。中点や交点などは作図で u から計算するので変数にならない。

表1は、完成した solver を後から7つの論点に整理したものである。開発はこの順序で計画したものではない。

表1　設計上の論点と、本稿での扱い

| 論点 | solver の選択 | 主な代案 | 本稿 |
|---|---|---|---|
| 何を解くか | 図を数値で探し、値を式にする | 多項式系を厳密に解く | 6章 |
| 問題の表し方 | 作図で変数を減らす。代数の前処理と尺度の固定 | 全ての点の座標を変数にする | 5.1【S8】 |
| 候補を見つける | 微分を使わない探索 NOMAD [5]。答えが出なければ別の探索で補う | 多点出発の局所探索 | 5.1【S8・S9B】 |
| 候補を残す | 互いに離れた候補を残して20個選ぶ | 残差の小さい順 | 5.2 |
| 精密化する | 倍精度では信頼領域型の LM法 [6]（範囲制約つきは TRF）。多倍長では LM法（減衰と、残差が減るまでの刻みの縮小）とニュートン法 | 減衰なし、固定の減衰、ニュートン法のみ | 5.3【S9A】 |
| 残差の形 | 接点を使う残差、距離0の座標差、半径の補助式 | 条件をそのまま式にする | 5.3・5.4 |
| 値の同定と検証 | PSLQ（係数の上限10⁸）、180桁以上での条件と枝の照合 | 桁数・上限を変える | 5.5 |

## 4 実験の設計

比較は2種類ある。1つは、変更する段の入力をそろえる比較で、同じ候補の集合から精密化だけ、同じ高精度値から同定だけを比べ、その段での効果を見る。もう1つは、完成した solver から工夫を外す比較で、他の段が補う分も含めた最終的な効果を見る。後者には開発群323問から機械的な規則で選んだ72問を使った（遅い・不安定な問題48、速い問題16、答えが複数ある問題の全件8。S4.6）。差が出やすい問題を多めに選んでいるので、全問題の平均とはしない。各問は3 seed、180秒、1コアで解き、3回中2回以上で答えの集合が完全に一致すれば「解けた」とした。費用は、正解なら実時間、それ以外は180秒として平均した。solver は凍結版（60db4b6）で、スイッチ以外は変えていない。開発群での比較は開発外の検証ではないので、開発に使っていない問題での検証と分けて示す。

## 5 結果

### 5.1 素朴な最適化から完成した solver へ

【S8（事前登録15）：素朴版 N から工夫の群を1つずつ積み上げたときの解けた問題数と費用。最大の段、NOMAD の役割（解ける数か時間か、10月の全323問比較：SciPy の多点出発は319問対308問だが時間は約5倍）。S9B：NOMAD が効く問題の性質（不等式の数など）。3〜4文。】

完成した solver から第2探索を外しても、72問で解けた問題は69問から67問に減っただけで、第2探索が動いたのも216回中13回だった（S4.6）。前段の改善が全体の性能に移るとは限らない。

### 5.2 候補の選び方：答えの集合を取りこぼさない

答えが複数ある問題では、図の候補が同じ谷に集まると、別の答えの図を落とす。そこで solver は、互いに離れた候補を残して20個を選ぶ。これを「残差の小さい順に20個」に替えると、答えが複数ある8問（24回）で集合が完全に一致した回数は19回から13回に減り、一部の値だけを返した回数は2回から8回に増えた。答えが1つの64問では、解けた問題の数は63問と64問で、時間の比の中央値も0.98倍だった（S4.7）。散らす選び方は、単一値の問題の時間をほぼ変えずに、複数値の取りこぼしを減らした。

### 5.3 残差の形：接する条件

単位円と、円上の点 T = (1, 0) を通り方向 (s, 1) の直線を考える。接する条件を「中心から直線までの距離＝半径」で書くと、残差は 1/√(1+s²) − 1 = −s²/2 + O(s⁴) で、接する s = 0 で1次の変化が消える。このときニュートン法は誤差を毎回およそ半分にしか減らせない。一方、「接線は接点で半径に垂直」を使った残差 (T − O)·(s, 1) = s は1次で変わり、1回で解ける。solver は、接点が円と直線の上にあることを入力の作図から確かめられる場合に限り、この形に自動で直す（S1.4）。直線を平行に動かす作図では元の残差も1次で変わるので、効くかどうかは作図の仕方による。

接する条件を含む12問で、同じ保存候補から、接する条件の残差だけを3通りに替えて精密化した（各90秒、事前登録10）。T0 は元の残差 |d − r|、T1 は接点を使わない符号付き残差（直線と円では δ² − r²。例では −s² + … と2次のまま）、T2 は接点を使う残差（既定）である。3問では T0・T1 とも8桁以下にとどまったが、T2 では340〜484桁に達した。1問は8→161→485桁と段階的に上がり、1問は T1 で6桁から159桁に上がった。残る7問は、5問が同程度、1問は T0 の方が27桁良く、1問は3通りとも候補が通らなかった（図2、S4.11）。

原因を調べる記述的な計測として、高精度の参照図で全ての残差のヤコビ行列の最小特異値を求めた（S4.12）。T2 で改善した3問では、T1 の最小特異値は差分の幅で変わるほど小さく、T2 では0.008〜0.2だった。差のなかった4問では両者は同程度で、小さくなかった。この指標を、比較に使っていない接する条件の問題32問に、精密化の前に当てはめて予測を固定した（事前登録12）。T1 だけが小さいと分類した2問では、予測どおり T2 が T1 より101桁と478桁良かった。両方とも小さいと分類した1問は T2 で483桁に達し、予測は外れた。条件を1本ずつ勾配で分類する事前の方法（事前登録11）も外れた。1本の残差が1次で変わっても、系全体で各方向の変化を捉えられるとは限らない。

完成した solver で T1 と T2 を比べると、T2 だけが解けたのは4問で、T1 は3 seed とも180秒で打ち切られた（事前登録13、S4.14）。【S6 の WinPC 再確認の結果】。一方、精密化の残差書き換え一式を外しても、72問で解けた問題は69問から68問とほぼ変わらず、費用の平均は26.8秒から33.1秒に増えた（S4.7）。最終検証も符号付きの残差とニュートン法の修正を使い、精密化の直後に書き換えありだけが通った5問のうち4問は、最終検証で書き換えなしの側も通った（S4.8）。後段まで通すと、書き換えの寄与は主に費用に現れた。

図2　接する条件を含む12問で、同じ候補の集合から接する条件の残差だけを替えて精密化したときの、目標値の正しい桁数（事前登録10）。

### 5.4 残差の形：接する条件の外へ

接する条件の外も含めて、開発群で参照図が得られた266問で、同じ候補から書き換え一式の有無だけを替えて精密化した（各90秒、事前登録14、S4.15）。測定できた261問のうち、252問では差が40桁未満で、書き換えなしでも多くの問題で300桁以上に達した。40桁以上良くなったのは8問（接する条件あり4問、なし4問）、悪くなったのは1問だった。差の出た9問は、すべて書き換えなしの系が参照図で特異と判定された問題だった。接する条件のない4問は距離を0にする条件を含み、書き換えなしでは約40桁で止まった【S7補遺：微分不能か特異かの区別】。一方、書き換えありでも特異な問題37問の86%は300桁以上に達し、「特異なら精密化が難しい」という予測（W2）は外れた。書き換えが効くのは、書き換えなしの系が特異になる限られた型であり、精密化の段は大半の問題でそれだけで十分な精度に達した。

### 5.5 値の同定と検証

AIME 2014 II-10 の答え 3042147√3 の最小多項式は x² − 27763975108827 で、2次だが係数が14桁ある。solver は5回とも図を見つけたが、同定で落ちた。保存した高精度の値で、係数の上限を10⁸のまま桁数を120・250・500と上げても同定は全て棄却され、上限を10¹⁴、10²¹に上げると正しい式が得られた。AIME 2019 I-12 では、同じ図のまま求める量だけを替えると、長さと面積は桁数を上げても棄却され、上限を10²¹にすると正しい式が得られた（S5.7）。実施した54条件では正しい式が50、誤った式が0、棄却が4だった（S4.9）。図を得る難しさと式にする難しさは別で、調べた失敗では係数の上限が制約だった。

数値で得た答えについて、目標値の最小多項式が入力の等式と非零条件から従うかをグレブナー基底で調べ、証拠の恒等式を別のプログラムで検算した。開発外で変換できた21問で、当初の規則では4問、結果を見て拡張した規則では11問を認証した。これは一部の問題で検算できる多項式関係の証拠であり、図の存在や答えの集合の完全さは示さない（S4.10）。

## 6 完成した solver は何ができ、厳密法とどう違うか

開発に使っていない34問（AIME 17問、HMMT 17問）を、入力を書き、予測を固定してから5 seed で解いた。170回中161回正解し、失敗は答えなし8回と記録の欠測1回で、記録の残る169回では誤った値はなかった。入力を原文と照合すると、答えから得た定数は0問で、解法の関係式が入った問題が5問あり、それを除いた29問でも145回中141回正解した（S3.2）。開発外の問題には答えが複数ある問題がなく、集合の回収は開発群でしか確かめていない。最初に作った別の26問では、答えの形式を整数の変数として書いた入力規則のために、130回中85回にとどまった（S3.3）。

同じ34問を多項式に自動変換して msolve [8] で解くと、正しい答えの集合が出たのは23問だった。そこで、入力から機械的に決まる規則で、求める量への消去、非零条件による飽和、三角関数の定数の代数化、未知数0の場合の直接評価を行う強化版の厳密法を作った。規則の開発に使った5問を除く開発外29問では20問を解き、従来の msolve で解けなかった開発群122問では39問を解いた（S4.3b）。solver が解けて強化版が解けなかった90問のうち52問は π や角度を含むなど変換器が扱えない入力で、残る38問は変換後に未解決だった（時間切れ15問など）。両方が解けた58問では、実行時間の中央値は強化版0.9秒、solver 2.7秒だった。強化版も、枝の選別と成功の判定には solver と同じ数値検証を使った。今回の実装では、両方が解けた問題の速さと、時間内に扱える入力の範囲に違いがあった。

## 7 限界

solver は、すべての答えを見つけたことを保証しない。設計の比較は開発群の限られた問題で行い、seed も3つ以下である。同じ72問・同じ seed を2台の PC で解くと、216回中4回で結果が違った。開発外の34問は少数で、HMMT は17問中16問が Guts である。入力はAIが作ったので、入力作成まで含めた未知問題の評価ではない。最小特異値は参照図を使うので、失敗の説明には使えるが、解く前に選択を決める規則ではない。時間は共有機の負荷の下での参考値である。外れた予測は各節に示し、S5.4 にまとめた。

## 8 結論

幾何の求値を数値計算で行う solver の設計を7つの論点に整理し、主な選択を替えたときの効き方を、段の入力をそろえた比較と完成した solver での比較で調べた。残差の形では、入力から確かめた接点を使う書き換えが、接点を使わない符号付き残差では精度が上がらない問題で、目標値の精度を数桁から数百桁に上げ、効く問題を系の性質から事前に当てられた。【S7 の一般化の結論】。候補を散らして選ぶと複数値の取りこぼしが減り、同定では係数の上限が制約だった。【S8：素朴版からの積み上げの結論】。一方、局所的な改善は後段が補って、完成した solver では主に時間の差として残った。必要な役割を担う選択と、他の処理で補える選択がある。今後は、利用者の解答を実際に助けられるかを確かめたい。
