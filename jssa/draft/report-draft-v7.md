# 作図で解く求値幾何solverと、その難しさ（題名は仮）

（v7・10/23朝。v6 に GPT-Pro の第9回レビューを反映し、夜の間に行った2つの実験を加えた。1つは、実行前に予測を固定して新しい43問で確かめたもの。もう1つは、その予測の一部が外れた原因を突き止めたもの。証明・手順・全ての表は補足資料 S1〜S4 に置いた。【 】は本人確認か未完。）

## 要旨

幾何の求値問題を、定理を使わず数値計算で解くsolverを作った。作図で決まる点は変数にしない。見つけた図を数百桁まで精密化し、答えを √ などを含む式として同定する。コンテストの323問では969回中953回正解し、時間の中央値は5.2秒だった。問いは2つである。(1) solverをどう実現したか。(2) そのsolverにとっての難しさは、人間の難しさとどう違うか。(1)では、各仕組みが受け持つ困難を決め、通常の実行の記録から、その仕組みを外したときに影響を受ける問題を予想し、外す実験と比べた。(2)では、局所探索の費用を「評価1回の費用」と「当たるまでの評価回数」に分けた。問題ごとの違いの87%は後者から来ていた。人間の難度は、両大会で前者と正の関係があった。さらに、正しい図を変えない入力の書き換えで、当たる確率が1.00から0.03まで落ちる例を示した。原因は変数の数ではない。点を式で持つと、遠くからの大きな一歩で作図の式が崩れ、一歩が切り詰められることだった。これを理論で導き、予測を先に固定した実験で確かめた。solverの難しさは問題文だけでは決まらず、何を作図で計算し、残りをどの座標で探すかで変わる。

## 1 はじめに

LLMの数学の力を競う大会（AIMO）で、私はLLMが長さや角度を求める幾何の問題（求値問題）を苦手とすることを知った。数学オリンピックで幾何を学んできた経験から言えば（IMO 2025 金メダル）、人間が苦労するのは補助線や定理を見つける部分である。しかし、図を正確に作れれば、答えは計算で求まるはずである。そこで、幾何の知識を使わず計算だけで答えを求めるsolverを作った。【本人確認：AIMOを見た時期と、目的の書き方。】

問いは2つである。(1) solverをどう実現したか。(2) そのsolverにとっての難しさは、人間が感じる難しさとどう違うか。(2)が分かれば、solverを人間やLLMの補助に使うとき、どの問題で役立つかが分かる。

## 2 先行研究

AlphaGeometry [1, 2] は命題を証明する方法で、値を求める本研究とは課題が違う。図を座標の多項式で表して厳密に解く方法 [3, 13] は、答えの正しさを保証できる。数値的な方法では GMB [6] が最も近い。GMB も座標の取り方を工夫して条件のずれを最小化し、図を作る。本研究が違うのは、「考えられる値をすべて求めよ」型を含めて答えの値の集合を求めること、複数の図を探すこと、値を式として同定して高精度で確かめることである。コンテストの求値問題で、solverの難しさを人間の実測難度と数百問の規模で比べた研究は、調べた範囲では見当たらなかった（S4）。

## 3 solverをどう実現したか

### 3.1 問題の表し方

問題は、探索変数 u（d 個の実数）、作図 h、等式 F(u) = 0、不等式 G(u) > 0、求める量 τ で書く。中点や交点などは、作図で u から計算する。不等式は、条件を満たす図が複数あるときにどれを指すか（以下、枝）を決める。求めるのは集合 { τ(u) ｜ F(u) = 0, G(u) > 0 } で、答えが1つの問題も「すべての値を求めよ」型も同じ形で書ける。

### 3.2 4つの困難と、それを受け持つ仕組み

求値の過程には4つの困難がある。それぞれに仕組みを当てた（表1）。

表1　困難と仕組み

| 困難 | 仕組み |
|---|---|
| 探す変数が多い | 作図で点を消す。式で直接解ける小さな系は、枝を列挙して探索を省く（代数的前処理） |
| 正しい図に当たらない | 微分を使わない安い探索（NOMAD [9]）を1段目に置き、答えが出なければLM法 [10] の多点出発（第2探索）と、範囲を分けた再探索（rescue）で補う |
| 精度が上がらない | 多倍長のLM法とニュートン法。「接する」などの条件は符号付きの残差に直す |
| 値が式にならない | PSLQ [11] で最小多項式を同定し、120〜500桁で条件と枝を確かめる |

### 3.3 1問を通して見る

AIME 2021 I-11 を例にとる。円に内接する四角形 ABCD の辺が 4, 5, 6, 7 で、各頂点から対角線に下ろした垂線の足 4 つが作る四角形の周の長さを求める。入力では A = (0, 0)、B = (4, 0) と置き、C、D の座標の 4 つを探索変数にする（d = 4）。垂線の足は作図で計算するので変数にならない。等式は BC = 5、CD = 6、DA = 7 と、4点が同一円上にあることの4つ、不等式は C、D が上側にあることと凸であることである。

実行（seed 0）では、1段目の探索が1.4秒で候補を20個出した。精密化（1.8秒）で14個が収束し、6個は偽として捨てられた。残りの候補から得た値 4.1016949… を、PSLQ が 242/59 と同定し、120桁以上で条件と枝を確かめた（7.9秒）。全体で12.9秒だった。1回の局所探索（LM法）で見ると、当たる確率は0.49、評価回数は129回、評価1回は2.0ミリ秒だった（5.2節）。

### 3.4 仕組みの役割を、通常の実行から予想して確かめる

表1の役割分担が正しければ、通常の実行で「その仕組みが答えを出した問題」が、外したときに影響を受けやすいはずである。本計測（323問×3回）の記録から答えの出どころを調べて影響を予想し、1つずつ外した計測（各323問）と比べた（S2.2）。

- **代数的前処理。** 答えを出したのは97問。外すと、このうち74問が1.5倍以上遅くなった（中央値2.3倍）。他の226問では0問だった。正解数は変わらず、他の経路が遅れて解いた。
- **第2探索。** 答えを出した10問のうち9問を、外すと失った。他の問題で失ったものはなかった。
- **rescue。** 答えを出した9問のうち、外して失ったのは1問だった。残りは別の経路が解いた。他の問題では、外して逆に解けた問題が3問あった。仕組みが重なっているので、1つを外しても正解数には表れにくい。

1回の局所探索が当たる確率を p、1回の時間を t とすると、出発点を独立に選び直す限り、当たるまでの時間の期待値は t/p である（S1.1）。LM法の多点出発を1段目に使うと、探索時間は t/p と順位がよく合い（順位相関0.72）、t/p の上位4分の1では中央値63秒かかった。NOMADは同じ問題で中央値1.5秒で、難しい問題でも費用がほとんど増えない安い1段目として働いている。

外れの費用は大きい。候補は数百桁まで精密化されてから真偽が決まるので、時間の51%は精密化に使われる。p が低い問題ほど偽の候補が増え、p の下位4分の1では1回の実行あたり中央値7個が偽と判定され、精密化に7.0秒かかった（上位4分の1では0個、0.07秒）。

### 3.5 精度と同定

323問の公式の答え（π を含む7問を除く316問）の最小多項式は、次数が4以下、係数は最大で10⁹程度だった。PSLQ で同定に要る精度の目安は（次数＋1）×（係数の桁数）で、最大でも43桁である。solverは120桁以上の作業精度で計算するので、余裕は大きい。ただし、作業精度は正しい桁数と同じではない。正しい桁数を下げるのは重根である。「接する」条件は重根になりやすく、二重根では残差が100桁小さくても座標は50桁程度しか決まらない（S1.5）。そこで接する条件などを符号付きの残差に直している。接する条件を含む12問で、同じ候補を、この書き換えありとなしで精密化した。なしでは7問が8〜48桁で止まり、ありでは同じ候補が119〜502桁に届いた。4問は差がなく、1問はなしの方が12桁多かった（S2.7）。同定は証明ではなく、高精度で一致を確かめ、公式の答えとの一致で検算したという意味である。

## 4 達成したこと

各問題に180秒と1コアを与え、seedを変えて3回ずつ解いた（表2）。開発用の323問は、AIME・HMMT・日本数学オリンピック予選（2000〜2025年）から私が選んだ。入力はAIが書いたので、解き方が入り込んでいないかを正解を見ずに全問調べ、問題文をそのまま書き移したと確認できた246問を「直接入力」と呼ぶ。答えが複数ある問題は、値の集合が一致したときだけ正解とした。時間の中央値は失敗も含む。

表2　問題の種類ごとの成績（各3回）

|---|---|---|---|
| 開発用 | 323 | 953/969 | 5.2秒 |

GMBの論文の36問で、両方の出力を同じ独立の検査（条件のずれ 10⁻⁶ 以内）にかけると、図を作れた回数は solver 100/108、GMB 30/108 だった。GMB がモデルを返した回数は95/108（88%）で、論文の93.52%（モデルを1つ作れた割合）はこの定義に当たる。通らなかった GMB の図は、ほぼすべて等式のずれ（半数以上は 10⁻³〜10⁻²）によるもので、差は主に成功の定義と許容誤差から来ている（S2.8）。図を多項式にして msolve [13] で解く方法は、解けた201問ではsolverよりはるかに速かった（中央値0.03秒）が、残る122問は解けず、solverはそのほぼすべてを解いた（S2.8）。

## 5 solverにとっての難しさ

### 5.1 値だけを決めればよい

msolveが解けなかった122問のうち68問は、解が有限個でないと判定された（65問は複素数の範囲で正次元、3問は自由な変数が残る）。solverに必要なのは τ の値だけである。τ が連続で値が有限個なら、τ は図の集合のひとつながりの部分（連結成分）の上で一定になる。各成分から図を1つ見つければ値は決まる。例えば HMMT 2013年2月 幾何2番では、台形の高さが決まらないが、求める長さの2乗はどの高さでも24になる。このような恒等式 s^N P(τ) = Σ C_i F_i（F_i は条件の多項式）を作り、どの図でも P(τ) = 0 となることを63問中24問で確かめた（S1.4）。

### 5.2 費用は「評価1回の費用」と「当たるまでの評価回数」に分かれる

t/p を、評価1回の費用 c と、1回の局所探索の評価回数 n（微分の計算に使う評価も含む）に分けると

  t/p = c × (n / p)　…(1)

となる。探索変数のある292問で、出発点200個から c、n、p を測った（S2.3）。作図はどの評価でも順に計算されるので、c は作図の数とともに増えるはずである。一方、n と p が作図の数によらないかは、理論からは言えない。作図は地形も変えうるからである。

結果は次のとおりだった。探索に残した変数の数 d の影響を除くと、作図の数は n とも p とも関係せず（偏順位相関 0.03、0.06）、c とだけ関係した（0.58）。逆に d は、作図の数の影響を除いても n と強く関係した（0.78）。問題ごとの c の違いは上下5%を除いて約4.5倍の幅しかないが、n/p は約3,300倍の幅があった。問題ごとの t/p の違いを対数で測ると、その87%（95%区間 84〜91%）は n/p から、3%は c から来ていた。p が0の問題の扱いを変えても、87〜91%だった。この分解は、LM法の局所探索という物差しでの結果で、NOMAD を含むsolver全体の時間の分解ではない。

### 5.3 正しい図を変えない書き換えが、難しさを変える

作図 y = h(u) で計算していた点を自由な点 y に戻し、その作図を表す等式を加えても、正しい図は変わらない。人間に示す問題文も変わらない。15問で作図を k か所（k = 0〜3）書き換えると、1回の局所探索が当たる確率の中央値は 0.96、0.77、0.40、0.38 と下がり、1か所ごとに当たるオッズが約0.49倍になった。完成したsolverでは、正解は45回中42回から41回でほぼ変わらず、時間が問題ごとの比の中央値で3.43倍になった（時間切れは180秒として数えた。S2.6）。

なぜか。y を自由な点に戻した系（以下、自由点の系）と、y を「作図からのずれ」 z = y − h(u) で表した系（ずれの系）を比べる。どちらも変数の数は同じである。ずれの系では、点は毎回作図で正確に作り直され、そこに z が足される。書き換えた点が元の等式に現れない場合、z = 0 から始めたLM法の反復は、元の系の反復と完全に一致する（S1.3、命題1）。つまり変数が増えても、座標の取り方しだいでは何も変わらない。

では、自由点の系では何が起きているのか。LM法の減衰を外したニュートン法で、AIME 2014 II-14（k = 3、自由点の系で当たる確率1.00→0.03）を追跡した（S2.5）。最初の一歩で u を動かす向きは、元の系と完全に同じだった。書き換えた点が元の等式に現れないとき、ニュートン法の u の向きは y によらないことが式からも言える。違ったのは一歩の長さだった。出発点が解から遠いと、提案される一歩は大きい。元の系は、その一歩を 1/128 に縮めて受け入れ、7回で収束した。自由点の系では、同じ一歩で作図の式（非線形）の残差が増えるため、1/8192 まで縮めないと受け入れられず、200回の上限までに収束しなかった。実際のLM法でも、自由点の系の失敗58回はすべて評価の上限で止まっていた。作図で計算する系は点を毎回正確に作り直すので、この制限がない。

この説明は、作図の式の非線形性が一歩の長さを制限するというものである。したがって、自由点の系の不利は出発点と解の距離とともに増え、解の近くでは消えるはずである。実行前にこの予測を固定し、自由点の系が0.2以上不利だった10問で、出発点を正しい解の周りの幅 r の箱から選んで確かめた（r = 箱の幅の2%〜100%、各30個）。予測どおり、r = 2% では10問中8問で自由点の系は元の系とほぼ同じ（差0.10以内）で、中央値はどちらも1.00だった。r を広げると、自由点の系の不利の中央値は 0、0.07、0.30、0.53 と増えた。ずれの系の不利は、どの r でも中央値0〜0.03だった（図3、S2.5）。解の近くでどの系も収束すること自体は、局所収束の定理から当然である。この実験が示したのは、不利が距離とともに増えること、そして同じ距離でもずれの系にはそれがほとんど出ないことである。

![図3](figures/fig3_near_start.png)

この説明に至る前に、外れた予測がある。私は最初、出発点での u の列の膨らみ（作図の微分が加わる分）で低下を予測できると考え、新しい43問で実行前に予測を固定したが、膨らみ3倍以上の6問で当てたのは3問だった（S2.5）。一歩の長さは、出発点での量ではなく解までの道のりで決まるからである。同じ43問で、命題1の予測は当たり外れの判定が600回中600回一致した（残差まで含めた厳密な一致は15問中12問。残りは収束しなかった出発点での丸め誤差の差）。

難しさを生んでいたのは、変数の数ではなかった。点を式で持つか、作図で計算するかという座標の取り方だった。作図で点を消すという設計（3.2節）が効く理由も、これで説明できる。

## 6 人間の難しさとどう違うか

### 6.1 solverの難しさは、問題文だけでは決まらない

5.3節の書き換えでは、人間に示す問題文は変えず、solverの入力だけを変えた。それでも当たる確率は、座標の取り方だけで1.00から0.03まで変わった。逆に、人間には難しい問題でも、入力の作図だけで図が決まればsolverは探索をしない。HMMT 2019年2月 幾何10番は、正方形を3段重ねた図が複雑で、面積の求め方がすぐには見えないため、人間には難しい（HMMTの79問中、難しい方から上位9%）。しかし作図だけで図が決まる（d = 0）ので、探索も精密化もなく1.5秒で解けた。

人間が補助線や定理で見つけなければならない関係が、solverの入力には作図として既に入っていることもある。入力を書くときにAIが人間の推論（中心の位置などを手で求めたもの）を入れていた5問で、その推論を外して原文の条件だけに戻した（S2.10）。探索変数が5〜6個増えた2問では、時間が8倍と12倍になった。一方、外した形が小さな多項式の系になった1問は、代数的前処理で解けて逆に速くなった。何を与えると楽になるかは、人間の見通しではなく、solverの仕組みが決める。

### 6.2 両者が重なる部分

実際の正答率から推定された人間の難度（Easy2Hard [12]）と、5.2節の c、n/p を、両方がそろう109問で比べた（図2）。人間の難度は、両大会で c と正の関係があった（n/p の影響を除いた偏順位相関 AIME 0.35、HMMT 0.45）。c は入力の大きさ（作図の数、入力の長さ）とともに増える量である。n/p との関係は、c の影響を除くと 0.26、0.09 で、区間が0をまたいだ。2つの因子への効き方が人間とsolverで違うかは、109問では確定できなかった（S2.3）。

## 7 限界

solverは、すべての答えを見つけたことも、答えの式の正しさも、数学的には保証しない。323問は開発に使った問題で、開発外の成績は2026年の20問と自動生成の88問で示した。c、n、p は、LM法の局所探索を独立な出発点から測った量で、NOMADを含むsolver全体の値ではない。5.3節の書き換えの実験も、局所探索での結果である。人間の難度との比較は109問で、入力はAIが書いたので、作図の数は書き方にも左右される。

## 8 結論

作図で変数を消し、安い探索と補いを重ね、数百桁の精密化と同定で答えを確かめるsolverを作り、コンテストの求値問題の大部分を数秒で解いた。各仕組みの役割は、通常の実行の記録から外したときに影響を受ける問題を予想でき、外す実験と合った。局所探索の費用は「評価1回の費用」と「当たるまでの評価回数」に分かれ、違いの大部分は後者が占めた。人間の難度は前者と関係した。本solverの難しさは、問題文だけでは決まらない。同じ幾何の条件でも、何を作図で計算し、残りをどの座標で探すかで局所探索の結果が変わる。点を式で持つと、遠くからの一歩で作図の式が崩れて一歩が切り詰められる。作図で計算すれば、点は毎回正確に作り直される。【本人確認：次の一手。】
