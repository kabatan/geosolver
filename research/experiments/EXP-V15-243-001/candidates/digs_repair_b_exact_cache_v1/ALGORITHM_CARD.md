# Wave3 — confirmed exact-identity cache × DiGS Repair B

## Hypothesis

The proof-bearing confirmed-identity cache safely avoids repeated exact replay
for an algebraic target that has already been admitted.  When that makes the
complete baseline authority finish early, Repair B observes the saving only as
real remaining wall time and can spend it on an independent DiGS tail.  No
synthetic time credit or shortened baseline deadline is introduced.

The supplied cache-lane formal-180 screen24 evidence reports identical control
and candidate case sets, HP attempts `594 -> 706`, and 454 cache hits.  This
combination lane did not inspect scorer/truth/case outcomes or rerun that panel.

## Candidate-private connection

The install order is fixed:

1. Repair B loads frozen raw champion-v2, preserve-binding, and exact_outer
   `CONFIRM_ALL_AUTHORITIES` exactly once.
2. The cache captures that exact callable and its ordinary callable exactly
   once.  It rejects a second installation or any callable drift.
3. Repair B installs its post-final atomic RESULT seam.

The cache worker and policy from the independently tested worktree are copied
byte-for-byte and hash-bound as closure references.  The small connection code
repeats their mechanism directly because importing the reference worker would
load a second exact_outer object graph.

On a miss, the ordinary attempt is charged once and the same object is passed
to exact_outer for confirmation.  Only an `authority_pass=true` exact result
populates the cache.  Therefore first and failed confirmations cannot be
skipped.  A hit emits no descriptor and has `authority_pass=false`; baseline
exact descriptor mapping remains the same as the no-cache control mapping.

After baseline finalization, Repair B freezes descriptor and HP-attempt
prefixes.  Only true callback and wall surplus can run DiGS.  A side identity
still passes through the same cache-decorated exact_outer authority.  Novel
proof-bearing attempts/descriptors append after the immutable baseline prefix;
duplicates, deadline censoring, malformed ledgers, and exceptions retain the
baseline RESULT.

There is no problem, family, truth, target-count, or previous-outcome routing,
and no shared portfolio framework.
