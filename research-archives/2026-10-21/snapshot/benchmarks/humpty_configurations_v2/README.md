# Humpty周辺の求値問題・改訂版 v2

前版は配置の多様性と求値の非自明性を優先し、幾何的性質を使った後にも大きな座標計算が残る問題を含めていた。この版では、使う幾何的関係から逆に与条件と問いを設計し直す。

`review.html` は具体的な問題、使う性質と解法、着想後の計算、前版との差分、実在例を一件ずつ読むための画面。`catalogue.md` は同じ内容の一覧。前版（v1）のファイルとブラウザ評価は2026-09-20の整理で廃止し、当時の記録はgit履歴を参照する。選定メタデータは `authoring/v1_metadata.json` としてv2へ取り込み済みで、v1ツリーへの依存はない。

## 採用の考え方

- 三辺を一律に入力する方針をやめ、構成中の長さ・角度・和なども与条件として使う。これはユーザー了承済み。
- 補助点・共円性・接線・中点・相似などを捉えることで、短い求値へ帰着するものを主学習候補にする。
- 答えだけが小さいことでは採用しない。幾何的関係を使った後の演算を各問に明記する。
- 隠したい等式をそのまま与えたり、等しい一方の量を与えて他方を聞くだけの問いは、原則として性質の確認用に分ける。
- 幾何的性質そのものの再証明が長くても、その性質を獲得する研究上の意味と求値を簡単にする実益があれば候補に残す。「解法」では使用する関係とその後の推論を示し、関係の根拠は検証欄へ分ける。
- 複雑な配置に無関係な小問を付けただけのものや、与条件だけで肝心の性質を使わず答えが出るものは避ける。残る懸念は各問の注意欄に記す。
- 図形全体は一意に定まらなくてもよい。ただし与条件を満たす非退化な例が存在し、全ての許容配置で答えを強制する推論が必要。

主学習候補は、着想の発見や学習効果まで実証済みという意味ではない。数値だけを学習させるとこの短い解法を獲得するかどうかが、後の実験の問いである。

今回の配置・与条件の選定には、研究者が知っている幾何的性質を使っている。「解法や性質をモデルへ直接教えない」ことと、「人間が性質を知らずに題材選定までできる」ことは区別する。この改訂集合だけで後者まで実証したとは扱わない。

## 区分と件数

最新の件数は `validation_report.json` とレビュー画面に表示する。全ての v1 ID に `main`（主学習候補）、`probe`（性質の確認用）、`defer`（再設計待ち）、`holdout`（評価留保）、`exclude`（不採用）の判断を付ける。数を満たすために不適切な問いを残さない。

カード数、前版での構造群数、数値例数を区別する。同じ構造の数値変更・求める量の変更を新しい構造として数えない。Humptyと直接つながるDumpty・派生三角形は含むが、SDの配置は混ぜない。Balkan SL 2019 G4、orthicに関する評価、および近接する H10/H11 は学習へ移さない。

## 学習用と研究者用

- `training_problems.jsonl`：主学習候補の具体的な問題と正解だけ。`problem` をモデル入力、`answer_exact` を照合用ラベルとして別々に扱う。ファイル全体をそのままプロンプトへ入れない。
- `probe_problems.jsonl`：性質の確認用。主学習候補の件数には含めない。
- `revisions.json`：前版との差分、解法、存在例、出典を含む研究者専用データ。学習・評価モデルの入力にしない。
- `authoring/*_revision.json`：改訂の編集元。`build_dataset.py` で上記ファイルと画面を生成する。
- `review.csv`：外部で評価するための空欄付き台帳。

ここで作った具体例の正解は数学的導出と独立計算で検査する。repoのsolverで生成済みの大規模コーパスではない。研究本番のラベル生成経路は引き続きsolverとし、人間が書いた解法は渡さない。

## 検証と次の段階

`authoring/verify_*_revision.py` が元の作図から与条件と答えを確認する。厳密式による解法・関係の確認と、数値的な実在例の再現は区別して記録する。数値例一つだけを一般命題の証明とは扱わない。

DA13・DA16・DA17、および確認用のDB09は、出典に記載された一般命題を使うが、その証明の独立確認は今回完了していない。これらにも具体的な数値例と短い求値の導出を付け、画面で確認範囲を明示する。ここでは候補から削除せず、数学的レビューを受ける対象として残す。正式な学習集合へ固定する前に、この根拠も確認する。

この段階で固定するのは、具体的な例と、広げるための与条件・枝・問いの設計である。`parameter_family_ja` は数値展開の方針であり、そこに記載した全パラメータが検証済みという意味ではない。量産時には定義域・退化・一意性・答えの簡潔さを改めてチェックする。

ユーザーによる数学的価値の評価後、構造単位で学習・評価を分離し、複数の非相似な数値例を生成する。指定した内部量から原構成を復元できる生成器、solver入力への変換、solverの正解照合を通してから学習に使う。現在の少数の具体例だけで汎化実験が十分になるとは主張しない。

## 再生成

リポジトリルートから `python3 benchmarks/humpty_configurations_v2/build_dataset.py` を実行する。検証スクリプトはSymPyを使うためリポジトリの `.venv/bin/python` を使う。

`.venv/bin/python benchmarks/humpty_configurations_v2/verify_dataset.py` は各作図検証を実行し、学習用出力との整合性も検査して `verification_report.json` を保存する。検証したデータとスクリプトのハッシュを記録する。

レビュー画面の評価は `humpty-config-review-v2:<データのハッシュ>` に保存する。v1の評価とは別であり、JSON出力にはデータのハッシュを付ける。変更された問題へ以前の評価を誤適用しないよう、異なるハッシュの評価は自動で取り込まない。

## 数値変種の修復（2026-09-22）

`authoring/gen_variants.py` は `variant_templates.json` の承認済み文章に数値だけを差し込む。
`training_variants.jsonl`（148件）と `eval_variants.jsonl`（37件）を再検証した。
H07/H08の数値とDA05の実在例も不等辺条件に合わせて修正済み。
過去の実験とは問題本文・ラベルのhashが異なるため、旧回答を新しい問題の評価へ流用しない。

`variant_validation.json` に修復履歴と検証範囲を保存する。`augmentation` は
original / shape / similarityを区別し、新規生成で相似変種を使う場合は
`--allow-similarity` を明示する。生成に失敗しても相似変種へ自動退避しない。
shapeは座標構成のパラメータを変えたという分類で、全例の相互非相似性まで保証しない。
現在も相似変種が多く、研究本番に十分な多様性を確保できたとは扱わない。
