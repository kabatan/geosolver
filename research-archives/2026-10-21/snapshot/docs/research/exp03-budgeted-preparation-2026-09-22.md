## 何を調べるか

数値の答えだけを報酬にした学習によって、教えていない幾何の証明・補助構成に改善が生じるかを見る。更新が正常に動くこと、数値問題への適応、証明への転移は別々に判断する。

- 学習：承認済み37配置・148問、各4回答、1周・最大37ラウンド。代表例37、shape変種27、相似変種84であり、148種類の独立した幾何的着想ではない。
- 数値dev：37問×2回答をbase/trainedの両方で取得する。同配置の数値への適応を測る補助指標。
- 証明：別配置EV02・DU01・OB01と、同配置AP01・N01・N02、それぞれ4回答を両モデルで取得する。計48答案。
- 初回のヒント条件、全checkpoint評価、無関係学習の対照実験は含めない。最初の試行で次の投資を判断するため。

現在の数値ラベルは構成計算による検証済みラベルで、repoのsolverが自動生成したコーパスではない。正の結果が出ても、solverによるデータ生成から新理論を得るという全体の構想を立証したことにはならない。また、これらの証明課題は既に開発中に見ているため、未使用の最終テストではなく探索的評価である。

## 採用経路と較正

Qwen3-4Bの固定snapshotを使い、base・KV・活性化はFP16、学習するLoRAのmaster weightとAdam状態はFP32。LoRA r32/alpha64、dropout 0。生成側はvLLMの未マージLoRAを使用する。全面FP32モデルの保存・マージ往復を各ラウンドで行わない。

温度0.6、top-p 0.95、top-k 20、thinkingあり。回答上限32,512、文脈上限32,768を維持する。長い思考を短く切って見かけの速度を上げる変更はしない。同時生成は最大4系列。

1ラウンドは4問×4回答を新規生成し、平均報酬を引いたadvantageによって1回更新する。打ち切り回答の学習tokenをマスクし、全回答の有効token数で正規化する。全一様報酬など有効なadvantageがない場合はoptimizerを進めない。KLは0。これはtoken正規化を使うGRPOであり、動的サンプリング等を含む完全なDAPO実装ではない。

生成側の温度・top-k/top-p処理後のlogprobを記録し、学習側との差には上限2のtoken単位importance weightを用いる。これは有界の近似で、丸め差や打ち切られた分布のsupportの問題を完全に取り除くものではない。各有効答案でrelative ESS ≥ 0.90、上限に達した割合 ≤ 1%を要求し、逸脱すれば更新を止める。

較正中の不合格も保存した。BF16・学習率1e-6の短い固定回答試験は目的関数が改善せず不採用。FP16・1e-6は短い回答では改善したが、通常の長文16回答による更新では目的関数が約7.5e-7下がり、長文の改善条件を満たさなかった。そこで同じ学習用較正データで5e-6を検査した。dev・証明の成績を見て学習率を選んでいない。

FP16・5e-6の長文更新では目的関数が0.09106633→0.09113405へ改善し、パラメータ差L2は0.02838、更新と更新後の測定は約99秒だった。生成側との補正のrelative ESSは約0.9998以上、weightの上限への到達は0%。保存前後の全有効答案のlogprob、Adam状態、スケーラ状態は一致した。optimizer状態を読み込んだ32,768 token逆伝播は約18.00 GiBで完了した。

較正の数値正答は11/16だったが、これは易しい問題を含む技術試験であり、性能評価に流用しない。少なくともDA05の正答1本には、不等辺という条件に反する二等辺配置を勝手に置く誤りがあった。数値報酬はその答案にも入る。この事実を記録し、証明への転移は別途厳密に採点する。

## 実行順と停止規則

1. 固定された問題文・ラベル・コード・環境・モデルhashを検査する。
2. FP16経路でbaseの証明・数値評価を取得する。exp01の別経路の回答を今回の比較対象に代用しない。
3. 元のbaseから最初の5ラウンドを学習する。準備で得たadapterは本学習の初期値に使用しない。
4. 生成長・生成速度・更新時間を使い、残り学習と学習後評価の費用を再計算する。以後は各ラウンドで再計算する。
5. 学習後評価の予算を確保できない場合、または最初の20問で混合報酬群が4群未満の場合は、そこで停止する。成績を見てcheckpointを選ばず、最後に完了した更新を固定して評価する。
6. 全37ラウンドまたは規定停止の後、同じ評価問題・生成条件・seedで学習後評価を行い、数値比較とモデル名を伏せた証明採点用データを出力する。

各GPU workerは共通の`budget.json`に記録される。モデル読込・生成・更新・終了処理と、失敗した試行も計上時間に含める。準備は累積2時間、全体は累積40時間を超えない実行期限を設定する。通常の中断はworkerの専用process groupを停止し、完了したroundと既生成の問題群から再開する。OS強制終了などで未完了記録が残った場合は、勝手に時間をゼロにせず、プロセスと記録の確認を要求する。

OOM・非有限勾配・policy不一致など、費用以外の失敗では自動で条件を変えたり再試行したりしない。原因を確認してから再開する。課金上限に達した場合の自動延長も行わない。

## 結果の採点と投資判断

証明は完全な一般的論証を正解とし、座標解法も同じく正解とする。Humpty/Dumptyの名称だけで配置に固有の核心を引用したものは完全証明に数えない。完全証明、局所的誤り、核心の欠落、数学的誤り、特殊配置のみ、最終答案なしを区別し、有効な補助構成とその論証も記録する。

48答案をモデル名を伏せて採点し、全採点を保存してから対応表を開く。別配置3題と同配置3題を分け、同じ問題からの4回答を独立した4問題とは扱わない。小さな正答率差の有意性や、転移効果の上限をこの試行だけで強く主張しない。

別配置で完全証明や核心の論証の改善が複数回答に再現した場合に、別seedと適切な対照学習への追加投資を検討する。数値だけの改善なら数値への適応と報告する。信号が乏しければ、この予算内では追加投資を支持する証拠が得られなかったと報告し、研究仮説全体の否定とはしない。

## 準備完了と実測費用

**準備完了。本学習・正式な前後評価は未開始。** 54件のCPUテスト、実際の長文更新、生成側への更新の反映、保存・復元、完了roundを再実行しない再開、32k逆伝播の確認を通過した。設定と入力を実際のCLIで固定し、数値74回答・証明24回答／モデルのdry-runも確認した。GPUの準備workerは全て終了している。

| 測定 | 実測 |
|---|---:|
| base、4回答同時、計16回答 | 267.3 token/秒 |
| adapter、4回答同時 | 188.9 token/秒 |
| adapter、2回答同時 | 117.2 token/秒 |
| 16回答中10回答を使う実更新＋更新後の測定 | 99.2秒 |
| 32,768 token、optimizer状態ありの逆伝播 | 18.82秒・18.00 GiB |
| 今回の準備全体（失敗試行を含む） | **0.685 GPU時間＝約41分** |

生成長を平均22,000 tokenとして、実測の遅い側を採り、計画値に15%の余裕を加える。更新は、32k逆伝播のtoken当たり時間から**全16回答が有効な更新対象**になる場合を見積もり、各回答に512 tokenのprompt分も見込み、通常更新で測った逆伝播以外の24秒も加える。30秒単位で切り上げて**240秒／ラウンド**とした。さらに生成・更新のプロセス起動等に60秒／ラウンドを置く。

300秒／更新という当初の値は未実測の仮置きだった。これを変更した根拠は32k容量試験と通常更新の実測であり、240秒が厳密な所要時間の上限だという意味ではない。実行中にも観測値で再見積りする。

| 計上対象 | 計画値 |
|---|---:|
| 準備（実績） | 0.69時間 |
| 学習37ラウンド（生成・更新・起動等、15%余裕を含む） | 25.58時間 |
| 前後の数値・証明評価（15%余裕を含む） | 10.74時間 |
| 合計 | **約37.0時間** |

学習後評価には、全98回答が上限32,512 tokenに達する場合を同じ実測速度で見積もり、さらに15%の余裕を置いて**8時間を確保**する。この留保分を平均長による後評価見積りと置き換えた合計は**39.63時間**。総上限は40時間のままで、準備後の残りは39.31時間。

24時間という目標には達していない。40時間の上限には収まる計画だが、速度は小標本の測定なので、37ラウンドと全評価の完了を保証する見積りではない。5ラウンド時点と以後各ラウンドの費用確認、および実行期限による停止を併用する。

追加のCUDA graph候補は5分の試行枠内に生成が完了せず、時限制御で終了した。速度改善の有無を確定できる完了データがなく、不採用とした。この試行も上記41分に含む。採用した経路は、測定済みのFP16・未マージLoRA・eager実行である。

## 開始・再開

設定は [`qwen/configs/exp03_budgeted.json`](../../qwen/configs/exp03_budgeted.json)。repoルートで実行する。

```bash
# 固定済み設定の検査のみ。GPUを使った本実験を開始しない。
qwen/.runtime/vllm-venv/bin/python -m qwen.study_run

# 本実験を開始、または同じ条件で再開。
qwen/.runtime/vllm-venv/bin/python -m qwen.study_run --run
```

出力先は `qwen/.runtime/exp03_budgeted/study/`、準備・学習・評価で共用する時間台帳は `qwen/.runtime/exp03_budgeted/budget.json`。`study/PREPARED.json` がconfig・readiness・入力manifestのhashを固定している。

完了後は `numeric_summary.json` と `proof_review/blinded.jsonl` を確認する。後者の全48答案を採点し、`grades.jsonl` を保存してから以下を実行する。

```bash
.venv/bin/python -m qwen.grpo_compare freeze-unblind \
  --output qwen/.runtime/exp03_budgeted/study/proof_review
```
