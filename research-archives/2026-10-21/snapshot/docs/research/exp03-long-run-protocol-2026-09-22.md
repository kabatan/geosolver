# 修復後の長時間実験：固定プロトコル

**費用判断を修正したため、この全量計画は次の実行の推奨から外した。** 以下は以前の案を記録として残すもの。[費用判断の修正](exp03-cost-revision-2026-09-22.md)を優先する。技術較正の通過だけを理由に5ラウンド・37ラウンドを開始しない。

目的は、**数値の正誤だけによる学習で、解法を教えていない証明課題の成績が変わるか**を調べること。数値訓練報酬の上昇や、技術的較正の4配置への適応を転移と呼ばない。

実行設定は `qwen/configs/exp03_pilot.json`。技術的較正の通過記録がない状態ではrunnerが本学習を拒否する。これは次の実験の準備であり、37ラウンドの本学習を今回すでに実行したという意味ではない。

## 固定する学習条件

- 固定revisionのQwen3-4Bから新しいLoRAを開始。exp01や人工的な短答較正のadapterを引き継がない。
- ユーザー承認済み37配置・修復後148数値問を1回ずつ使用。順序のseedは20260923。4問×4生成を1ラウンドとし、計37ラウンド。
- LoRA r32/alpha64、7種類の線形層、dropout 0。AdamW、学習率1e−6、weight decay 0、epsilon 1e−8、勾配norm上限1。
- 群平均を引いたadvantage。標準偏差による再尺度化なし。KL 0、clipping幅0.2。
- 有効な回答トークン全体の数で正規化し、micro-batchの損失を加算。打ち切り回答は全トークンをmaskする。promptトークンに損失を与えない。
- 全回答が一様報酬で有効な非ゼロadvantageがないラウンドは、optimizerを進めず記録してスキップする。したがって37ラウンド＝必ず37optimizer更新ではない。ゼロ勾配でAdamのmomentumだけを進める旧実装とは異なる。
- 学習・生成とも検証済みのFP32経路。生成モデルは毎回、不変のbaseと当該adapterから作り直して同期する。learnerにmerge/unmergeを繰り返さない。
- 学習時の注意計算はKV headを明示的に展開し、FP32対応の省メモリkernelを指定する。暗黙のGQAによる巨大な注意行列へのfallbackを許さない。
- temperature 0.6、top_p 0.95、top_k 20、thinking有効。回答上限は `min(32512, 32768−prompt長)`。短い思考を強制する指示は加えない。
- 1 GPU、生成と更新を別プロセスで行う。世代ごとにtoken列、問題本文・変種・正解・採点器・adapterのhash、seed、報酬、advantage、終了理由を保存。更新した回答にはold logprob、勾配norm、パラメータ差、時間を保存。

これはDAPOのtoken目的関数を用いる小規模GRPOであり、dynamic samplingなどを含むDAPO全体の再現とは呼ばない。生成にはtop-k/top-pによる切り詰めがあるため、厳密な未切り詰めpolicyからのon-policy samplingではない。engine間の生logprobの差も測定し、無視できない差をそのまま隠して学習しない。

## データの位置付け

この148問は37の独立した配置候補であり、148種類の幾何的着想ではない。内訳は代表例37・shape変種27・相似変種84。devは37問中28問が相似変種である。従ってdev正答率は主に同配置の数値への適応を測る。

現在のラベルは構成計算・独立な式との照合によるもので、repoのsolverを通して生成した本番コーパスではない。DA13/DA16/DA17には一般命題の独立証明の確認が未完という既存の注記もある。この実験の主張は「数値だけの監督による転移の予備検証」まで。**solverが人間の知らない理論を発見させた、という主張にはしない。** 肯定的な兆候の後にsolver出力と照合したコーパスへ進む。

問題文・数値・解法ヒント・証明課題を、結果を見て途中変更しない。入力・評価問題・コード・モデル・依存のhashとコピーを実験開始時に保存する。変更があれば新しい実験として扱う。

## 進め方と停止基準

まず同じ固定設定の最初の5ラウンドで停止する。これは性能の有意差判定ではなく、長文の実負荷、報酬混在、更新量、答案品質を確認する区間である。

```bash
qwen/.runtime/vllm-venv/bin/python -m qwen.grpo_run \
  --config qwen/configs/exp03_pilot.json \
  --output qwen/.runtime/exp03_pilot --through-round 5
```

以下は停止して原因調査する条件であり、学習率や報酬をその場で都合よく変更する条件ではない。

- NaN/Inf、OOM、入力hash不一致、採点不能な正解ラベル、checkpoint破損。
- 5ラウンドとも有効な報酬混在がない、または有効なadvantageがあるのに更新量が0。
- 保存・再読込・生成への同期で、FP32参照との変化の一致が較正の許容範囲を外れる。
- 数値報酬の監査で、問題の条件違反や解析器の誤採点が見つかる。
- 実測時間から48時間の学習上限内に予定ラウンドを完了できない見込み。思考上限を黙って短縮しない。

正しい数値に誤った議論で到達した答案は別に記録する。単発の誤推論を理由に、途中から人間の幾何的解法を報酬へ追加しない。答案全体の正しさと数値報酬は別の測定である。

通過した場合は、**同じ出力先・同じconfig**で続ける。完了済みラウンドの再生成・再更新は行わず、adapterとoptimizerを復元する。

```bash
qwen/.runtime/vllm-venv/bin/python -m qwen.grpo_run \
  --config qwen/configs/exp03_pilot.json \
  --output qwen/.runtime/exp03_pilot
```

学習上限48時間は再起動でリセットしない。途中失敗の生成済み群は保持する。停止後にコード・データを修正した場合、同じ実験へ黙って継ぎ足さない。

## 所要時間の見積り

修復後の4題16回答の生成実測は249,317 token / 2,529秒＝98.6 token/秒、平均回答長15,582 tokenだった。
旧BF16/fp8の約1,000 token/秒を、このFP32の実験の予算見積りに使わない。

| 区間 | 生成量 | 今回と同じ平均長での生成時間 |
|---|---:|---:|
| 最初の5ラウンド | 80回答 | 約3.5時間 |
| 訓練37ラウンド全体 | 592回答 | 約26時間 |
| 数値dev、両モデル | 592回答 | 約26時間 |
| 証明6題×8回答＋ヒント4題×4回答、両モデル | 128回答 | 約5.6時間 |

この表は生成時間だけの外挿であり、訓練更新、重み同期、評価答案の採点を加える必要がある。
平均長が22,000 tokenなら生成部分は約1.4倍になる。4題の平均は全148問の性能保証ではない。
初回の訓練・評価を合わせて**約3〜4日＋採点**を見込み、まず5ラウンドの実測で更新する。
計算を速めるために丸め誤差の大きかった経路へ戻す場合は、別の較正が必要である。
現時点では、時間をかければ転移が得られるという保証はない。段階実行により、経路不良や信号不足が分かった時点で残りの計算を止める。

## 評価を三つに分ける

| 測定 | 固定問題 | 生成数/問題/モデル | 解釈 |
|---|---|---:|---|
| 同配置・数値 | 修復後dev 37問 | 8 | 数値への適応。独立な幾何37分野の汎化とはしない |
| 別配置・関係の証明 | EV02・DU01・OB01 | 8 | 研究上の主要な転移指標 |
| 同配置・未提示の証明 | AP01・N01・N02 | 8 | 数値問題から証明への転移 |
| 補助点ヒントあり | 対応4問 | 4 | 発見と性質利用の切り分け。主評価と混ぜない |

新しいbase評価を、trainedと同じFP32経路・同じ問題・同じ予算で取り直す。旧exp01のBF16 merged評価をbaselineとして流用しない。初回の正式比較はbaseと37ラウンド後だけとし、中間checkpointの成績を見て都合のよいものを最終結果に選ばない。

これらの証明課題はexp01で既に観察した開発用の評価集合であり、初見の独立テスト集合ではない。
今回結果を見て問題や採点基準を変えないことと、研究全体として未使用の評価であることは区別する。
肯定的な結果を一般化する段階では、未使用の証明課題を追加する。

```bash
# --adapterを省略するとbase。学習開始時に凍結した評価入力を使う。
qwen/.runtime/vllm-venv/bin/python -m qwen.grpo_evaluate \
  --experiment qwen/.runtime/exp03_pilot --suite proof --samples 8 \
  --output qwen/.runtime/exp03_pilot/eval/base_proof

# adapterの実パスは実験のCOMPLETE.jsonに記録される。
# 同じコマンドに --adapter <そのパス> を加え、別outputでtrainedを評価する。
# suite numericは8生成、suite proof_hintは4生成として別々に実行する。
```

完全証明だけを主指標で正解にする。座標・ベクトル等も同じ正解。Humpty/Dumptyという名前だけで核心を済ませた答案は不可。有効な補助点の導入・性質を根拠付きで使ったか・論証の欠落・局所誤りは別欄に記録する。

モデル名を伏せて全答案を採点し、判定・理由・境界例をhashで固定してから対応表を開く。可能ならユーザー自身にも境界例と改善例を確認してもらう。途中で見た答案がある採点者は、その限界を記す。

`qwen.grpo_compare proof --base <baseのresponses.jsonl> --trained <trainedのresponses.jsonl> --output <採点先>`
でモデル名を伏せた `blinded.jsonl` と採点基準を作る。`identity_key.json` は採点完了まで開かない。
全答案について `grades.jsonl` にcategory・method・auxiliary_relation_proved・evidenceを記入した後、
`qwen.grpo_compare freeze-unblind --output <採点先>` で判定を固定し集計する。
`numeric` モードは入力・変種・label・seed・生成上限の一致を確認し、配置単位で数値成績を比較する。

9月末までの初回の成果は、この1 seedの結果と、改善例・失敗例の数学的な検討を揃えることとする。
複数seed・対照学習・広い新規問題群までを、この1回だけで完了したと扱わない。
9/22の較正後、5ラウンドの確認、37ラウンドの完了、固定評価と盲検採点の順で進め、
実測から9月末に間に合わない場合は、追加学習の量よりも定義済みの前後評価を優先する。
10/27のレポートには、技術的に直った点と研究仮説を支持した／しなかった点を分けて記す。

## 結果の判断

- 数値だけ改善：数値適応の結果。証明への転移は未確認。
- 同配置の証明だけ改善：学習済み配置での能力変化。別問題の補助構成への転移とは分ける。
- 別配置の完全証明が複数の回答で再現：次のseedと、計算量・難度を合わせた無関係な数値学習の対照群を行う根拠になる。
- 変化なし：修復後の設定・学習量・評価課題で変化を検出できなかった。数値成績すら改善しない場合、まず学習信号・学習量の問題と転移の問題を分ける。

回答8本は同じ問題からの反復であり、独立した8問ではない。数値は配置単位の差・区間、証明は問題別の完答数と答案内容を中心に報告する。別配置の主評価は3問しかないので、幾何全体に対する有意な一般化や、小さい効果の不在を断定しない。正の兆候も負の結果も、追加予算の判断に使える形で残す。
