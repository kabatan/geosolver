# Solverを使う次の経路の実現性監査

2026-09-25。CPUのみ。既存solver、学習データ、採点、モデルは変更していない。

**結論：対象を限定した「関係候補の列挙→反例による除去→一般有理式の検証」は既存の基本作図と短い追加コードで実行できた。ただし、これをモデルの知識獲得や別配置への転移の成功と数えてはいけない。** 全37配置の証明器、新しい学習アルゴリズム、大規模RLが容易に作れるという証拠ではない。

## 既存実装をそのまま使える部分

- `geosolver.geometry`のPoint、Line、Midpoint、Orthocenter、FootOfPerpendicular。SymPy backendは座標を記号のまま扱え、垂心は垂線の連立一次式、垂足は直線への射影式で構成する。
- 数値問題の求解、非退化性のguard、枝の記録、結果の高精度照合の基盤はある。しかしREADMEが明記する通り、solverの`completeness`は常に`unknown`である。`solve`の未発見を反例不存在・一般証明と同一視できない。
- `verify_h_revision.py`等の検算資産は作図を再構成する参考になる。ただし既知の個別関係のassertが多数あり、その成功を「定理なしの発見」に数えられない。
- `problem/scalar_geometry.py`は自ら「Small exact arithmetic model … not a solver」と明記し、対応構成も限定的。既存の汎用自然言語証明チェッカーとみなせない。

今回利用したのは**geometryの基本作図backendだけ**。`solver.solve`、数値最適化、GPU、LLM、学習は使っていない。

## 実施した小実験

H01の作図から、A,B,C,M,H,Pの全15点対距離の二乗を機械的に列挙した。候補の文法は、これらの1次・2次単項式同士の等式で、比の係数は分子・分母が各16以下の正有理数。対象関係のリストや採点用正解式は探索に与えていない。

作図入力を`A=(u,v), B=(-b,0), C=(b,0)`に正規化し、M,H,Pを上記の既存APIで作った。HやPの既知の最終座標式は手で埋め込んでいない。ただしH01という配置の選択・基本作図への翻訳・正規化・探索文法は研究者が行っており、自然文の任意問題を自動形式化する実験ではない。

| 段階 | 結果 |
|---|---:|
| 相似な3数値例だけで成立する候補 | 994 |
| 非相似の追加配置で厳密な反例を得た候補 | 921 |
| 独立に生成した非相似12例からの候補 | 73 |
| 別seedの40未見形状で反例が出た候補 | 0/73 |
| 共通因子と同値な二乗式の簡約後 | 25式 |
| 一般u,v,bで有理式の恒等性を確認 | 25/25 |
| 垂心という条件を外しても中点・垂足の定義だけで成立 | 6/25 |

形状の同一性は`(abs(u/b), v/b)`で判定し、鏡映とB,C交換を同じ形として扱う。固定seedで生成済みの50候補は45形状となり、そのうち学習側と同型の5形状を除いた40形状を評価した。追加生成はしていない。学習側12例にはこの基準での重複はなかった。各集合内部と集合間で形状が重複しないこと、および鋭角不等辺条件を厳密有理数で確認した。「未見」はこのCPU試験内の意味であり、研究全体の未曝露評価題ではない。

**独立監査による補正：** 初版は`(u/b,v/b)`で判定していたため、鏡映を別形として数えていた。「47未見形状」は誤りで、旧47行は鏡映をまとめると43形状、学習側の鏡映同型まで除くと40形状だった。正規化を修正して再実行した結果、73候補、921反例、一般式25件の検証結果は変わらなかった。

反例の一つは`AB²=(8/5)AC²`。`u=-18/25, v=63/25, b=9/5`で残差が`-40014/3125`となり、鋭角不等辺の許容範囲内で否定される。相似拡大の例数を増やすだけでは、この種の偽関係を排除できない。

一般検証を通った式には`AM²·MP²=BM⁴`が含まれた。探索コードにこの式の個別テストはなく、全単項式対の列挙から得られた。距離の非負性から`AM·MP=BM²`が従う。ただしAPを求める際の点の順序など、追加の不等式・枝の推論をこの探索器が自動で行ったわけではない。

25式中19式が定義だけでは出ないからといって、19独立の発見ではない。BM=CM、BC=2BMによる同値式や、他式からの組合せが多い。二項式の指数ベクトルのrankは全体で5であり、定義由来の2方向を除けば実質的な関係の幅はさらに小さい。今回この数を「独立定理数」や「有用性得点」として扱わない。

一般検証では、垂心を外した対照として`P=alpha·A, H=P+beta·rot(A)`を置き、PがAM上、HPがAMに垂直という定義だけを保った。そこで残差が消える式を定義由来とした。恒等性の判定はSymPyの有理式整理に基づく。Lean等の証明カーネルによる形式証明ではない。

処理時間は`results.json`の`timings`に保存した。鏡映同型の補正後の最新実行はスクリプト内部0.274秒、プロセス全体0.410秒。初回の補正前実行は内部0.260秒、プロセス全体0.346秒だった。これは小さなH01に限る実測であり、円の第二交点や反転の枝を含むH03/H14に外挿しない。

## この結果で保証されないもの

1. **モデル自身が関係を提案できるか。** 今回の提案者は小さな全探索器でありLLMではない。モデルに要求するなら、同じ文法の候補を生成させ、真・反例あり・未検証を分けて記録する追加実験が要る。
2. **複雑な構成を同じ関係に結びつける能力。** H03/H14のボトルネックは、間接的な円構成から垂心の射影を同定する部分。H01の恒等式の取得はその解決ではない。
3. **別配置の証明での有用性。** 今回は抽出した関係の再利用を試していない。単に真の式が多数出ても研究の中心課題は満たさない。
4. **任意の自然言語答案の正しさ。** 未検証の文章を、式の一部が成立したという理由で全文正解の教師にできない。
5. **全条件の自動処理。** 有理な点・直線構成の恒等式には向く。平方根の符号、円の二交点の選択、点の順序、追加仮定、分母が0となる特殊配置は、別途管理が必要。
6. **新規の数学。** H01は既知の配置で、研究者も関係を知っている。これは候補を手で列挙せず機械で取り出せるという実装可能性の検査である。

## 現実的な次の実験

いきなりRLへ移行せず、次の小さな関門を順に置く方がよい。下記の数は成功率予測ではなく、予算上限・停止判断のための案。

1. **既存回答から候補を抽出し検査する。** 学習前後の保存済み回答から、実際に書かれた関係を欠落補完なしで取り出す。文字対応と適用条件を記録し、簡単なものは基本作図から反例を探す。正しい関係の生成率と証明欠落を分ける。これなら新しいGPU実験に先立って着手できる。
2. **2〜3構造で検査経路を確かめる。** H01型の有理な射影に加え、円の第二交点を含む1構造で、真偽と未検証を正しく分けられるかを確認する。1〜2作業日を投資上限とし、特定の問題の核心を手で教える実装ばかりになれば拡張を止める。H03/H14全体の証明器完成を前提にしない。
3. **学習なしの候補→検査→利用を測る。** 選んだモデルが同じ候補文法で自発的に出した関係だけを検査し、別の配置に与えたときの成功率を、関係なし・無関係な真関係という対照と比較する。例数・生成回数は固定する。ここで利用効果がなければ、RL/SFTへの投資を増やす根拠は弱い。
4. **材料と利用効果が出た場合だけ短い学習比較。** まず検証済みの構造化候補だけを扱うSFT/再選別を無更新baseと比べる。反例ありの候補は不正解、一般検証できない候補はunknownとし、同一視しない。RLは、十分な検証可能候補、安定した報酬、枝条件の扱いができてから比較対象にする。

モデルの自己提案率が低い場合、全探索器の候補を提示してモデルに利用させることは技術的にはできる。ただしそれは**機械が抽出した知識を外部から渡す経路**であり、「モデルが数値経験から自分で関係を獲得した」という主張は弱くなる。元の仮説との整合を優先する本実験では、モデル提案→solver検査を主にし、全探索候補は道具の陽性対照・候補空間の上限確認に分けるのが妥当。

今回示せたのは、この限定的な検査経路なら大型の証明基盤を新造する前に試せる、ということまで。SFTの転移不振を新方式なら解決できるという根拠にはならない。
