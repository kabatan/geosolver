# AP01 numeric-SFT pilot: independent pipeline audit

Scope: static read of PROTOCOL.md, build_data.py, and the current run_remaining.py; limited inspection of the existing trainer, continuation wrapper, generation driver, and geosolver condition semantics. No model generations or old model outputs were opened. This is a code audit, not an observation of completed runs or proof scores.

## Findings

| Check | Finding |
| --- | --- |
| AP01 premises and teacher meaning | **Pass in code.** The side convention is \(a=BC,\ b=CA,\ c=AB\), with \(B=(0,0), C=(a,0), A=((c^2+a^2-b^2)/(2a),\sqrt{c^2-x^2})\). Midpoint and line-intersection expressions construct precisely \(M,N,P,D,E,F\). The perpendicular-bisector intersections are initially with line \(AM\); positive dot-product guards put \(D,E\) on ray \(AM\). AcuteTriangle is a guard, scaleneness is ensured by unequal integer side lengths, and the sum of unsigned subtriangle areas equal to \(ABC\) together with each area strictly positive enforces \(F\) strictly inside. No cyclicity condition is used in solving or selecting shapes. The solver target is only Distance(point,point). |
| Conclusion/proof leakage | **Pass in exported training path.** The manually fixed English text repeats only AP01 premises and adds side lengths plus a distance query. train.json is explicitly restricted to id, source_id, kind, messages, and a six-decimal target; no coordinate, construction DSL, reference proof, theorem name, or cyclic goal is exported. The detailed solver provenance and numeric key are separate files; numeric generation jobs omit target, and the generation driver rejects jobs carrying target or answer_exact. The proof prompt necessarily states the goal for evaluation, but it is not a training target. |
| Train/heldout similarity | **Pass.** Each accepted shape gets a signature of the three sorted, exact rational side/max-side ratios. The global seen set covers both splits, so permuted, scaled, and reflected similar triangles cannot cross them. The split is 64 train and 8 heldout shapes, with 4 and 1 uniformly sampled distinct query types per shape respectively. prepare() independently asserts 64/8 distinct signatures and no overlap. Four additional diagnostics are deliberately probes from training shapes and are labeled separately. |
| Base/SFT and common cap | **Pass in current orchestration, pending run receipts.** The numeric arms use the same numeric-jobs.json; proof SFT uses the same proof-jobs.json as the separately launched base arm. The existing generation driver fixes model metadata, decoding parameters, batch_size=4, and per-job seed; only adapter presence differs. The trainer uses assistant-target-only LoRA SFT and a 32-update checkpoint; the continuation wrapper extends the identical deterministic data order and optimizer state to 128 updates, i.e. 512 examples = two passes over 256 training rows. For either task kind, if either arm has finish_reason == "length" at 32,768 tokens, both arms regenerate that job with the identical seed at 81,920 tokens / 98,304 context. Blinding then uses the extended output for both arms, preserving initial outputs in their original directories. |
| Independent label audit | **Good safeguard, pending execution.** Before SFT, prepare() recomputes \(A\) through \(F\) from the side lengths with separate primitive arithmetic, checks all 256 training labels and 8 heldout labels against solver decimals, checks six-decimal rounding, and verifies the public export columns. This audit does not use the cyclic conclusion. |
| Material bugs | **No confirmed blocker found** in the inspected code. The caveats below need run-time/provenance checks before interpreting outcomes. |

## Interpretation limits

The protocol correctly treats this as one AP01 problem, one SFT seed, 64 training shapes, 8 heldout numeric shapes, and eight proof samples per arm. Training repeatedly exposes the same AP01 premises, so a proof gain alone cannot establish that numeric reasoning caused it. It may reflect task-specific adaptation, sampling variance, or compute spent on the SFT arm. The planned blind proof review and separate numeric score can establish whether this particular intervention coincided with improved full proofs; causal and cross-problem claims require the additional controls listed in the protocol.
