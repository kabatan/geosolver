# 数値情報を学習時だけ与える自己学習：文献と単GPU実装の調査

2026-09-26。一次論文・著者実装・TRL実装と、このrepoの学習環境を確認した。調査後に実施した限定的GPU技術確認は [DISTILLATION_PROBE.md](DISTILLATION_PROBE.md) に記録。研究目的は「対象の解法を外部から教えず、solverの数値経験を学習した後、モデル自身の未指導の幾何能力が改善するか」。一般関係の自由発見や汎用形式検証器の開発へ目的を移さない。

## 判断

最も追加実装が少ないのは、**数値答えをヒントに本人が作った答案を、ヒントなしの問題文へ戻して学習するSTaR型**。最も過去の数値正誤GRPOと異なる学習信号を作れるのは、**数値答えを知った同モデルで元の出力を再採点するSDPO型**。後者は新しい正解答案を毎回生成・選別する必要がない。

どちらも既存手法の利用であり、それ自体を新規アルゴリズムとは呼ばない。数値問題の精度から未指導の一般証明へ移るかは、引用論文で実証されていない。本研究におけるその転移が実験対象となる。

## 1. 数値答えをヒントにするSTaR型

**一次研究の支持と限界。** STaRは正解をヒントに自己生成した説明を、ヒントを除いた入力へ対応付けてSFTする。原論文のGSM8Kでは、答えのみSFT 5.8%、自己生成答案SFT 10.1%、正解ヒントによる追加 10.7%。ヒントの追加効果は小さく、算術や常識問題での改善をそのまま幾何へ外挿できない。正解に合う誤った理屈も失敗例として報告している。[STaR原論文](https://arxiv.org/html/2203.14465v2)

**今回の具体化。** 学習中に一般証明問題は出さず、数値求値問題を出す。

```text
Original training question:
<numeric geometry problem>

Privileged information, supplied only during answer generation:
An independent numerical solver returns <exact numerical value>.
Derive this value from the given assumptions. The supplied value itself
is not a justification. Do not introduce additional assumptions.
```

採用した本人の答案を、元の問題文のみを入力とする既存SFT driverへ渡す。答えはsolverが供給し、解法は本人が生成する。評価は数値を除いた同構図の一般証明を含む。本人が答案中で一般関係を発見しても、それは禁止しない。外部の正解証明は混ぜない。

**失敗点を先に特定できる小実験。** 同じ16個の数値問題で、通常生成1回と答えヒント付き生成1回を対応させる。32出力について最終数値と推論の成立を別に採点する。正解数値を与えているので、最終数値一致だけでヒント条件を採用してはならない。採点者は合否のみ返し、修正解法を教師にしない。これは収集方式の実在性を測る診断であり、学習を行うことの論理的な必須条件ではない。

良い答案の増加が見えれば、小さな固定学習予算で、通常の自己生成答案SFTとヒント条件のSFTを比較する。両群で問題数・採用答案数・学習トークン数を可能な範囲で一致させる。正解数値は増えたが説明の成立が増えないなら、rationalizationの既知の弱点が今回も出ており、これを大量化する理由は弱い。

既に本人の一般証明を少数SFTした実験とは異なるが、最終的な学習器は同じSFTである。以前の教師品質・忘却の問題を自動で解決するわけではない。主候補にするなら、学習率・更新回数を増やすのでなく、まず同じ小予算で比較する。

## 2. 数値答えで元の出力を再採点するSDPO型

**一次研究の支持と限界。** SDPOは、環境フィードバックを受けた同モデルの次トークン分布を使い、学生自身の生成列を再評価する。Qwen3-8B等で数値報酬RLより改善したが、主要実験はnon-thinking、4枚のGH200上。フィードバックを解釈できないモデル・情報量の小さいフィードバックでは有効性が弱いと著者も述べる。本repoの主9B実験はnon-thinkingなので、thinking条件の不一致はない。[SDPO原論文](https://arxiv.org/html/2601.20802v1)、[著者実装](https://github.com/lasgroup/SDPO)

**今回の一更新。**

1. 学生：元の数値問題だけで答案 `y` を1回生成する。
2. 同じモデルの教師側：元の問題とsolverの数値答えだけを受け取り、同じ `y` の各トークンの確率を再計算する。新しい答案は生成しない。
3. 学生側：正解を知らない入力で、教師との差に基づくLoRA更新を行う。
4. 次の問題では更新後の学生で再生成する。一般証明は更新用データに入れず、評価時だけ問う。

元のGRPOは、答案全体に正誤から同じadvantageを与えていた。ここでは例えば数値答えを知ることで、本人が元の不適切な分岐に低い確率を与えられるなら、その分岐に異なる更新信号が入る。全サンプル不正解のグループでも教師との分布差は作れる。ただし、数値答えだけで途中の誤りが分かるとは限らず、最後の数値トークンだけを直す更新になる可能性がある。

**まず行う費用の小さい診断。** 既存の不正解出力を4〜8本使い、問題だけと問題＋数値答えで、教師のトークン対数確率がどこで変わるかを測る。新しい長文生成は不要。正解末尾以外にも変化するか、既知の誤った式をむしろ強化していないかを見る。これは有効性の証明ではないが、「数値報酬とは異なる信号が実際に入る」という実装・機序の確認になる。

その後の探索実験は、例えば16数値問題・各4更新巡回の64生成までと固定し、同じ問題・生成予算の数値正誤RLと比較する。これは小規模探索であって、陰性から方法全体の不成立を結論しない。一般証明の採点は既存のままとし、短文化だけを改善と数えない。学習後の未指導証明が改善した場合に、別の構図と学習seedで再現する。

**数値情報の作り方。** 最初は「独立solverの数値結果はX」だけ。複数の数値実現やモデルが要求した測定値を追加する変種も考えられるが、それは別条件にする。正解関係・人手の補助点を作って教師文脈へ入れると、元の仮説の検証でなくなる。solverが同じ点集合の一般的な測定量を返すことと、研究者が正解に必要な量だけを選ぶことは区別する。

## 3. 単一5090への実装上の入口

公開TRLのSDPOはexperimentalだが、PEFT/LoRA対応を文書化している。さらに `_setup_teacher_model` のpure-LoRA + EMA分岐は、baseを共有してteacher用adapterだけを持つ。教師の9B全体をもう1個GPUへ載せる必要はない。[TRL公式文書](https://huggingface.co/docs/trl/sdpo_trainer)、[trainer実装](https://raw.githubusercontent.com/huggingface/trl/main/trl/experimental/sdpo/sdpo_trainer.py)

ただし、このrepoで実際に入っている環境は次のとおり。read-onlyでdistribution metadataを確認した。

| 環境 | 実際のバージョンと制約 |
|---|---|
| `qwen/.runtime/vllm-venv` | torch 2.13.0、transformers 5.17.0、peft 0.18.0、trl 0.26.2、vllm 0.29.0 |
| 同上のTRL | GKDはあるがSDPOファイルはない。最新版文書のAPIをそのままimportできない |
| `qwen/.venv` | torch 2.12.1+cu130、transformers 4.57.6。9B側の実績環境ではない |

環境を全面更新するより、最初の教師forward診断は既存9B loaderをそのまま使う方が範囲が小さい。

- 9B loaderとLoRA target：`docs/research/qwen35-diverse-sft-2026-09-24/train.py`。BF16、SDPA、非reentrant checkpointing、r8/alpha16、hybrid attentionの `in_proj_qkv` などを含む。
- 生成：同ディレクトリの `generate.py`。既存adapterの名前写像の修正実績を尊重する。
- 省メモリの確率計算部品：`qwen/grpo_loss.py` の `frozen_head_logps`。凍結LM headの語彙softmaxをchunk単位で計算し、全トークン×全語彙のlogitを保存しない。
- `qwen/grpo_policy.py` のloaderはQwen3-4B固定。9Bへ丸ごと流用しない。

最小driverは、生成→教師no-grad forward→必要な確率をCPUへ退避・教師中間値破棄→学生forward/backwardの順にする。最初は学生の生成トークンに対する対数確率だけで更新する近似が軽い。full-vocabulary KLやtop-k KLと同じ手法を完全再現したとは呼ばない。EMA teacherを使うならLoRA adapterだけを保存・切替する。

現存receiptでは、38更新、総answer 21,403 tokens、最大系列1238で学習20.37秒、peak allocated 21.17GiBだった。これは短いSFT系列の実測にすぎず、4k〜8kの教師付きforwardが収まる保証ではない。`teacher_prompt + student_completion` の長さで別途peakを測る必要がある。長文生成が主要費用になる可能性が高く、論文の「1時間」をこの5090へ移し替えて見積もらない。

今回別途用意した `distillation_probe.py` は、既存no-hint出力についてfull-vocabulary forward KLを1回だけ更新する技術試験。teacherは同じbaseをadapter無効で利用し、logitをCPUへ退避する。chunked KLの値・勾配がdense実装と一致するCPU確認後、GPUで1024-token prefixと自然終了した5670-token全答案を各1更新した。両方成功し、peak allocatedはそれぞれ18.51GiBと26.16GiB、load込み4.41秒と12.70秒。これにより短いprefixだけでなく、現存5.7k答案全体での技術的実行可否も確認できた。学習後の改善は測っていない。

**学習pilotも最初は1024-token prefix蒸留、未指導証明の評価は従来の32k上限、という分離は実装範囲として妥当。** 最初から32k全系列のKLを必要条件にしない。prefix末尾へ人工的なEOS教師を足さず、打切りを「答案の完成」と扱わない。ただし重要な幾何推論が後半にしか現れない場合には学習信号を逃す。1024 tokensが最適、長い能力が保持される、という根拠にはならない。最新の数値答えOPSD論文と比べ、今回の技術試験はteacher non-thinking（論文はthinking）、KL成分clampなし（論文はあり）であるため、その論文の再現ではない。GPU試験1回が通っても、on-policy再生成・反復更新・評価を含む完全な訓練loopの動作確認は別途必要。

## 4. 好材料だけで判断しないための文献

2026年7月の独立研究は、正解情報付き自己蒸留がthinkingモデルの長い推論を損ないうることを報告した。数値答えのみの条件は完全解法を見せる条件より悪化が小さい。これは現在のnon-thinking主条件の直接反証ではないが、短い出力の精度だけで判断せず、従来の証明評価と出力長・自然終了を併記する理由になる。[Rethinking On-Policy Self-Distillation for Thinking Models](https://arxiv.org/html/2607.05184v1)

別のOPSD論文では強い効率改善があるが、主なprivileged informationは検証済み解法で、8枚のA100/H100を用いている。解法を持たない本研究の直接の成功証拠として扱わない。[Self-Distilled Reasoner](https://arxiv.org/html/2601.18734v2)

数値答えだけのOPSDを直接比較した最新論文 `2609.25623` は別メモの調査対象。SDPOと同じ略称で一括りにせず、forward KL/reverse KL・教師更新・thinking設定・生成予算を区別する。

## 優先順位

1. 追加実装の小ささを優先するなら、数値答えヒントの対応比較と既存SFT。期待する改善は正しい自己答案の供給率であり、転移の保証ではない。
2. 元の数値正誤GRPOの情報不足を変える候補として、数値答えを使うSDPO/OPSD。まず教師forwardのメモリと更新信号を実測し、独立小driverで小予算学習。これは現在のnon-thinkingモデルでは検討に値する中リスク案。
3. 大規模化や新規方式を主張する前に、同構図の未指導一般証明という元の評価で確認する。教師側の数値問題が解けるだけでは成果としない。

どちらも「解法を知らずに供給できる数値情報を使い、モデルの重みに学習する」という主題を保つ。汎用証明器の完成、自由な定理発見、外部から補題を与えた解法システムの成功を前提にしない。
