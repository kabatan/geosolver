# 数値教師から未指導の幾何能力へ：一次文献・実装調査

調査日：2026-09-26。訂正：初版は GeometryZero v2 を参照して証明転移評価を見落とした。v3（2026-04-20）Appendix F を確認し、以下を修正した。文献調査と公開コードの読み取りのみ。この担当では GPU 学習・推論は実施していない。

研究意図は「対象の幾何性質・証明を教師にせず、solver が出す数値経験を使って重みを学習し、直接教えていない幾何能力を改善する」である。同配置の一般証明改善も有効な第一成果。自由な定理発見、DDAR を上回ること、外部証明器完成を必須条件に追加しない。

## 判断

最も試す理由があるのは、**数値解を特権情報として与えた同じモデルから、解を見ないモデルへ学習する**方向。既存の答案 SFT の反復ではなく、学習時に使える数値解を、推論経路の学習信号へ変える。その簡便版が STaR の答え付き再生成、密な信号を使う版が answer-only 自己蒸留。後者は直近の実験根拠が見つかった。

自己蒸留・STaR の根拠は数値解法の改善であり、一般証明への転移は別途検証が必要。一方、GeometryZero v3 には、数値問題のみの RL 後に証明問題が改善した追加実験があり、こちらは原仮説に直接近い支持である（下記）。したがって「数値教師から証明能力へ転移する根拠がない」とは言えない。実装容易性と、目的への直接の実証強度を分けて候補を選ぶ。

## 1. 答えだけを教師側に見せる on-policy 自己蒸留

一次論文：[What Should a Self-Teacher See? Privileged Context Design for On-Policy Self-Distillation](https://arxiv.org/html/2609.25623v1)（2026-09-22、非常に新しいプレプリント）。

**確認した事実。** 同一ベースの凍結 teacher が、学生自身の生成 prefix を参照解付きで採点する。答えのみの条件 L5 も比較。4B の数学ベンチマーク peak 平均は base 60.28、全解法 teacher 63.43、答えだけ teacher 63.61。8B は順に 62.13、66.67、66.76。学習 pool 29,434 問、200 optimizer steps、LoRA rank 64、8 H200、学習生成上限 1,024 token。学生 non-thinking、教師 thinking、評価 thinking。損失は full-vocabulary の teacher→student forward KL に語彙成分ごとの上限 clip を施したもの。最終評価は最大 38,912 token。

**限界。** 主結果はベンチマークごとに八つの checkpoint の最大値を選ぶため上方選択バイアスがあると著者も記載。L5 は主に 1 seed の比較で、証明転移実験ではない。teacher の分布変化が大きいほど学習効果が高いわけではない。同論文の重い学習をそのまま「小規模に再現可能」と呼ばない。

**この repo での具体化案（論文そのものではなく提案）。**

- 入力 `x` は数値幾何問題、`a` は solver の数値解。teacher には `x + known numeric answer a`、student には `x` のみを渡す。対象の一般式や定理名は一切追加しない。
- student が生成した各 prefix に対し、adapter を無効化した同じ base を teacher として teacher-forcing 採点する。LoRA 学生なら二つのモデル重みを同時常駐させる必要はない。teacher は学習しない。
- 対照は「同じ書式・同じ thinking 設定で、teacher に答えを渡さない」。文体・thinking 切り替えの効果を数値教師の効果と混同しない。
- full-vocabulary logits の全系列保存は不要。位置を chunk に分けて forward KL を計算する。sampled-token log-ratio だけの近似へ変えた場合は、原論文の追試とは別方式として明記する。
- 最初の採否判断用 pilot は 12～24 の数値問題で、答えなし／ありの生成を各 2 本程度比較し、最終数値ではなく途中推論を盲検評価する。既存の確実な誤推論も教師が支持し続けるなら、dense teacher を有望視する理由が弱くなる。これは教師の健全性検査であり、学習効果の十分条件でも必要条件でもない。
- 小規模学習はまず 64～128 の異なる問題・数値実現、16～32 更新程度を工学的 pilot とし、数値の新規実現と同配置の一般証明を学習前後で測る。これで効果がなければ原理的不可能とは言えないが、少なくとも本格 run の積極的根拠は得られない。
- 数値答えを知る教師が誤った途中推論をもっともらしく支持するリスクは残る。最終答え token だけを当てる能力に効果が集中していないか、答え部分を損失から除く補助比較を行える。ただし最初から多数の variant を走らせない。

**従来との違い。** 37 本の人手／外部教師の完成答案を模倣するのではなく、自分が実際に通る prefix を、計算結果を知る自分のモデルで修正する。数値経験だけで学習を進めるという意図を保ちつつ、最終正誤 1 bit より密な学習信号を得る。

## 2. STaR 型の答え付き自己答案収集を、先に安く判定する

一次論文：[STaR: Bootstrapping Reasoning With Reasoning](https://arxiv.org/html/2203.14465v2)。正解だけを知って再度理由を生成する rationalization、成功した自己生成理由の学習、再生成を反復する。人手の少数 reasoning 例を使う原論文と、対象証明を与えない今回の条件は区別する。

具体案は、数値問題ごとに通常解答を生成し、不正解時には solver の最終数値だけを与えて解き直す。学習時にはヒントを消し、元の問題から本人の解法を生成するよう SFT する。原理的に既存の generation / SFT パイプラインを使えるので、dense distillation より実装コストは小さい。

ただし現在の実験は「正解数値でも推論が誤っている」という失敗が多い。答えを知らせると、この問題をさらに悪化させる場合がある。したがって即 SFT ではなく、上の答えあり／なし生成 pilot を共用し、完全な推論の率と有効答案の幅を測る。『solver が数値を保証したから答案も正しい』とはしない。少数 pilot の人手／独立採点を大量収集時の無限の工程として隠さない。

採択できたら、まず自己生成答案 100～300 本程度で 1 回の SFT を試す。これは成功予測ではなく計算予算を区切る提案値。構図を 3～5 個に固定して数値だけ繰り返すのではなく、解法が既知である必要のない作図系列から収集し、同じ自己生成答案の反復数を揃えた対照を置く。learning rate と更新回数は今までの退行を踏まえ控えめにし、checkpoint は検証集合で選ぶ。

原論文でも rationalization の効果はタスク依存。今回、答えヒントで完全解法の回収率が増えなければ、同じモデルでの STaR 大量生成は優先しない。

## 3. 数値 RL から証明への改善報告はある。ただし GCPO は幾何過程の真偽検査ではない

一次論文：[GeometryZero v3](https://arxiv.org/html/2506.07160v3)。数値・選択肢の最終解を教師として RL する幾何学習。主訓練は 3,443 問、4 H100、全パラメータ更新、group size 8、completion 1,024。v2 の 7B GCPO は 22.67 GPUh と報告するが、14B 証明実験や現行 9B 長推論への費用換算はできない。

**v3 の追加実験は原仮説を直接支持する材料。** UniGeo の証明部分から 108 問を選び、Qwen2.5-14B-Instruct 64.8% → GeometryZero-14B 72.2%（7.4 percentage points）の改善を報告する。著者は証明問題を訓練に含めていないと明記。モデルの完全な proof sequence を golden sequence と比較して採点する。これは「未指導の幾何証明能力の改善報告あり」と記述すべきであり、初版の否定は訂正する。

**この結果からまだ判断できないこと。** 108 問の選抜・golden sequence 比較に依存し、同値な別証明の扱いや細かな採点再現条件は Appendix F だけでは明確でない。証明側の GRPO / SFT / GCPO 成分 ablation、複数 seed のばらつきは記載されず、改善のどこまでが GCPO の特有要素かは分からない。AG 比較側の自動検証と、LLM 側の golden sequence 比較は同一検証ではない。人類未知の性質獲得や今回の構図での一般証明まで示したものでもない。最後の点は原仮説への支持を取り消す理由ではなく、支持の範囲を定めるもの。

UniGeo 自体は平行・三角形・四角形・合同・相似の証明を理由と式の列として表すベンチマークであり、難度も研究対象の補助構成問題と必ずしも同じではない。[UniGeo 原論文](https://aclanthology.org/2022.emnlp-main.218.pdf)

GCPO の核心は、補助構成を強制する群／しない群の最終正答率差で、主 rollout の補助構成報酬を正・負・ゼロに切り替えること。補助構成そのものの幾何的正しさを検証する方法ではない。長さ報酬も追加する。

公開実装も確認した：

- [reward_func_relax_v9.py](https://github.com/ekonwang/GeometryZero/blob/main/workspace/reward/reward_func_relax_v9.py) は `aux_line_reward_v2_func` を呼ぶ。
- [reward_utils.py](https://github.com/ekonwang/GeometryZero/blob/main/workspace/reward/reward_utils.py) の v2 は `<auxiliary>…</auxiliary>` の存在を正規表現で検出して 0.5 を返す。別 v3 は TikZ の描画可否を確認するが、Python 分岐はコード抽出に成功すれば報酬を返す。
- [experience_maker.py](https://github.com/ekonwang/GeometryZero/blob/main/r1_workspace_openrlhf/openrlhf/trainer/ppo_utils/experience_maker.py) の L436–474 は 3 群の最終正答率から補助報酬の符号を決める。

したがって『数値 RL で未指導の証明能力が上がりうる』という根拠としては重視する。一方、今回の補助線発見の困難に対して『GCPO を移植すれば解消できる』とは言えない。GCPO 特有の追加コストを払うなら、モデルが補助構成あり／なしで異なる正答率を出し、学べる差が生まれるかを先に小さく測る。数値 RL の可能性を、タグ報酬の不完全さだけを理由に低く評価しない。

単純 GRPO の再挑戦をするなら、まず rollout を集めて成功・失敗が混在する数値問題の密度を測り、その範囲に学習を集中する。全不正解 group は正答 reward の相対優位が出ないので、更新数だけ増やしても改善を期待しにくい。ただし成功答案の推論が誤っていれば、その集中は誤学習も加速する。既存の 40 問・160 出力・9 更新の陰性結果は無視しないが、数千問で行う先行研究と同等の否定結果ではない。

## 「SFT はだめ、RL なら一般化する」と結論しない理由

[Bridging Supervised Learning and Reinforcement Learning in Math Reasoning](https://arxiv.org/html/2505.18116v2) は、自己生成の失敗例も使う NFT が数学で rejection SFT を上回り、GRPO 等と競合すると報告する。strict on-policy では勾配の関係も示す。『SFT vs RL』という名称の違いより、本人の現在の出力上で、成功と失敗のどちらをどの信号で学習するかが重要。ただし NFT に替えるだけで幾何転移が起きる根拠はなく、失敗時にも正しい理由が必要という報酬の不整合は解消しない。

[RLVR Implicitly Incentivizes Correct Reasoning](https://arxiv.org/html/2506.14245v1) は、数値正誤のみの RL が正しい reasoning を増やせる実証を示す一方、正答と正しい推論の差、分野不一致での非改善を報告する。32B・32 MI300X・2 週間超の実験で、ここから小予算の成功を推定しない。結論は『数値教師では推論を学べない』ではなく、『数値正答の改善は目的の証明能力の改善を保証しない』。

## 優先順位

1. 同一モデルへの数値答えヒントが正しい解法を増やすか、小さな paired inference pilot。外部 Pro は実験設計相談だけに使い、対象モデルへの解法教師にしない。
2. 回収率に効果があれば、実装が最も簡単な STaR 型と、密な学習信号を使う answer-only 自己蒸留のどちらかを、資源とコード適合で選ぶ。二方式とも大規模に同時始動しない。
3. 一般証明転移を直接測る。数値スコアだけ上がった場合、原仮説の成功とは報告しない。
4. 数値 RL は proof-transfer の直接先行根拠を持つ有力な並行候補。ただし GCPO 全面移植に先立ち、補助あり／なしの paired rollout で有益な学習差が出るかを調べる。『長さを増やす』『補助線タグに報酬』が今回の欠落能力を埋めるかは別問題。

## 追記：GeometryZero を実行候補にする場合の最小構成

公開 [7B 訓練スクリプト](https://github.com/ekonwang/GeometryZero/blob/main/workspace/train/grpo_v9_7b_mix.sh) も確認した。`num_episodes=1`、各 rollout データに対する `max_epochs=1`、rollout batch 64、train batch 32、各 prompt 8 samples、生成上限 1,024、Qwen2.5-7B-Instruct、全パラメータ BF16、ZeRO3、Adam offload、4 GPU、LR 3e-7。公開 script は LoRA を使わない。実際に完了した optimizer updates のログは今回確認していないので、step 数は断定しない。

GCPO は各問題を3群に展開し各8生成を行い、主群だけを学習に使う。3,443問が全て一度通ると仮定した単純な規模計算は、主群約27,544生成、全3群約82,632生成（打切り・端数batch等を無視）。これは実ログの件数ではない。公開scriptの比較群Bは元のpromptをそのまま使い、群Aに補助構成の指示、主群に補助構成を選択する指示を加える。そのため実装上Bが必ず補助構成をしない、とも保証されない。

**exp03 陰性後に通常の数値 GRPO をもう一度行う合理性はあるが、単なる長時間再実行では弱い。** exp03 は4B・40問・160生成・9更新であり、先行研究の問題数・生成経験数からかなり隔たる。今回の9B non-thinkingへ変えるだけで成功する保証はないが、既存手法が原理的に無効とするには小さすぎる。反対に、GPU時間だけ延長して同じ40問と誤推論の正答を反復するのは、以前の失敗原因を残す。

現実的な案は、既存GRPOコードと9B LoRAを使い、**異なる作図／非相似な数値実現を128問程度、各4生成**から始めること。データ生成に解法や目的定理の注入を必要としない。最終数値のみを報酬とし、成功失敗が混在する問題数、正答のうち途中推論も成立している割合、自然終了率をまず測る。正答率が全0／全1に偏る場合は難度や問題分布を調整する理由になる。次に32～64更新程度で数値検証集合と、訓練に一切使わない一般証明集合を測る。これは小予算で試す提案値であって、GeometryZero再現を称する規模ではない。

5090単GPUでは、全パラメータ7B/14Bと3群GCPOを直接再現せず、既存のLoRA学習・逐次生成を使う方が実装現実性は高い。生成長上限を先行研究どおり1,024に切って大量の打切りを生むなら比較にならないので、現在の9Bが自然終了する長さを今回のpilot実測で決める。費用は実測tokens/secと有効rollout数から見積もり、論文の4H100のGPUhを5090の時間へ換算しない。

**GCPO全面移植は必須ではない。** 証明改善表には素のGRPOとの比較がなく、GCPO固有部品がその改善を生んだと切り分けられていない。まず上の通常GRPOを数値経験の効果を測る基準にできる。補助構成の選択が明確な失敗要因と確認できたら、12～24問の補助指示あり／なし各4生成だけで、正答率差の方向が安定するか確認する。差がほぼゼロ、または補助タグだけ増えるなら3群の費用を払う理由は薄い。長さ報酬を無条件に足すことも、実際の正しい推論が増えるまでは勧めない。

**新規性の制約。** GeometryZero v3 が存在するので、「数値解だけによる学習から証明能力が伸びることを世界で初めて示した」は主張できない。独自solverから対象性質を知らずに作る経験で、どの未指導幾何能力がどの条件で伸びるかを、訓練信号を明確に分離して示す余地はある。ただし実験前に、それが論文として十分な新規性になるとは保証しない。
