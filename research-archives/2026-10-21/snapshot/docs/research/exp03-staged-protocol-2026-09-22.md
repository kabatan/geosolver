# exp03：数値正誤から証明への転移と、追加報酬のための段階実験

2026-09-22。旧 `exp03_budgeted.json` の一括実験を置き換える。今回の依頼範囲は**計画・実装・準備完了まで**であり、正式なGPU学習・評価は開始しない。実行入口は `qwen.staged_study`、設定は [`exp03_staged.json`](../../qwen/configs/exp03_staged.json)。

## 問いと主張の範囲

第一の問いは、対象の性質・補助構成・証明を教師として与えず、数値正誤だけによる追加学習から、学習で教えていない一般証明が改善するかである。同配置の一般証明への転移を第一成果、別配置での有効な補助構成・性質の利用を第二成果とする。後者がないことだけで前者を無価値としない。

今回の条件Cの報酬は **R=C∈{0,1}**。推論の妥当性V・幾何的説明価値Gはオフラインで分析するだけで、学習報酬・データ選択・プロンプトへ戻さない。将来のCV/CVGは別実験として [追加報酬の追試計画](exp03-reward-followup-plan-2026-09-22.md) に定義する。Cが陰性でも、数値だけでは区別されなかった妥当な説明が観測されれば、追加報酬を試す理由になり得る。

現在の数値ラベルは構成計算から独立に検査した値であり、repoの汎用solverが実際に生成したコーパスではない。人が既知のHumpty/Dumpty周辺の配置を選んでいる。従って本試行が検証するのは、研究構想のうち「数値教師から未指導の証明への転移」であり、未知理論の全自動発見ではない。モデルの事前学習で対象理論が未見だったとも主張しない。

## 学習データと方法

承認済み37配置・148問をすべて維持する。内訳は代表37、shape変種27、相似変種84であり、148種類の着想ではない。修正・検証済みの `training_variants.jsonl` を使用し、過去の不正プロンプトや採点結果を再利用しない。

順序はseed 20260923で固定する。最初に37個の代表例v0をシャッフルし、その後に残る111問をシャッフルして並べる。1ラウンド4問×4回答なので、最初の10ラウンド・40問には37配置すべてが含まれる。特定配置の成績を見て順序を変えない。残り108問を続ければ合計37ラウンドで1周する。

Qwen3-4B固定snapshot、FP16 base/KV/活性化、FP32 LoRA/Adam、LoRA r32/alpha64/dropout0、学習率5e−6。生成は未マージLoRA・eager、同時4系列、temperature0.6/top-p0.95/top-k20、thinkingあり、回答上限32,512・文脈上限32,768。較正済みの更新・生成コードは変更しない。

各問4回答の報酬から群平均を引き、標準偏差では割らない。全有効tokenによる正規化、KL0、token単位importance weightの上限2、relative ESS≥0.90・capped fraction≤1%を維持する。打ち切り回答のlossをマスクし、非ゼロadvantageの有効tokenがなければoptimizerを進めない。37ラウンドは必ず37回の有効更新を意味しない。

## 証明採点

全答案をモデル名を伏せて混合し、全採点を保存してから対応表を開く。中間評価は48答案、最終評価は96答案。中間で既に見た答案が最終にも含まれる場合があるため、査読者と過去の閲覧有無を記録し、完全に独立した盲検とは称さない。

完全な一般証明を正解とする。座標・ベクトルの正しい証明も同じく正解。名前だけで核心を仮定したもの、特殊配置のみの検証、未証明の核心があるものは完答としない。局所誤りは核心不足と区別する。

各答案に以下を付ける。

- `category`: complete / local_error / core_gap / mathematical_error / special_case / no_final
- `method`, `auxiliary_relation_proved`, `evidence`
- `core_proved`: 配置固有の核心が実際に論証されているか
- `core_applied_correctly`: 核心から先を正しく利用しているか
- `auxiliary_constructed`, `auxiliary_useful`: 補助対象の定義と有効な利用
- `unsupported_core_claim`: 名称引用・断言で核心を済ませているか
- `reviewer`, `prior_exposure`

N01/N02/AP01とEV02/DU01/OB01を合算しない。題ごとの0〜8正解と、各3題を等重みにした平均を出す。3題×8回答を24個の独立な数学課題とは扱わない。核心の論証は有用な副指標だが、完全証明に置き換えない。

## 中間で何を分析し、どう続けるか

開始コマンドは、base評価→10ラウンド→中間数値・証明評価→採点用ファイル作成までを実行して停止する。これは追加のユーザー承認を必須にする仕組みではなく、研究者または担当agentが科学的分析を行うための区切りである。再実行だけで分析を飛ばして残りを学習しない。

同時に、数値devと同じ12配置の**学習代表例**について4回答ずつ、計48答案をレビュー用に出す。選定は事前固定し、正誤を見て選び直さない。全raw思考・logprob・報酬・checkpointは保存する。レビューは最終提出説明を対象に、`reasoning_valid`（yes/no/uncertain/no_final）、`geometric_value`（yes/no/uncertain）、根拠、査読者を記録する。思考中の撤回された誤りは最終説明の誤りと混同しない。このGの有無という診断は、将来の0/0.5/1の報酬採点器較正とは別である。

| 中間で観測する状態 | 解釈・判断 |
|---|---|
| 同配置の完全証明・核心の論証が改善 | 第一段階の支持候補。残りC学習で持続するか確認する理由になる |
| 別配置で補助構成を根拠付きで利用 | 第二段階の支持候補。数値だけの改善と分けて記録する |
| 数値が改善し、証明は変わらない | 数値への適応。Cを継続するか、将来のV/G比較に資源を残すか判断する |
| 数値正答でも誤推論が多い | Cの限界の具体例。Vが異なる答案を選別できるか検討する |
| 妥当な幾何的説明が出るがCでは差がない | G追加の候補が実在する。較正を通せば追試の根拠になる |
| 10ラウンドで改善なし | 仮説否定ではない。有効更新数・答案内容・費用を合わせて継続判断する |

中間の完全な証明採点と48答案のレビュー後、判断理由・査読者・採点hashを保存する。選択肢は `continue`（同じ条件Cで37ラウンドまで）または `finish`（現在のcheckpointで8回答の最終評価を完成する）。途中で有望だったcheckpointを結果に合わせて「最終モデル」に差し替えない。finish時は中間の4回答を第一ブロックとして再利用し、第二ブロックだけを追加する。

中間成績を継続判断に使うため、全体は探索実験である。強い信号が見つかった対象には、別seed・適切な対照・未使用の関連課題による確認を次に計画する。最初からそれらすべてを要求して着手を遅らせない。

**Cを37ラウンド完走することは、追加報酬を検討する前提ではない。** 10ラウンド時点で証明への信号が乏しく、妥当性や説明価値で選別できる答案が実際にあるなら、Cはその地点で最終評価まで終え、残る計算資源を報酬比較に振り向ける選択を優先して検討する。逆にCだけで核心論証が改善するなら、その持続を37ラウンドまで確認する意味がある。どちらでも結果と判断理由を残す。

## 時間と計算資源

24〜40 GPU時間は目安であり、40時間を少し超える予測だけでは停止しない。今回の数値モデル経路は再較正せず、既存の実測を使用する。数値・証明評価、モデル読込、失敗試行、準備約0.685時間を計上する。

- 最初の10ラウンドと前後の中間評価：合計およそ13〜15 GPU時間。
- 10ラウンドでfinishし、証明8回答の最終評価まで揃える場合：平均長の概算でおよそ14.2 GPU時間。
- 37ラウンドまで継続する場合：中間評価を含め合計およそ35 GPU時間。
- 生成長22,000 token、学習/証明188.85 token/s、数値117.16 token/s、更新240秒/ラウンド、起動60秒/ラウンド、15%余裕からの概算。
- 正式な値はreadinessの`cost`に計算・保存する。小標本からの推定であり、実行中も実測で更新する。

40時間超の見積りは警告として記録する。無人workerの暴走を避けるため**48 GPU時間の累積実行上限**を別に置く。これは研究上の許容時間を48時間と決め直した意味ではなく、今回の既定実行設定である。実験途中に自動延長しない。後評価のため8時間を確保し、上限に近づけば新しい学習roundを始めず、最後の確定checkpointを評価する。採点に要する人・AIの時間と将来のAPI費用はGPU時間と分ける。

旧40時間台帳は改変しない。新台帳へ12件の準備jobと失敗分をすべて引き継ぎ、旧台帳hashと移行理由を記録する。費用をゼロから数え直さない。旧経路と新経路を同時に実行しない。

## 次の追加報酬実験への接続

今回の学習は最後までC。V/Gの採点値を今回の更新に混ぜない。最終確定したCのcheckpointを原則の追試出発点とし、追試を始める前に分岐点と使用データを固定する。同じ重み・optimizer・scalerからC継続、CV、CVGへ分岐する。比較は同じ更新機会・問題順・生成条件で行い、後続のCVだけ学習時間を増やして古いCと比較しない。

数学的に妥当な説明への報酬は、数値一致だけでは区別できない誤推論を選別し得るため、試す理由がある。幾何的説明への報酬も、実際に有効な説明が生成され、採点器が適切に識別できるなら有望な候補となる。ただし効果を既定事実としない。点名・用語・短文への報酬ではなく、関係を根拠付きで利用して問題を簡約した役割を採点する。

追加報酬は汎用judgeの数学知識を含む意味的な教師情報である。CV/Gだけが成功した場合、数値正誤のみからの転移が実証されたと主張しない。現在のC実験が明確な陽性であることを、V/G追試の必須条件にはしない。

## 実行手順

準備・実行ともrepoルートで、既存のGPU用Pythonを使う。デフォルトはCPUの準備検査のみである。

```bash
# 固定設定・環境・データを検査する。本実験を開始しない。
qwen/.runtime/vllm-venv/bin/python -m qwen.staged_study

# 開始または再開。最初は10ラウンド後の分析待ちまで進む。
qwen/.runtime/vllm-venv/bin/python -m qwen.staged_study --run
```

出力先は `qwen/.runtime/exp03_staged/study/`。`interim_review/blinded.jsonl` と `training_review/responses.jsonl` を読んで、それぞれの `protocol.json` に従い `grades.jsonl` を作成する。判断根拠には、証明の完全性、核心の論証、数値の適応、誤推論、費用を記す。単なるキーワード増加を根拠にしない。

```bash
# 証明の採点を凍結し、対応を開示して段階別に集計する。
qwen/.runtime/vllm-venv/bin/python -m qwen.staged_study --grade interim

# 採点・分析完了後の例。理由と担当者を実際の内容に置き換える。
qwen/.runtime/vllm-venv/bin/python -m qwen.staged_study \
  --decision continue --reason 'ここに実際の科学的判断を記す' --reviewer '担当者'
qwen/.runtime/vllm-venv/bin/python -m qwen.staged_study --run

# 現在のcheckpointで終える場合は上のcontinueをfinishにする。
# 最終の96答案を採点後、最終集計を作る。
qwen/.runtime/vllm-venv/bin/python -m qwen.staged_study --grade final
```

`COMPLETE.json`は生成完了を示し、数学的採点の完了や転移の成立を意味しない。証明の集計は`final_review/ability_summary.json`、数値の集計は`final_numeric_summary.json`。同配置・別配置を分けた答案数、完全証明、核心論証、有効な補助構成と反例を報告する。

OOM、非有限勾配、入力・policyの不一致は費用停止と区別して例外終了する。勝手にprecision、回答長、報酬、学習率を変えない。途中生成・確定checkpoint・台帳を残し、原因を確認して同じ設定で再開する。新しい報酬条件を開始する機能はこのrunnerにない。
